# 補登納入科目數與輸入舊課程簡化

## 現況

- **科目數**：後端 [FinanceController::subjectUnits](backend/app/Http/Controllers/FinanceController.php) 只依 **Laravel** 的 `LearningRecord`（Status = approved）+ `ClassSession` + `StudentClass` 計算。老師的科目數 = 加權時數 ÷ 8。
- **補登**：前端 [CourseManagement.vue](frontend/src/pages/CourseManagement.vue) 的補登只寫入 **Supabase** `student-classes`（或與 Laravel 共表則寫入同一張表），**不會**建立 `ClassSession` 或 `LearningRecord`，因此 科目數統計 不會把補登的課算進去。
- **輸入舊課程**：目前補登為「一筆一筆」填表（學生、科目、老師、固定排課日、堂數、費率等），若要把過去一個月都建好，需重複操作多次，負擔大。

---

## 一、補登也算進科目數

**目標**：補登的課程要出現在「科目數統計」裡，與過去紙本／Excel 核課後計算老師科目數的習慣一致。

**方案 A（建議）：補登後由後端補寫 LearningRecord**

- 前端補登成功後，呼叫後端 API，例如 `POST /api/v1/backfill/register-subject-units`，傳入：
  - 剛寫入的 `student_class_id` 清單（或 branch + 日期區間 + 依 student-classes 查詢對應的 Laravel StudentClass ID），
  - 選填「計入科目數的日期區間」（例如過去一個月）。
- 後端依區間內每個「該課程應上課的日期」（依 day_of_week 推算），為每筆建立一筆 `ClassSession` + 一筆 `LearningRecord`（Status = approved，Content 可為「補登／納入科目數」），不扣堂數（或依業務決定是否一併扣堂）。
- 如此一來，`subject-units` 查詢的 LearningRecord 會包含這些筆，科目數自然包含補登。

**方案 B：科目數改為雙來源**

- 若不想在補登時產生大量 LearningRecord，可改為 科目數 API 除 LearningRecord 外，再納入「StudentClass 依老師／科目」的權重（例如每筆 student-class 算 0.25 科目數）。需明確定義規則，避免與既有 LearningRecord 重複計算或與薪資邏輯不一致。

**建議**：採方案 A，由後端提供「補登註冊科目數」API，前端補登成功後可選「是否一併計入科目數」並傳入日期區間，後端建立對應 ClassSession + LearningRecord（approved）。

---

## 二、輸入舊課程不要太麻煩

**目標**：學生、老師都建好後，把「過去這個月的課程」建完即可銜接自動化；輸入過程要省力、好記。

可行方向（可擇一或並行）：

1. **補登表單預設與一鍵帶入**
  - 預設「開始日期」為本月 1 號、「剩餘堂數」依選的固定日數建議值。
  - 可選：「複製上一筆」按鈕，帶入上一筆的學生／科目／老師／時段／費率，只改堂數或日期，減少重複填。
2. **批次補登（多筆一次送）**
  - 同一學生、同一科目、同一老師、同一時段，可一次選「多個日期」或「過去 N 週」，一鍵產生多筆 student-class（或多筆 schedule），不用一筆一筆開 modal。
3. **CSV 匯入過去課程**
  - 提供「匯入過去課程」範本（學生、科目、老師、固定星期、開始日期、已購堂數、已上堂數等），匯入後寫入 student-classes，並可選擇是否呼叫「註冊科目數」API 寫入 LearningRecord，讓科目數一次到位。
4. **補登流程說明與預設**
  - 在補登 modal 加簡短說明：「先選學生、科目、老師與固定排課日，填剩餘堂數與費率；送出後可選「計入科目數」並選日期區間。」預設繳費方式、費率、時長等，減少必填欄位。

實作時可先做 1 與 4（預設＋說明），再視需求做 2 或 3。

---

## 三、實作順序建議

1. **後端**：新增 `POST /api/v1/backfill/register-subject-units`（或類似路徑），接收 student_class_id 清單（或可解析的參數）與日期區間，為區間內符合 day_of_week 的日期建立 ClassSession + LearningRecord（approved），不扣堂（或依需求決定）。
2. **前端**：補登成功後，可選「一併計入科目數」並選日期區間，呼叫上述 API；若後端與 Supabase 為不同 DB，需傳入對應的 Laravel StudentClass ID（或由後端依 student_id + subject + teacher_id 解析）。
3. **輸入簡化**：補登表單預設值與「複製上一筆」；可選批次補登或 CSV 匯入過去課程。
4. **文件／說明**：補登區塊加一句「補登後可勾選計入科目數，與紙本核課習慣一致」。

---

## 四、注意事項

- 若 Supabase 的 `student-classes` 與 Laravel 的 `StudentClass` 為不同 DB，需在後端 API 內以學生／科目／老師／時段等條件查詢對應的 StudentClass ID，或由前端傳入已對應好的 ID。
- 建立 LearningRecord 時建議寫入明確的 Content（例如「補登／納入科目數」），方便日後區分來源。
- 補登「計入科目數」是否要一併扣堂數，需依貴單位規定決定；若只為統計科目數，可不扣堂，僅建立 approved 紀錄。
