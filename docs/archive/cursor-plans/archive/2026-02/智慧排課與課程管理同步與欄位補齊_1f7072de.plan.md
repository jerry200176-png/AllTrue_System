# 智慧排課與課程管理同步與欄位補齊

## 問題與根因


| 問題                 | 根因                                                                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 智慧排課和課程管理沒有同步      | 兩頁皆讀寫同一 Supabase `student-classes`，但各自 `loadCourses()` 僅在 onMounted / branchId 變更時呼叫。若切換分頁時元件未重新掛載，或一方只更新「單一列」而另一方以「合併列」顯示，會造成認知上的不同步。                                                                                         |
| 智慧排課編輯成一對一/一對二沒有反應 | 同一門課（例：週一+週四）在 DB 為 **多筆** student-class（每筆一個 day_of_week）。智慧排課點擊其中一塊只帶出 `editingCourseId = 該筆 id`，[submitModal](frontend/src/pages/SmartCalendar.vue) 僅對 **單一 id** 做 update，故只有被點到的那一列（例如週一）會更新 class_type，週四那筆不變，畫面上仍會看到舊類型。 |
| 課程管理沒有第一堂課開始日期     | [SmartCalendar.vue](frontend/src/pages/SmartCalendar.vue) 的 modal 已有 `first_class_date`（約 205 行、923 行寫入）；[CourseManagement.vue](frontend/src/pages/CourseManagement.vue) 的編輯與補登表單皆未提供該欄位，也未讀寫。                                 |


---

## 一、智慧排課：編輯時同步更新「同課程」所有列

**檔案：** [frontend/src/pages/SmartCalendar.vue](frontend/src/pages/SmartCalendar.vue)

- **現狀**：`submitModal` 在 `editingCourseId.value` 存在時只執行一次  
`supabase.from('student-classes').update(payload).eq('id', editingCourseId.value)`（約 931 行），因此只更新被點擊的那一筆。
- **作法**：編輯儲存時，先以「同學生、同科目、同老師、同時段」找出同一門課的所有列（與課程管理分組邏輯一致：`student_id`、`subject`、`teacher_id`、`start_time`、`end_time` 正規化後相同），再對 **每一筆** 做 update，payload 中 `day_of_week` 維持各列原本的值，其餘欄位（如 `class_type`、`subject`、`rate_per_30min`、`first_class_date` 等）統一更新。
- **實作要點**：
  1. 在 `submitModal` 內，當 `editingCourseId.value` 存在時，先查詢當前筆的 `student_id, subject, teacher_id, start_time, end_time`（或直接從當前 `courses` 裡找同 group 的 id 清單）。
  2. 查詢 `student-classes` 取得與上述條件相符且 `branch_id` 相同之所有列 id（或沿用既有 courses 資料推得同組 id）。
  3. 對每個 id 執行 update，payload 勿覆寫該列的 `day_of_week`（每列保留自己的星期），其餘欄位一致。
- 如此一來，在智慧排課把「週一」改成 一對一 時，同一門課的「週四」也會一併更新為 一對一，兩邊顯示一致。

## 二、課程管理：新增「第一堂課開始日期」

**檔案：** [frontend/src/pages/CourseManagement.vue](frontend/src/pages/CourseManagement.vue)

- **編輯表單**：
  - 在編輯 modal 中新增欄位「第一堂課開始日期」，綁定 `editForm.first_class_date`（型別 date 字串或 null）。
  - 開啟編輯時，從該組第一筆或合併資料帶入 `first_class_date`（若有多筆可取 `c.first.first_class_date` 或第一筆有值者）。
  - `submitEdit` 時，將 `first_class_date` 納入 `shared`（或各 update/insert payload），對所有該組的 update 與新 insert 的列都寫入同一 `first_class_date`。
- **補登表單**：
  - 在補登 modal 中新增欄位「第一堂課開始日期」，綁定 `backfillForm.first_class_date`（可選填）。
  - `submitBackfill` 組 records 時，每筆都帶入 `first_class_date: backfillForm.first_class_date || null`。
- 若 DB 的 `student-classes` 沒有 `first_class_date` 欄位，需在 Supabase 後台或 migration 新增；若已有（與 SmartCalendar 一致），則前端補齊即可。

## 三、兩頁資料一致（進入時重載）

- **建議**：在 [App.vue](frontend/src/App.vue) 或各頁內，當「當前分頁」切換到智慧排課或課程管理時，觸發該頁的 `loadCourses()`（或等價的資料重載）。若目前為 `v-if` 切換且無 keep-alive，每次進入會重新 mount，onMounted 會跑，理論上會重載；若有 keep-alive 或路由快取，需在 onActivated 或對應的「頁面可見」鉤子裡呼叫 `loadCourses()`，確保從另一頁編輯後回來會看到最新資料。
- 若實作一後，智慧排課已改為「同課程多列一併更新」，加上兩頁都讀同一張表且進入時會重載，同步問題應可緩解。

---

## 四、實作順序建議

1. **SmartCalendar submitModal**：編輯時依「同學生、同科目、同老師、同時段」解析出同課程所有列 id，迴圈 update 每筆（保留各自 `day_of_week`），解決一對一/一對二沒反應。
2. **CourseManagement 編輯**：新增 `first_class_date` 欄位與 `editForm` / `submitEdit` 讀寫。
3. **CourseManagement 補登**：新增 `first_class_date` 欄位與 `submitBackfill` 寫入每筆。
4. **可選**：確認進入智慧排課／課程管理時會觸發 loadCourses（必要時加 onActivated 或 watch 當前分頁）。

---

## 五、不變更範圍

- 課程管理「合併顯示」與智慧排課「一列一天」的顯示方式維持不變；僅修正寫入範圍與欄位一致。
- 若 Supabase 上 `student-classes` 尚無 `first_class_date`，需另於 DB 新增欄位後前端再寫入。
