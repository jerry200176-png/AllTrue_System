# 智慧排課修復與班主任優化計畫

## 現況與問題

- **快速排課按下去一片空白**：同一顆按鈕對應 `openQuickAdd()`，與「點時間格」對應的 `onSlotClick()` 會開同一個 modal（`showModal`），表單結構已改為「無每月例行上課週」＋「兩小時多少錢」。若線上仍看到舊版（還有每月例行上課週、費率 $/30min），代表**目前對外提供的是舊版前端 bundle**；空白多半是舊版 JS 與新 template 不一致（例如沒有 `ratePer2h`）導致執行期錯誤，整塊元件掛掉。
- **點時間表排課沒有改到**：程式上「快速排課」與「點時間格」共用同一個 modal 與同一份表單，所以**原始碼**已同時套用：無每月例行上課週、費率改兩小時。若你實際操作仍看到舊欄位，就是**尚未部署最新 build**。另外 `onSlotClick` 未設定 `payment_type`，開窗時繳費方式會是 undefined，可能造成顯示或送出不一致。

---

## 一、必做：修復空白與表單一致

### 1. 避免 modal 空白（防呆與錯誤隔離）

- **原因推論**：modal 內使用 `ratePer2h`、`modalForm.rate_per_30min`、`modalForm.days_of_week` 等，若任一為 undefined 或舊版未定義 `ratePer2h`，可能拋錯導致整頁或整塊白屏。
- **建議**（`[frontend/src/pages/SmartCalendar.vue](frontend/src/pages/SmartCalendar.vue)`）：
  - **ratePer2h**：computed 的 get/set 都對 `modalForm.value`、`rate_per_30min` 做防呆（預設 0），避免未初始化或 API 回傳缺欄位時出錯。
  - **表單綁定**：`modalForm.days_of_week` 在 template 用於 `includes()`，確保 `openQuickAdd` / `onSlotClick` 都一律給定陣列（例如 `[]` 或 `[dayOfWeek]`），不要出現 undefined。
  - 若有任何 `v-for` 依賴非同步資料（如 `allStudents`、`teachers`），用 `(allStudents || [])` 或 `v-for="s in (allStudents ?? [])"` 避免未載入時拋錯。

### 2. 兩種開窗表單欄位一致

- **openQuickAdd** 已有：`weeks`、`payment_type`、`first_class_date`、`rate_per_30min` 等。
- **onSlotClick** 目前少設 `payment_type`，且若未來有其它欄位只在一邊設，容易造成「點時間格」開出來的表單與「快速排課」不一致。
- **建議**：在 `onSlotClick` 內設定 `modalForm` 時，補上與 `openQuickAdd` 相同的預設欄位，至少包含：
  - `payment_type: 'session'`
  - 視需要補 `first_class_date: getDefaultFirstClassDate()`（若尚未有）。
- 這樣無論從按鈕或從時間格開 modal，表單形狀一致，且「兩小時多少錢」與「無每月例行上課週」在兩種入口都會一致（前提是部署最新版）。

### 3. 確認部署的是最新前端

- 目前表單已改為「無每月例行上課週」＋「兩小時多少錢」，若線上仍看到舊版，代表**尚未用最新 build 覆蓋** `backend/public`。
- **建議**：在修完上述防呆與 `onSlotClick` 後，重新執行 `npm run build`（必要時用 `dist_build` 避開權限），再將產物複製到 `backend/public`，並強制重新整理驗證。

## 二、班主任視角：智慧排課頁可再優化的方向

以「班主任日常排課」為情境，建議優先順序如下。

### 1. 一鍵開單、少填少錯（高）

- **現狀**：開 modal 要填學生、科目、老師、類型、排課日、首堂日、時長、開始時間、兩小時多少錢、繳費方式、堂數等，欄位多。
- **建議**：
  - 預設值維持：時長 2 小時、開始時間 16:00、兩小時價與堂數給合理預設（例如 2000、8），繳費方式預設堂數制；「排課日」在**點時間格**時已帶入該日，**快速排課**可預設「本週一」或今天所屬週一。
  - 表單分區：上半「誰／什麼課／誰教」、中間「何時／多久／兩小時多少錢」、下半「繳費方式／堂數」，必要欄位（學生、老師、至少一天）未填不給送出並明確提示。
  - 可選：提供「複製上一筆」或「複製上週同一天」的快速帶入，減少重複輸入。

### 2. 衝堂與衝突更明顯（高）

- **現狀**：已有 `conflictWarning` 文案。
- **建議**：衝堂時在 modal 頂部用明顯色塊＋圖示顯示，必要時在週課表上該時段也標示「衝堂」或不同樣式，避免排錯。

### 3. 本週／當日負擔一眼看懂（中）

- **建議**：在週課表上方或側邊顯示「本週總堂數」或「今日總堂數」，可選按老師或按學生篩選；或在小計旁顯示「已排 N 堂／本週共 M 堂」，方便班主任掌握負擔。

### 4. 快速排課與點格排課的差異再收斂（中）

- **現狀**：快速排課＝先選時段再填表；點格＝先選「星期＋小時」再填表，排課日已帶入。
- **建議**：兩種入口都使用**同一套預設與同一套欄位**（如上 1），並在說明文字註明：「點空白格可帶入該日該時段；用快速排課則需自選排課日與時間。」減少認知負擔。

### 5. 可選進階（低）

- 匯出本週課表（PDF/列印）。
- 依老師／學生篩選後，一鍵複製整週排課到下一週（需確認業務規則）。

## 小結

- **空白**：先當成「舊 bundle 或缺少防呆導致執行期錯誤」處理——補防呆、統一兩種開窗的 form 形狀、再部署最新 build。
- **每月例行上課週／費率**：原始碼已改為「無每月例行上課週」＋「兩小時多少錢」，若畫面上仍看到舊版，代表需部署最新前端。
- **班主任優化**：以「少填、少錯、衝突明顯、負擔可見」為主軸，先做表單預設與分區、衝堂提示，再視需求做本週小計或複製/匯出。
