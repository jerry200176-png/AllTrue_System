# 修復歷史排課扣堂與顯示不一致

## 問題定位

- 後端主要入口是 `[/home/admin/backend/app/Http/Controllers/ClassSessionController.php](/home/admin/backend/app/Http/Controllers/ClassSessionController.php)` 的 `batchStore()`。
- 目前 `confirmed_dates` 會寫入 `attended`，`future_dates` 寫入 `scheduled`；剩餘堂數主要仰賴既有扣堂流程，沒有在 batch 完成後用「已完成堂次」做一次權威回算。
- 前端 `[/home/admin/frontend/src/pages/SmartCalendar.vue](/home/admin/frontend/src/pages/SmartCalendar.vue)` 會在 API 載入後以 Supabase 值覆寫 `remaining_sessions`，可能把後端正確扣堂結果蓋回舊值。

## 修復範圍

- 後端寫入狀態修正（歷史堂次 -> completed）
- 後端剩餘堂數回算修正（購買堂數 - 已完成堂數）
- 前端顯示來源修正（優先採用 Laravel API 回傳的 remaining）
- 回歸測試補強（batch 建課 + 扣堂）

## 實作步驟

1. 在 `[/home/admin/backend/app/Http/Controllers/ClassSessionController.php](/home/admin/backend/app/Http/Controllers/ClassSessionController.php)` 調整 `batchStore()` 寫入規則：
  - `confirmed_dates` 建立/更新時，狀態統一寫 `completed`。
  - `future_dates` 維持 `scheduled`。
  - 若既有同日堂次非完成態，升級為 `completed`（避免歷史資料留在 `scheduled`）。
2. 在同檔新增「堂數回算」私有方法，於 batch 寫入完成後執行：
  - `completedCount = ClassSession where StudentClassID = ? and Status in (completed, attended)`（相容舊資料）。
  - `used = min(SessionCount, completedCount)`。
  - `remaining = max(0, SessionCount - used)`。
  - 回寫 `StudentClass.UsedSessions`、`StudentClass.RemainingSessions`（必要時同步 `Stop` 狀態）。
3. 調整 `[/home/admin/frontend/src/pages/SmartCalendar.vue](/home/admin/frontend/src/pages/SmartCalendar.vue)` 的課程合併邏輯：
  - 當 Laravel API 已有 `remaining_sessions` 時，不再用 Supabase 的舊值覆寫。
  - 僅在 API 無值時才 fallback 使用 Supabase 欄位。
4. 更新/新增測試：
  - 修改 `[/home/admin/backend/tests/Feature/ClassSessionBatchApiTest.php](/home/admin/backend/tests/Feature/ClassSessionBatchApiTest.php)` 既有斷言（confirmed 的 status 期望改為 `completed`）。
  - 新增案例驗證 `SessionCount=8, confirmed_dates=3` 時，`RemainingSessions=5`、`UsedSessions=3`。
  - 新增相容案例：既有 `attended` 也能被回算為已使用堂次。
5. 驗證與回歸
  - 執行目標測試：`php artisan test --filter=ClassSessionBatchApiTest`。
  - 手動驗證流程：在通用排課勾選歷史日期 -> 儲存 -> SmartCalendar 與課程列表剩餘堂數同步下降。
