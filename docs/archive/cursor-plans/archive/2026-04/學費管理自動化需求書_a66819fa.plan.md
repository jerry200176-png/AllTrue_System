# 學費管理自動化與系統介面優化 — 需求計畫書（提交開發部門）

**文件版本**：v1.0  
**撰寫角色**：專案經理（PM）  
**背景**：行政端需在多介面快速核對繳費狀態；現行「手動切換已繳／未繳」步驟多、易與實際入帳日不一致；催繳名單表格曾出現欄位視覺錯位，影響對外專業形象。

---

## 一、功能效益說明

1. **降低人工失誤**  
   將「繳費日期」與「已繳費」狀態連動，減少同仁只改狀態卻未註記日期、或日期與狀態不一致的情況；對帳時可依單一欄位追溯決策依據。

2. **提升對帳與稽核效率**  
   管理層在催繳名單、當月學收、學生資料、課程列表四處皆可看到同一語意的「繳費日期」，無需在多頁來回比對；有利於月結、續課提醒與家長溝通時快速說明。

3. **行政作業路徑縮短**  
   新增／編輯課程時一次完成「註記繳費日 + 標示已繳」，取代反覆點選切換狀態，縮短操作時間並降低遺漏。

4. **品牌與專業形象**  
   修正催繳名單表格跑版，確保數字與表頭對齊、報表列印或螢幕展示時清晰，避免家長或內部同仁對資料正確性產生疑慮。

---

## 二、需求清單

### A. 課程主檔 — 繳費日期（選填）與自動連動

| 編號 | 需求描述 |
|------|------------|
| A-1 | 於「新增課程」「編輯課程」表單增加欄位：**繳費日期**（選填，日期選擇器）。 |
| A-2 | **連動規則**：使用者選定並儲存「繳費日期」後，系統應自動將該筆課程之帳務狀態標示為 **已繳費**（等同現行 `Paid`/前端 `payment_status` 之已繳語意）。 |
| A-3 | **清空規則（建議，待產品拍板）**：若使用者清除繳費日期並儲存，是否自動改回「未繳費」須明確定義；建議與「手動改回未繳」行為一致，並於介面上提示風險。 |
| A-4 | **與既有帳務模組關係（建議）**：若組織仍以 `Invoice`/`Payment` 為正式稽核依據，應定義「僅寫入課程註記日期」是否需同步產生最小筆數之繳費紀錄，或僅更新 `StudentClass`；避免雙軌資料長期不一致。（技術細節由開發評估，產品需選定策略） |

**主要涉及檔案（供開發對照）**：[frontend/src/pages/StudentsList.vue](frontend/src/pages/StudentsList.vue)、[frontend/src/pages/CourseManagement.vue](frontend/src/pages/CourseManagement.vue)、[backend/app/Http/Controllers/StudentClassController.php](backend/app/Http/Controllers/StudentClassController.php) 及相關 API／migration（若新增欄位）。

### B. 管理資訊透明化 — 四介面顯示繳費日期

| 編號 | 介面 | 需求描述 |
|------|------|----------|
| B-1 | **催繳名單** | 列表須顯示該課程之繳費日期（與 A 欄位或正式入帳日一致之單一業務定義）；未填／無紀錄時顯示占位（如「—」）。 |
| B-2 | **當月學收分析** | 同上，依報表所選月份可辨識之繳費日期或「該期最後入帳日」定義須與產品規格一致。 |
| B-3 | **學生資料**（學生課程列） | 每門課可一眼看到繳費日期。 |
| B-4 | **課程列表**（課程管理） | 同上。 |

**現況參考**：系統已透過 `Payment.PaidAt` 彙總顯示 `last_paid_at` 於部分 API 與頁面；本需求若改為「課程表單註記日期」為準，須統一**顯示優先序**（例如：正式入帳日優先，否則顯示註記日）。

**主要涉及檔案**：[frontend/src/pages/TuitionCollectionPage.vue](frontend/src/pages/TuitionCollectionPage.vue)、[frontend/src/pages/TuitionReportPage.vue](frontend/src/pages/TuitionReportPage.vue)、[backend/app/Http/Controllers/AlertController.php](backend/app/Http/Controllers/AlertController.php)、[backend/app/Http/Controllers/FinanceController.php](backend/app/Http/Controllers/FinanceController.php)。

### C. 催繳名單 — 跑版修復與視覺優化

| 編號 | 需求描述 |
|------|------------|
| C-1 | 修正「剩餘堂數」與「繳費日期」等欄位與表頭**不對齊**或數字誤入鄰欄之問題；桌機與常見寬度下表頭與儲存格須一一對應。 |
| C-2 | 檢視 `@media (max-width: 768px)` 下以 `nth-child` 隱藏欄位時，**表頭（`th`）與內容列（`td`）** 隱藏規則須一致，避免僅隱藏一側造成錯位。 |
| C-3 | 必要時改為小螢幕 **卡片式列表** 或固定欄寬／`table-layout`，確保「學生、科目、狀態、剩餘堂數、繳費日期、操作」語意清楚。 |

**主要涉及檔案**：[frontend/src/pages/TuitionCollectionPage.vue](frontend/src/pages/TuitionCollectionPage.vue)。

## 三、驗收標準（業務操作角度）

以下皆以「指定分校、具權限之主任／行政帳號」操作為前提。

### 1. 課程新增／編輯與連動

- 新增一門課程，**不填**繳費日期儲存後：該課程在課程列表／學生資料中顯示為**未繳費**（與現行一致）。
- 編輯同一門課程，**填入**繳費日期（例如當月某日）並儲存後：  
  - 該課程在學生資料、課程列表、催繳名單（若仍符合提醒條件）、當月學收中，皆顯示**相同日期**（或產品定義之優先顯示邏輯）。  
  - 繳費狀態自動為**已繳費**，無須再手動點「已繳費」按鈕即可完成標示。
- （若採用 A-3 清空規則）清除繳費日期並儲存後，狀態與畫面符合規格說明（已拍板之行為）。

### 2. 四介面可讀性

- **催繳名單**：每一列可讀到「剩餘堂數」數字出現在「剩餘堂數」欄下方，「繳費日期」欄僅顯示日期或「—」，不得與鄰欄數字錯位。
- **當月學收分析**：列表含繳費日期欄，與表頭對齊，小螢幕不影響主要數字可讀性。
- **學生資料、課程列表**：每門課可看到繳費日期（或無資料時之占位），與已繳／未繳標示一致、無矛盾。

### 3. 跑版與專業呈現

- 在 **1280px 寬桌機** 與 **375px 寬手機**（或專案約定之兩種 viewport）下截圖驗收：表頭與內容逐欄對齊，無「數字跑到錯誤欄位標題下」之情況。
- 列印或匯出（若有）時，催繳名單主要欄位仍對齊可讀（若本階段無列印，則以螢幕驗收為準）。

### 4. 迴歸與風險

- 變更**不得**擅自修改主任「繳費／續課提醒」之商業條件（見專案規範文件）；若連動「已繳」會改變是否出現在催繳名單，須與產品確認是否為預期。
- 既有「僅手動切換已繳／未繳」路徑：須定義是否保留、或改為僅能透過繳費日期／正式入帳流程處理，並在驗收中列出同意行為。

## 四、開發注意（非驗收條文，供排程）

- 若新增 DB 欄位（例如課程註記繳費日），需 migration、API 契約與前端表單一併更新。  
- 與現有 `last_paid_at`（來自 `Payment.PaidAt`）之關係須在技術設計書中寫清顯示與寫入優先序。  
- 前端變更後依專案規範執行 `npm run deploy`，避免 `index.html` 與資產 hash 不同步。
