# GitHub 程式碼備份計劃

## 目前狀態

- **Branch**：`main`（push 目標：`origin/jerry-sync-main`）
- **未推送 commits**：9 筆（最新到最舊列於下方）
- **未 commit 的修改（M）**：約 40+ 個檔案（controllers、services、frontend、docs 等）
- **未追蹤的新檔案（??）**：23 個（含 migrations、tests、新元件、文件）

## 安全保證

這個計劃只做 git 操作（`git add / commit / push / branch`），**不會**：
- 重啟 PHP-FPM / Nginx / Laravel
- 修改 `.env` 或資料庫
- 觸發 `npm run deploy`
- 刪除任何現有分支

## 執行步驟

### Step 1 — 提交全部待辦變更

使用現有的 [`scripts/git-sync.sh`](scripts/git-sync.sh) 腳本，一鍵 `git add -A` + commit + push：

```bash
cd /home/admin
./scripts/git-sync.sh "chore: backup all pending changes 2026-04-16"
```

這會：
1. Stage 全部 M 檔案 + 23 個 untracked 檔案（含 `backups/`、`scripts/infra/`、新 Vue 元件、migration、測試等）
2. 建立一筆 commit
3. 把本地 9 個舊 commit + 這筆新 commit（共 10 筆）一起 push 到 `origin/jerry-sync-main`

### Step 2 — 建立日期備份分支

在 push 完成後，從目前 HEAD 建立一個帶日期的備份 branch 並推上 GitHub：

```bash
git branch backup-2026-04-16-main
git push origin backup-2026-04-16-main
```

這樣 GitHub 上就會有一個永久快照 `origin/backup-2026-04-16-main`，與既有的 `backup-2026-04-10-admin` 並列。

## 備份後 GitHub 分支結構

```
origin/main                   (舊的 base，不動)
origin/jerry-sync-main        (協作主幹，push 目標)  ← 本次更新至此
origin/backup-2026-04-10-admin (舊備份)
origin/backup-2026-04-16-main  (本次新增備份 snapshot)
```

## 風險評估

- **無服務中斷風險**：純 git 操作
- **網路斷線風險（極低）**：push 失敗不影響本地 commit；重跑 `git push origin HEAD:jerry-sync-main` 即可
- **SSH 金鑰**：若 `git@github.com` 連線中斷，用 `ssh -T git@github.com` 先驗證
