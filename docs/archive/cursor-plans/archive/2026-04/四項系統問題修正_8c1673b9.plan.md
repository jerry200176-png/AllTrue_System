## PRD-A：今日課表出缺勤狀態顯示錯誤

### 1. 文件資訊
| 欄位 | 內容 |
|---|---|
| 功能名稱 | 今日課表出缺勤狀態修正 |
| 版本 / 日期 | v1.0 / 2026-04-18 |
| 狀態 | Draft |
| 目標角色 | 主任（DirectorDashboard 使用者） |

### 2. 目標與業務背景
- **痛點**：沈宇璿 17:00 這堂已有到班操作，但主任儀表板「今日課表」仍顯示「缺席」，導致主任誤判出勤狀態，影響後續處理決策。
- **業務價值**：確保今日課表狀態與實際點名/刷卡結果一致，主任無需再交叉比對出缺勤頁確認真實狀況。
- **KPI**：今日課表中每筆 `ClassSession.Status` 與最新有效 `StudentSingIn` 記錄一致，異常比例降至 0%。

### 3. 範圍
- **In Scope**
  - 診斷並修正 `ClassSession.Status` 與 `StudentSingIn` 不同步的根本原因
  - 今日課表 API (`GET /api/v1/class-sessions`) 回傳資料是否能正確反映最新到班記錄
  - 若 UI 僅用 `ClassSession.Status` 而不做即時 reconcile，修正後端在點名/刷卡寫入時的同步邏輯
- **Out of Scope**
  - 重構整個出缺勤模組
  - 歷史資料補正（過去已存的不一致資料）

### 4. RACI
| 角色 | 代表 | R/A/C/I |
|---|---|---|
| PM | | A |
| CTO / 工程 | | R |
| UI/UX Designer | 本次後端邏輯為主，前端無視覺改動 | I |
| QA | | R |
| 資安 | | C |
| IT / Ops | 1. 後端部署：執行 `php artisan optimize:clear` 並確認服務重啟正常；2. Backfill 腳本執行：先以 `--dry-run` 自動驗證影響筆數 < 500 且全部位於過去 7 天內，符合條件則自動執行補正，不需人工確認；3. 部署後監控 Laravel `storage/logs` 確認無新增 500 錯誤；4. 備妥 git revert 回滾方案 | R |

### 5. User Stories
> **As a** 主任, **I want** 今日課表中的到班/缺席標籤與學生的實際刷卡/手動點名結果一致, **so that** 我不需要再另開出缺勤頁才能確認真實出勤狀況。
>
> Acceptance Criteria：
> - [ ] 學生完成刷卡（`StudentSingIn.Status = present`）或主任手動點名到班後，今日課表該堂次顯示「已到班」
> - [ ] 有效的到班記錄存在時，今日課表不得顯示「缺席」
> - [ ] 主任手動將狀態改回「缺席」後，今日課表正確顯示「缺席」

### 5b. UI/UX 精緻化需求
| 面向 | 要求 |
|---|---|
| 版面層次 | 狀態標籤顏色語意維持現有（綠色=到班、紅色=缺席），無需調整 |
| 互動回饋 | 本次無前端互動變更，N/A |
| 其他 | 本 PRD 以後端邏輯修正為主，前端無視覺改動 |

### 6. 功能需求
- **FR-A-001**：後端在執行點名寫入（`AttendanceController` 相關路徑）或刷卡觸發 (`/api/v1/attendance/swipe`) 時，必須同步將對應 `ClassSession.Status` 更新至正確狀態（`attended` / `absent` / `leave`）
- **FR-A-002**：`GET /api/v1/class-sessions?branch_id=…&start=…&end=…` 回傳的 `status` 欄位，必須反映該 `ClassSession` 最新有效（`VoidedAt IS NULL`）的 `StudentSingIn` 或 `ClassSession.Status` 的同步結果
- **FR-A-003**：當 `ClassSession.Status` 與最新有效 `StudentSingIn.Status` 不一致時，系統應以後者為準進行修正（reconcile），或在寫入端禁止出現此種不一致
- **FR-A-004**：提供一次性 backfill 腳本（支援 `--dry-run` 模式），補正過去 7 天內 `ClassSession.Status` 與最新有效 `StudentSingIn` 不一致的記錄；`--dry-run` 後自動驗證影響筆數 < 500 則直接執行，無需人工確認；超過 7 天的不一致記錄輸出至 `storage/logs/backfill-report-{date}.csv`，不自動補正

### 7. 非功能需求
- `GET /api/v1/class-sessions` API 回應時間 < 500ms（當天資料量 ≤ 500 筆）
- 點名寫入操作不得因狀態同步邏輯影響現有 `SessionDeducted` 堂數扣除流程

### 8. 技術方向
- **受影響頁面**：`DirectorDashboard.vue`（今日課表 widget）、`AttendancePage.vue`（已存在出缺勤管理）
- **受影響 API**：`GET /api/v1/class-sessions`、`POST /api/v1/attendance`、`POST /api/v1/attendance/swipe`、`PATCH /api/v1/class-sessions/{id}`
- **受影響資料表**：`ClassSession`（`Status`）、`StudentSingIn`（`Status`, `VoidedAt`）
- **架構選擇**：在後端寫入 `StudentSingIn` 的同時強制同步 `ClassSession.Status`，確保單一資料來源（ClassSession）對外呈現一致狀態；今日課表 UI 不需改動
- **是否需要 migration**：否（僅業務邏輯修正）
- **Sub-task 派發**：`[FEATURE]` → `AttendanceController` + `ClassSessionController` 邏輯修正；`[TEST]` → Pest Feature test；`[REVIEW]` → 確認 `applyAttendanceEffects` 所有觸發路徑；`[DOCS]` → CHANGELOG

### 9. 資安與存取控制
- 出缺勤寫入需 `role: director/teacher`，`require_campus` 限制校區隔離，無新增存取路徑
- 無 PII 新增暴露風險
- STRIDE：低風險；修正後可能影響薪資/學習記錄計算，需確認不改變 `SessionDeducted` 已有邏輯

### 10. QA 驗收標準
| FR | Happy Path | Edge Case | Error Case |
|---|---|---|---|
| FR-A-001 | 刷卡後今日課表顯示「已到班」 | 同一學生同天兩堂，各自獨立狀態正確 | 刷卡寫入失敗時 ClassSession.Status 不被更新 |
| FR-A-002 | API 回傳 status=attended 當有效 sign-in 存在 | VoidedAt 非 null 的 sign-in 不影響 status | 無 sign-in 時維持 ClassSession 原始 status |
| FR-A-003 | 不一致狀態自動修正 | 多筆 sign-in 以最新有效為準 | 同一 ClassSession 有 present 與 absent 記錄時以最新為準 |

**UI/UX 驗收清單**：本 PRD 無前端視覺改動，清單 N/A（已標注原因）

**回歸測試**：參照 `docs/AI_REGRESSION_LESSONS.md` 中出缺勤/堂數扣除相關段落，確認 `SessionDeducted`、`RemainingSessions` 未被影響

### 11. 上線與維運

## PRD-B：家長端登入範圍與入口設計重整

### 1. 文件資訊
| 欄位 | 內容 |
|---|---|
| 功能名稱 | 家長端學生綁定機制與入口體驗重新設計 |
| 版本 / 日期 | v1.0 / 2026-04-18 |
| 狀態 | Draft |
| 目標角色 | 家長（LINE 綁定 / 手機登入） |

### 2. 目標與業務背景
- **痛點一**：家長登入後可能看到「手機號碼相同的所有學生」，包含非同家庭的學生（例如不同家庭填寫了相同手機號），造成隱私疑慮
- **痛點二**：家長入口目前已有「學習評量、剩餘堂數、出缺勤」，但出缺勤顯示不完善（缺乏明確格式），整體入口體驗與業界慣例有落差
- **業務價值**：確保家長只能看到自己孩子的資料；提升家長滿意度與信任感
- **KPI**：家長登入後 100% 只看到自己授權的學生；家長出缺勤查詢準確率 ≥ 95%；LINE 綁定率目標：上線後第 1 個月達 40%、第 3 個月達 65%（參照台灣補習班業者 LINE 官方帳號導入案例中位數）

### 3. 範圍
- **In Scope**
  - 家長手機登入時，學生配對邏輯僅限「明確授權的學生」（需定義授權機制）
  - LINE 綁定後的家長首頁：依業界作法顯示學習評量、剩餘堂數、出缺勤（格式完善）
  - 出缺勤顯示格式改善（目前 `AttendancePage` 是老師/主任用，家長端需獨立呈現）
