## §2 目標與業務背景

### 痛點

**痛點 1 — 一般月結課程：主任要手動逐格點日期**

目前建立一般月結課程時，主任必須在日曆上一格一格點出「這個月的每個禮拜四」，且日曆限制只能選同一個月，跨月即彈出警告。實際操作：4 個禮拜四 = 要點 4 次。課程若持續半年，主任每個月都要重進來補點。業界（Tutorbase / Google Calendar）做法是：設定「每週四」+ 開始/結束日期，系統一次生成全期。

**痛點 2 — 多科共用方案月結制：完全沒有 ClassSession**

多科方案月結制建立後，系統不生成任何 ClassSession（程式碼明確 `if (!$isMonthly)` 跳過排課邏輯）。老師每次上課都要手動補登，主任無法事先看到課表，形成管理盲區。

**痛點 3 — UX 詞彙不一致**

建立流程用「每月固定」，編輯流程用「月結」，導致主任覺得是兩個不同功能。

### 業務價值

- 主任建立月結課程的操作從「N 次點選 × 每個月」縮短為「一次設定固定星期 + 結束日期」
- 多科月結方案有完整課表，主任可事前確認排課、老師不需手動補登
- 詞彙統一，降低學習成本

### 可量化 KPI

| 指標 | 目標 |
|---|---|
| 建立一般月結課程的點擊次數 | 從「N 次點日曆格」降為 0 次（固定星期自動展開） |
| 多科月結方案建立後 ClassSession 數 | > 0（目前為 0） |
| 月結路徑 UI 詞彙一致性 | 所有「每月固定」替換為「月結制」|

## §5 User Stories

### US-01：主任建立一般月結課程（核心流程）

**As a** 主任，  
**I want** 建立月結課程時只需選「每週四 18:00-20:00」+ 開始日 + 結束日，  
**so that** 系統自動排好所有禮拜四的課，我不需要逐格點選。

**AC：**
- GIVEN 主任選擇月結制、週四 18:00、開課日 2026/05/01、結束日 2026/07/31
- WHEN 點「建立課程」
- THEN ClassSession 自動生成該期間所有週四（共約 13 堂），Status = `scheduled`

### US-02：主任建立多科共用方案月結課

**As a** 主任，  
**I want** 建立多科月結方案時，每科都能設定固定星期 + 結束日期，  
**so that** 方案建立後就有完整課表，老師不需手動補登。

**AC：**
- GIVEN 方案含 2 科，數學週二 / 英文週四，結束日 2026/07/31
- WHEN 點「建立方案」
- THEN 數學科生成所有週二 ClassSession，英文科生成所有週四 ClassSession

### US-03：主任確認排課預覽

**As a** 主任，  
**I want** 送出前看到「每週四 18:00–20:00，共 N 堂」的文字摘要，  
**so that** 確認沒有選錯星期或日期範圍再送出。

**AC：**
- GIVEN 已選週四 18:00、開課日 2026/05/01、結束日 2026/07/31
- WHEN 表單填完後（未送出）
- THEN 顯示動態預覽：「每週四 18:00–20:00，共 13 堂（2026/05/01 ～ 2026/07/31）」

| 面向 | 規格 |

## §8 技術方向

### 受影響頁面、API、資料表

| 層 | 位置 | 異動說明 |
|---|---|---|
| 前端 UI | `frontend/src/components/UniversalClassScheduler.vue` | 月結一般路徑：移除月曆點選，改為 chip + end_date；方案路徑：補回 days_of_week + end_date |
| 前端 API | `frontend/src/lib/universalSchedulerApi.js` | 月結路徑 payload 新增 end_date + days_of_week |
| 後端 Controller | `backend/app/Http/Controllers/ClassSessionController.php` | batchStore validation 新增 end_date |
| 後端 Service | `backend/app/Services/EnrollmentService.php` | 月結分支用 end_date + days_of_week 自動生成 future_dates；EndDate 設為 end_date |
| 後端 Controller | `backend/app/Http/Controllers/CoursePackageController.php` | createMultiSubject 月結路徑補排課欄位 + buildSessionsFromWeeklySchedule |
| 資料表 | `StudentClass`（`EndDate`、`week`、`time`、`week1~week6`、`time1~time6`） | 無 migration（欄位已存在）|
| 資料表 | `ClassSession` | 無 migration（補排現有欄位）|

### 架構選擇理由

- **複用 `buildSessionsFromWeeklySchedule`**：`StudentClassController` 已有此方法，透過 `app()->make()` 注入，不重複實作。
- **EnrollmentService 月結分支**：偵測 `end_date` + `days_of_week` 有值時走新路徑，否則 fallback 舊邏輯（向後相容）。
- **CoursePackageController 移除 `if (!$isMonthly)` 限制**：月結方案也需要排課欄位，但不呼叫 `extendSessionsIfNeeded`（那是堂數制邏輯），改呼叫 `buildSessionsFromWeeklySchedule`（日期範圍生成）。
- **無 migration**：`EndDate`、`week`/`time`/`week1~week6`/`time1~time6` 欄位均已存在。

| 2026-04-23 | NFR-004 end_date 上限 | A: 1年 / B: 2年 / C: 不限制 | **B（2年）** | 2年×52週×5科=520筆，在可接受範圍內；超過2年的情況極少（補習班慣例） |

## §10 QA 驗收

### Happy Path

| 場景 | 預期結果 |
|---|---|
| 建立月結課程：週四 18:00，2026/05/01 ~ 2026/07/31 | ClassSession 生成 13 筆（13 個週四），Status = scheduled，StartTime = 18:00 |
| 建立月結課程：使用「+3個月」快選 | end_date 自動設為 start_date + 3 個月 |
| 建立多科月結方案：數學週二 / 英文週四，結束 2026/07/31 | 數學科生成週二 ClassSession；英文科生成週四 ClassSession；members_scheduled 回傳各科堂數 |
| 預覽文字：選週四 18:00，2026/05/01~2026/07/31 | 顯示「每週四 18:00–20:00，共 13 堂（2026/05/01 ～ 2026/07/31）」 |
| 堂數制課程建立 | 行為與修改前完全相同（回歸） |

### Edge Cases

| 場景 | 預期結果 |
|---|---|
| end_date = start_date（同一天）且當天為週四 | 生成 1 筆 ClassSession |
| end_date = start_date 但當天不是週四 | 生成 0 筆；toast warning「此期間無符合的課堂日期」 |
| end_date 超過 2 年 | 後端回傳 422，前端顯示 inline error |
| days_of_week 有複數（週一+週四） | 每週生成 2 筆，共 N×2 堂 |
| 多科月結方案不填 days_of_week（只填 start_date） | 建立成功，ClassSession = 0，members_scheduled 顯示「尚未設定排課時段」；不阻擋送出 |
| end_date < start_date | 前端 inline error；不送出 |
| 月結課程有舊路徑（無 end_date，有 future_dates） | 後端 fallback 舊邏輯，不受影響 |

### Error Cases

| 場景 | 預期結果 |
|---|---|
| 未選 days_of_week 就送出（一般月結）| 前端 disabled + tooltip 阻止送出 |
| days_of_week 含無效值（如 0 或 8）| 後端 422 |
| 同時傳 future_dates 與 end_date + days_of_week | 後端優先使用 end_date + days_of_week 路徑 |

## §13 風險 / 假設 / 開放問題

### 業界解法（WebSearch 來源：Tutorbase 2026）

| 風險 | 等級 | 業界標準解法 | 本專案採行 |
|---|---|---|---|
| 月結 end_date 生成過多 ClassSession 拖慢建立 | 低 | Tutorbase：一次性生成全期 series，後端非同步 INSERT；前端顯示進度 | NFR-002 < 5秒目標；生產資料量（每年 < 104 筆/科）可控 |
| end_date 後舊月結課程（無 end_date）行為改變 | 低 | 漸進式 migration：新欄位 nullable，舊資料 fallback | end_date nullable，null 時走舊邏輯 |
| 多科方案月結與堂數制排課邏輯混用 | 中 | 明確分支：date-range 用 buildSessionsFromWeeklySchedule，count-based 用 extendSessionsIfNeeded | 月結分支永遠不呼叫 extendSessionsIfNeeded（REVIEW 驗證） |
| 主任設定 end_date 後忘記續約導致課程中斷 | 中 | 業界標準：到期前 N 天主動提示（Tutorbase 7天前 email）| FR-010 P2：到期前 14 天橘色提示 + RenewMonthlyModal |

### 假設

- `buildSessionsFromWeeklySchedule` 透過 `app()->make(StudentClassController::class)` 可在 EnrollmentService 和 CoursePackageController 中複用
- 補習班慣例上課週期不超過 2 年，NFR-004 上限合理
- 多科月結方案各科 `start_date` 早於或等於方案 `end_date`

### 開放問題

無（所有設計決策已在 §8b Decision Log 確定）
