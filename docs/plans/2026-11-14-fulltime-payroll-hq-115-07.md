# PLAN：正職薪資要件照總部 115.07 公告重做（P0）

**Risk-Class:** 每一刀照 `pr_declaration.py` 的判定（第 2 刀 R2；第 3 刀動到路由與權限相關畫面，R3）。
**權威規則：** 台北全真總管理處公告（115.05.11 公告，115.07.01 生效）＋附檔 1 科目數獎金表。先前依「蘆洲長樂 docx」做的分校版規則作廢。不再跟其他系統對數字，只對公告。
**一段課：** 2 小時。
**這頁只結算獎金，不含本薪。**

## Founder 決定（2026-11-14／15）

1. 科目數獎金 = 附表[無條件捨去(核薪總科目數)]；一對三獎金 = 一對三總計 × 100；「20 科 +5%」只看正課。
2. 每週 16 段看排課：老師自己請假不算，學生請假照算。正課、輔導、試聽都用「時數 ÷ 2」。
3. 段數與一對三總計都看老師的時鐘時間：同一時段重疊的課只算一次。過去重疊被重複計算，造成薪水多算。科目數仍照每位學生加權。
4. 科目數用 AllTrue 自己的算法，來源就是「科目數統計」頁（`SubjectUnitsTimelineService`）；老師跑分校，全分校加總。
5. 16 段課獎金每月 4,000：該月每一週都排滿 16 段才發，有一週沒滿就沒有。
6. 假日（0–10%）與平日下午（0–5%）倍率：系統先算，主任可在範圍內改並寫原因，總部核准後生效。
7. 頁面盡量少人工填寫：系統算得出來的都自動算，只留人才知道的事。
8. 頁面不要有底薪：不顯示、不輸入、不核准。
9. 同一位老師的課表不能有兩種算法：這頁的課一律從 `TeacherClassCalendar` 讀。

## 公式

```
核薪總科目數 = (正課 + 輔導試聽) ÷ 8         ← 科目數統計頁的數字；頁面三欄同一個單位，加得起來
科目數獎金   = 附表[無條件捨去(核薪總科目數)]
一對三獎金   = 一對三總計 × 100               ← 一對三總計 = 一對三課的時鐘時數 × 0.5
教師倍率     = 100 + 假日(0–10) + 平日下午(0–5) + (正課 ÷ 8 ≥ 20 ? 5 : 0)
               + 行政加給(0–10) + 特殊表現(每項 5) + 扣除(每項 −10)
倍率後獎金   = 無條件捨去((科目數獎金 + 一對三獎金) × 倍率)
保底         = 到職前 3 個月且每週都滿 16 段 → max(2000, 倍率後獎金)
獎金合計     = 16 段課獎金 + 倍率後獎金(或保底) + 現金加扣款
```

數字只放 `backend/config/teacher_salary.php`；規則只寫在 `TeacherEligibilityPolicy`。

## 頁面怎麼設計（11-15）

方向：**系統先全部算好，主任只看「需要你處理」的那幾筆。** 不照抄任何現有系統的欄位。

參考的成熟做法（只取做法，不取畫面）：
- 發薪前檢查清單，分「會擋住」和「提醒」兩種（Gusto 的發薪檢查步驟、Workday 的薪資稽核例外）。
- 每個數字點得開，看得到是哪些課、哪條規則算出來的（CaptivateIQ 的獎金明細）。
- 一次性加扣款是有日期、有原因、有核准的獨立項目，不是改總數（Frappe HR 的 Additional Salary）。

畫面：
1. **頂部**：月份、分校、狀態（草稿／已鎖定）、匯出、鎖定。
2. **需要你處理**（排最上面，沒有就不顯示）：待主任確認、待總部核准、資料不足算不出來、跟上個月差很多（先用 30%，可調）。點一筆直接到那位老師。
3. **主表**：老師｜正課｜輔導試聽｜核薪總科目數｜一對三總計｜科目數獎金｜一對三獎金｜教師倍率｜倍率後獎金｜加扣款｜獎金合計。全部唯讀。
4. **點一列 →「怎麼算的」**：每週段數（一週一列、達標與否、哪些課）、倍率逐項（系統算的／主任改的／核准狀態）、科目數對到附表哪一列、加扣款明細。
5. **規則說明卡**：內容直接來自設定檔，改規則不用改畫面。

人工只剩三種（其餘全自動）：
- 行政加給、特殊表現、扣除：人才知道的事，沿用現有「主任確認 → 總部核准」。
- 現金加扣款：有金額、原因、起訖月。
- 倍率調整：系統算的假日／平日倍率不合實況時，主任在範圍內改並寫原因。

拿掉：底薪、手動輸入總倍率（改成逐項調整）、「本週／本年度」切換。
