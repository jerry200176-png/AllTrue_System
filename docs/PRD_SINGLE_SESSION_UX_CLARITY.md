# PRD — 單堂操作頁語意澄清

> 版本：1.0 | 日期：2026-04-14 | 狀態：已實作 UI 變更，待營運驗收

---

## 1. 背景與問題

從智慧排課（SmartCalendar）或課程管理（CourseManagement）點擊單堂課程時，彈窗中同時顯示「星期幾」（disabled）與「首堂上課日期」（disabled），一線操作人員（主任、櫃台、排課人員）容易誤解：

- 把「首堂上課日期」當成「本次上課日期」
- 把「星期幾」當成可修改欄位，而非整門課的固定排課星期
- 無法快速區分「本堂資訊」與「整門課契約設定」

## 2. 設計目標

- 操作人員能在 3 秒內正確辨識「本堂日期」與「整門課設定」
- 消除「可修改整門課」的視覺暗示
- 跨頁面術語一致（SmartCalendar / CourseManagement / SessionEditModal）

## 3. 已實作變更摘要

### 3.1 SmartCalendar 單堂檢視 modal

| 項目 | 舊版 | 新版 |
|------|------|------|
| 標題 | 檢視／單堂操作 | **單堂檢視** |
| 頂部提示 | 「正在檢視 YYYY-MM-DD（星期X）此堂」文字段落 | **本堂資訊卡**（綠底卡片：本堂日期 + 上課時間） |
| 星期幾 dropdown | 獨立 disabled 欄位 | **移除**（星期已顯示在本堂資訊卡括號內） |
| 首堂上課日期 | disabled 欄位 | **移除**（與單堂操作無關） |
| 行動按鈕位置 | 表單最下方 | **上移至本堂資訊卡下方**（第二優先層級） |
| 課程參考區 | 無區隔，與本堂混在一起 | **灰底區塊「課程資料（僅供參考）」** + 說明文字 |
| 時段/費用/繳費 | 混合可編輯與不可編輯 | 在編輯模式改為**純文字顯示** + 「僅供參考」標示 |

### 3.2 SessionEditModal（課程管理內的單堂操作）

| 項目 | 舊版 | 新版 |
|------|------|------|
| 標題 | 單堂課操作 | **單堂檢視** |
| 日期欄位 | 「日期」 | **「本堂日期」** |
| 時段欄位 | 「時段」 | **「上課時間」** |
| 操作區標題 | 「操作」 | **「單堂操作」** |

### 3.3 QuickAddSessionModal（加課/補登）

| 項目 | 舊版 | 新版 |
|------|------|------|
| 日期欄位 | 「上課日期」 | **「本堂日期」** |

### 3.4 資訊層級設計

```
第一層（最高優先）：本堂資訊卡（綠底）
  └ 本堂日期 + 星期
  └ 上課時間（起~迄 + 時數）

第二層（行動區）：單堂操作按鈕
  └ 加課 / 請假 / 調課 / 換代課

第三層（參考區，灰底）：整門課資料
  └ 課程資料（學生/科目/老師/類型）
  └ 時段與費用
  └ 繳費狀態
```

## 6. 風險清單

| 風險 | 等級 | 緩解措施 |

## 7. 角色權限驗證

| 角色 | 可見操作 | 驗證項目 |
|------|----------|----------|
| director / admin | 全部單堂操作（加課/請假/調課/換代課） | 四個按鈕皆可見 |
| teacher | 加課/請假/調課（無換代課） | 「換代課」按鈕隱藏（`v-if="!isTeacher"`） |
| 家長 | 無（家長入口不使用此 modal） | N/A |

## 8. 稽核紀錄覆蓋

單堂操作（請假/調課/加課/換代課）的關鍵行為已有後端稽核：

| 操作 | 後端寫入 | 追溯方式 |
|------|----------|----------|
| 請假 | `schedules` (status=leave) + `ClassSession` (status=leave) | `schedules.created_at` + `user_id` |
| 調課 | `schedules` (status=rescheduled) + 新 `schedules` | `original_schedule_id` 關聯 |
| 加課 | `schedules` (type=extra) + `ClassSession` | `schedules.created_at` |
| 換代課 | `ClassSession.substitute_teacher_id` | `updated_at` |

> 本次 UI 變更不新增或移除任何稽核點。

## 9. 事件應變

若上線後出現大量誤操作或客訴：

1. **即時回滾**：`git revert` 對應 commit + `cd frontend && npm run deploy`
2. **公告**：通知各分校「系統已恢復舊版面，操作方式不變」
3. **調查**：收集具體誤操作案例，判斷是文案問題還是流程問題
4. **修正後重新上線**：經 PM + 營運確認後再次部署

## 10. 上線策略

- 本次為全量上線（四分校同時生效），因為：
  - 純前端文案/版面變更，無資料風險
  - 回滾成本極低（1 分鐘內可完成）
- 上線後 7 天觀察期：
  - 收集各分校操作人員回饋
  - 監控是否有操作疑問增加

## 11. UX 驗收指標

| 指標 | 目標 | 量測方式 |
|------|------|----------|
| 理解時間 | < 3 秒辨識本堂日期 vs 整門課資訊 | 營運人員口頭測試 |
| 誤判率 | < 10% 把首堂當本堂 | 5-8 人可用性測試 |
| 任務成功率 | >= 95% 正確完成單堂請假 | 情境任務測試 |
| 主觀清晰度 | >= 4/5 | 簡化問卷 |
