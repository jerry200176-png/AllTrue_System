# 月結帳單：月底才定案、多收自動抵、一顆「更正帳單」

**一句話：** 月結帳單在月中只是「預估」，金額跟著上課走；月底主任按一次「定案」才固定。多收的錢在定案時自動轉到下個月的帳單。定案後要改金額，只能按「更正帳單」，開一張新的、舊的作廢、兩張連在一起。

相關：計畫 `帳務中心重整`（#4991）、[`REF_BILLING_DATA_DICTIONARY.md`](../REF_BILLING_DATA_DICTIONARY.md)、[`RFC_REPORTED_PAID_ACCOUNTING_SPLIT.md`](RFC_REPORTED_PAID_ACCOUNTING_SPLIT.md)。堂數制（`count`）的金額規則**不變**。

---

## 1. 為什麼要改

- 月結續課當下就照「預排堂數 × 單價」開正式帳單（`ContractRenewal::renewMonthly`，`backend/app/Services/Billing/ContractRenewal.php:1264`）。之後請假、改單價、提前結束，帳單跟現實就不一樣（in-app #555 #557 #558 #560；合約 3256、4318、4635）。
- 為了補這件事，系統疊了五種特例，各畫面套得不一樣：
  1. 單月、未收款的帳單，讀的時候重算（`InvoiceAmountReconciliationService::resolve()` 108-134）。
  2. 服務期間跨月的帳單，不重算（同檔 89-106）。
  3. 第一次收款時把金額凍結（`MonthlyBillFreeze::priceBeforeFirstPayment`，`BillingController::recordPayment` 253-275 另有一份一樣的）。
  4. 月中暫緩（`MonthlyPeriodPaymentService` 97-105、198-215 的 `amount_deferred`）。
  5. 「需核對：帳單金額跟照堂數算的不一樣」（`amount_discrepancy`）。
- 已收款的帳單沒有正式的「更正」：畫面只寫「請聯絡總部」。寫好的更正程式（`AgreedFeeCorrection`、收據改掛、`receipt_correction_reissue`）都關著或沒有按鈕，而且只管未收款或只管堂數制。

2026-11-16 正式資料：未繳 97 張、NT$ 722,343；月結真跨月未繳 14 張（125,000）；預先開好的月結帳單約 40 張。

## 2. Founder 已決定（2026-11-16，不再重問）

1. 月結帳單**全部月底才定案**；月中只有「預估」。
2. 先收的學生，實際上課比收的少：**差額留到下個月抵**。
3. 已收款的帳單，**主任可以自己更正**，一定要寫原因，總部看得到全部紀錄。
4. 改正式資料一律：試跑 → 核准 → 執行，可還原。
5. 堂數制還沒開帳單時，金額＝合約學費（10/11，不變）。
6. 更正帳單先在大安分校試，再全開（11-17，「A」）。

## 3. 模型

### 3.1 一張月結帳單只有三種狀態

| 狀態 | 怎麼認 | 金額從哪來 | 能不能收錢 |
|---|---|---|---|
| **預估** | `finalized_at IS NULL` | 每次讀都重算：這個月已上的堂 × 當天單價 ＋ 還沒上的預排堂 × 單價（`MonthlyBillingService::summarizePeriod()` ＋ `remainingScheduledCharge()`）。存的 `TotalAmount` 只是上次算的快照。 | 可以（先收） |
| **定案** | `finalized_at IS NOT NULL`，不是作廢 | 存的 `TotalAmount`。之後只有「更正帳單」能改。 | 可以 |
| **作廢** | `Status = 'void'` | — | 不行 |

「已繳／未繳／多收」**不是狀態**，一律由收款紀錄算（`Invoice::netPaidSql()`，字典規則 2）。

堂數制的帳單一開就是定案（`finalized_at` = 開立時間），所以「更正帳單」兩種課都能用。

### 3.2 唯一的金額規則（取代上面五種特例）

> 預估帳單：金額＝重算的預估。定案帳單：金額＝存的金額。沒有別的情況。

所以 `resolve()` 的月結分支變成一行判斷；跨月不重算、首次收款凍結、月中暫緩、`amount_discrepancy` 都刪掉（§7）。這是**刪特例**，不是在 `resolve()` 加特例。

### 3.3 一個月一張

- 每份月結合約、每個有上課的月份，最多一張沒作廢的帳單（`billing_period` = 那個月，明細的 `PeriodStart`/`PeriodEnd` 在那個月裡面，P9）。
- **續課不再開帳單**（改 `renewMonthly`）。帳單在兩個時候出現：家長先繳錢時（現有的 `PaymentReportController::confirm` 513-530 本來就會在沒有帳單時開一張，月份由 `collectionPeriodFor()` 決定，開出來是**預估**），或月底定案時。
- 跨月的續課週期（例如 8/15–9/26）不再是一張帳單，而是 8 月一張、9 月一張。

### 3.4 多收的錢＝餘額，不另外存

- 定案時，如果這張帳單收到的錢比定案金額多，多的部分記成「多收（待抵）」。
- 下一個月定案時，系統先把同一條合約鏈（續課前後的合約）**前面定案帳單的多收**，用一對非現金收款紀錄轉過來抵：舊帳單一筆 `transfer_out`（負）、新帳單一筆 `transfer_in`（正），兩筆連在一張連結表上。這跟跨科轉用（`PaidContractCreditMovement`）、手足轉課（`SiblingContractTransfer`）是同一個做法。「這不是收到現金」已有一個判斷 `Payment::isCreditMovement()`（`Payment.php:52`），帳務明細（`AccountingController.php:560`）和 `BillingPayableResolver.php:502` 已經在用；PR 1 要把每個現金報表（收款日報、月報、銀行對帳）逐一核對有沒有用它，沒有的補上。
- 學生的「餘額」＝ 他所有定案帳單的多收加起來（還沒轉走的部分）。**用算的，不存一個數字**（Kill Bill：餘額由帳單和收款算出）。
- 合約結束、沒有下一期：多收留在畫面上「餘額 NT$ X」，主任可以按「退多收」，或等下次續課自動抵。
- **「退多收」是新的寫入**，不是現有退費：現有 `BillingRefundService::assertRefundable()` 拒絕月結與已停的合約，`preview()` 也拒絕有多收的帳單，而且它會調低帳單金額並結束課程。退多收只做一件事：在有多收的定案帳單上記一筆 `Method = 'refund'` 的負數收款（現金流出），金額 ≤ 那張帳單目前的多收；不改帳單金額、不動課程。原因必填、可重送一次、有紀錄（放在 PR 3）。

> **Agent 決定的事（與已核准計畫不同的地方）：** 計畫第 3 步原本要「新增一張只增不改的餘額帳」。這份規格改成「用現有的轉入／轉出收款紀錄把多收轉到下個月，餘額用算的」。理由：使用者看到的行為完全一樣（月中預估、月底定案、多的下個月抵）；但不用新的錢的資料表、不用改 `Payment.InvoiceID`（目前 NOT NULL）、不用改所有現金報表。代價：每次抵一筆會多兩筆收款紀錄。

### 3.5 月底定案

- 位置：帳務中心「月結」分頁（現有 `MonthlyDraftsPanel`、`GET accounting/monthly-drafts`，`AccountingController::monthlyDrafts` :46）。每個月 1 號起，列出上個月還沒定案的合約，主任按一次「全部定案」。也可以一張一張按。
- 定案做的事（每份合約、每個月，一個交易、同一把鎖、可重送）：
  1. 這個月有沒有「過去還沒點名的堂」？有 → **這份不定案**，列進「需要處理」，寫出日期（跟 #5398 調整總堂數同一個規則）。
  2. 算定案金額 ＝ 這個月已上的堂 × 當天單價（`summarizePeriod()`，`source = billable_sessions`），**先排除已經被別張沒作廢帳單的明細服務期間涵蓋的堂**（舊的跨月帳單；沿用 `MonthlyBillingService::unbilledPeriodFor()`（`app/Services/MonthlyBillingService.php:137`）對 `InvoiceItem` 服務期間的檢查）。整個月都被涵蓋 → 不開帳單。回歸：一張已繳的 11 月帳單涵蓋 11/15–12/26，12 月定案只算 12/27 以後的堂。
  3. 沒有帳單 → 開一張（定案）；有一張預估 → 把金額寫進去、寫 `finalized_at`、存證據快照（堂數、期間、單價）到 `billing_snapshot`。
  4. 拉前面定案帳單的多收來抵（§3.4）。
  5. 這個月 0 堂而且也沒收錢 → 預估帳單作廢（原因「本月沒有上課」），不留 0 元帳單。
- 不會自動定案。主任沒按，畫面一直顯示「預估」，「需要處理」清單會提醒。

### 3.6 更正帳單（第 2 步）

只給**定案**的帳單（含所有堂數制帳單）。預估帳單不需要：改合約的單價或堂數，預估就跟著變。

- 按鈕在學生帳務的帳單列 ⋯、合約卡 ⋯。主任（自己分校）或總部可用，原因必填（至少 2 個字），先預覽再確認，同一個操作識別碼重送只會做一次（P7）。
- 做的事：開一張新帳單（新金額、同月份、同合約，定案）；舊帳單作廢並在 `invoice_corrections` 連結兩張（`kind = 'bill_correction'`，舊金額、新金額、原因、操作者）；舊帳單上**所有已收的錢**（不只多收）用一對 `transfer_out`／`transfer_in` 轉到新帳單，轉完舊帳單的已收是 0。
- 結果自然出來：新金額比已收多 → 新帳單還要補收；比已收少 → 新帳單多收，下個月定案時自動抵，或按退費。
- 堂數制：同時把合約的 `Charge` 改成新金額（現在 `AgreedFeeCorrection` 已經這樣做，只限未收款）。
- 總部多一頁「更正紀錄」：誰、什麼時候、哪張、從多少改成多少、原因。
- 不能更正：作廢的帳單；已經被更正過的；有待確認的繳費回報（先確認或撤銷）；多科合收的帳單（先拆）。

### 3.6.1 錢被轉走之後，撤銷收據怎麼辦

收據（`payment_reports`）指的是原本那張帳單。錢被「抵」或「更正」轉走以後，原帳單的已收可能是 0；現在的 `PaymentReportController::void()` 遇到「作廢帳單、已收 0」會當成「已經沖銷過」，回「已撤銷收款」卻沒有把錢從新帳單拿掉。所以：

- 撤銷收據前，先找出**這張收據入帳之後**從同一張帳單轉出去的錢（`billing_carry_forwards`、`kind = 'bill_correction'` 的 `invoice_corrections`），**沿著轉帳鏈往下追**（A→B 之後又 B→C，就追到 C），從最後一段開始依相反順序倒轉（`transfer_reversal_out`／`transfer_reversal_in`，`Payment::isCreditMovement()` 已認得），倒轉的金額合計只到這張收據的金額為止；錢回到原帳單後再照現有流程沖銷。每一段的連結表都記了來源、目標帳單，所以追得到。
- 收到錢的那張帳單因此變成「還要補收」，畫面照常顯示。
- 倒轉後那張帳單的已收會變成負的（例如錢已經被退多收退掉）→ **拒絕撤銷**，說明要先處理哪張帳單。
- 回歸測試：更正已收款帳單後撤銷原收據；月底抵到下個月後撤銷原收據；A→B→C 轉兩次後撤銷 A 的收據；都要確認錢從最後收到的帳單上消失、中間帳單回到 0、現金合計正確。
- 開關：只對列在設定裡的分校打開（先大安），Founder 核准上線時才加分校。

### 3.7 狀態轉換表（#4991 P6）

| 從 | 到 | 誰 | 怎麼 |
|---|---|---|---|
| （沒有） | 預估 | 系統 | 月結合約先繳錢時（`confirm`／主任登記收款） |
| （沒有） | 定案 | 系統、主任 | 月底定案；堂數制開帳單 |
| 預估 | 定案 | 主任、總部 | 月底定案 |
| 預估 | 作廢 | 系統、主任 | 定案時本月 0 堂且沒收錢；主任作廢（沒有收款時） |
| 定案 | 作廢＋新的定案 | 主任、總部 | 更正帳單 |
| 定案 | 作廢 | 主任、總部 | 現有作廢（只限沒有收款；有收款請用更正） |
| 定案 | 定案（金額調低） | 主任、總部 | **只限堂數制現有退費**（`BillingRefundService::refund()`，`BillingRefundService.php:88-94`：記負數收款、加一行「退費」明細、`TotalAmount` 一起調低）。規則不變，所以保留；月結不走這條（月結用「退多收」，§3.4） |

除了這張表，不准別的地方寫 `Status`、`TotalAmount`、`finalized_at`。之後加一個架構測試擋直接寫入（P6）。

## 4. 不變式（每個 PR 都要有測試）

1. 定案帳單的 `TotalAmount` 只會經由「更正帳單」改變（作廢＋新帳單）；唯一例外是 §3.7 列的堂數制現有退費。回歸：PR 1 之後堂數制退費照常成功，帳單明細合計仍等於 `TotalAmount`。
2. 每份月結合約、每個月，沒作廢的帳單最多一張。
3. 每一對轉入／轉出加起來等於 0。**抵**：轉走的錢 ≤ 來源帳單定案後的多收。**更正**：轉走的錢 ＝ 舊帳單當下的全部已收（全額、部分收款都要有測試）。任何帳單的已收、任何學生的餘額都不會是負的。
4. 定案、抵、更正都不改變現金合計（`Payment::isCreditMovement()` 為否的收款紀錄總和）。
5. 預估和定案用同一個算法（`summarizePeriod()`），差別只在「還沒上的預排堂」要不要算。

## 5. 收款規則

- 先收：月結合約還沒定案的月份可以收錢。上限＝這份合約所有還沒定案月份的預估合計 − 已收 − **同一條合約鏈上可以抵的多收**（範圍跟 §3.4 自動抵的一樣；別科、別條合約鏈的多收不算）。擋打錯字，但允許一次繳整個週期。回歸：同一位學生英文多收 1,000、數學一份新合約，數學的上限不受影響。取代 `monthly_amount_stale`（`PaymentReportController` 456-479、735-752）和 `amount_exceeds_outstanding` 對月結的判斷。
- 少繳：照舊允許。
- 繳費單：預估帳單列「這個月已上＋預排的堂」，金額寫「預估」；定案帳單列這個月實際上的堂（`MonthlyBillingService::invoiceCoveredSessions()`）。

## 6. #5372、#5385 被抓到的問題，這裡怎麼解

| 問題 | 解法 |
|---|---|
| 月中收了一次款之後，再上的課不會被算進去 | 收款不凍結金額；月底定案才固定，那時所有上過的課都算進去。 |
| 期間從月中開始的帳單，會把上一張算過的課再算一次 | 一個月一張，期間＝那個月；每堂課只屬於一個月份。 |
| 帳單裡的教材費會被吃掉 | 月結帳單只放學費。教材費另開一張（手動開帳單），不參與定案重算。舊帳單裡已經有教材費明細的，過渡時拆出來（§8）。 |
| 先收的學生收不了錢（還沒上課時應收是 0） | 上限用「預估」（含預排），不是「已上」。 |
| 折扣續課被用沒折扣的單價重算 | 單價一律從 `StudentClassPricingService::forDate()` 拿（含舊合約的折扣快照）；交易折扣功能已關（Founder 10-14）。 |
| 繳費單課表只列帳單月份 | 一個月一張，帳單月份就是全部。 |
| 既有檢查工具會當掉 | 每個 PR 跑完整 CI；檢查工具的輸入改讀 `finalized_at`。 |

## 8. 舊資料過渡

1. **資料表（只新增，Founder 核准 migration）：** `Invoice.finalized_at`（DATETIME NULL）；連結表 `billing_carry_forwards`（來源帳單、目標帳單、金額、轉出／轉入收款紀錄、操作者、時間、操作識別碼唯一）。
2. **回填（同一個 migration，`chunkById`）：** 所有帳單 `finalized_at = created_at`，**除了**：月結、沒作廢、`billing_period` 是本月或以後、沒有任何收款紀錄的帳單（留 NULL＝預估）。已收款的帳單一律當定案，**金額不動**。
3. **過去月份還沒收款的月結帳單**（約 40 張，含 14 張跨月）：回填後是「定案」、金額照舊。要改成實際上課的金額，用受控操作：試跑列出（帳單、舊金額、照實際上課算的金額）→ Founder 核准 → 用「更正帳單」同一個寫入路徑執行，可還原。
4. **含教材費明細的未收款月結帳單：** 同一個受控操作裡把教材費拆成自己的帳單。
5. 分校開關：`finalize` 與新的金額規則只對設定裡的分校生效；沒開的分校照舊。全部開完、30 天沒有差異，才做 §7 的刪除。
