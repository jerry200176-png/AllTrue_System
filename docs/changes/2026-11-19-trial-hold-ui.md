## 2026-11-19 — feat(calendar): 試聽暫留：先留老師時段，之後轉成正式試聽（#5499，in-app #575）
<!-- release-notes: staff_update=staff-2026-11-19-trial-hold -->

- 智慧行事曆工具列多一顆「試聽暫留」，只有主任和 super_admin 看得到。按下去選老師、日期、起訖時間，可以寫備註（100 字內），就能留住時段。
- 暫留會以虛線框卡片顯示在週檢視和日檢視，位置和高度依實際分鐘數，會照老師篩選。點卡片可以看細節並「取消暫留」，同一個框裡也寫了怎麼轉成正式試聽。
- 招生詢問的「安排試聽」多一個「用試聽暫留（選填）」選單，只列本分校 60 天內的暫留。選了之後老師、日期、開始時間、分鐘數自動帶入，送出時帶 `trial_hold_id`。
- 讀暫留失敗時只是不顯示卡片，不會擋到其他功能；衝堂由伺服器擋。

**後端**
- 新表 `trial_holds`（additive，只新增），新 API 三支：`GET/POST /api/v1/trial-holds`、`POST /api/v1/trial-holds/{id}/cancel`。只開給主任和 super_admin，而且只能操作自己授權的分校，老師必須屬於該分校。
- 暫留不建學生、課程、點名、扣堂或帳單。它在衝堂檢查裡算成「一個試聽席位」，所以沿用現有規則：同時段只能有一個試聽，一對一的課不能疊上去，一對三時段占一個位子。
- 會算進暫留的地方：依日期的衝堂檢查（`buildTeacherDateOccupancyEntries`）、改課程與轉課的循環檢查（`collectConcreteRecurringOverlaps`）、找空堂和跨分校忙碌（`SubstituteService`）。
- 取消暫留只改狀態、保留紀錄，時段立刻空出來。
- 這個 PR 沒有畫面；行事曆顯示與「轉成正式試聽」在下一步。表裡沒有資料時，現有排課行為完全不變。回復方式：revert 這個 PR（表留著不影響）。

**轉成正式試聽**
- 招生詢問的「安排試聽」API 多一個選填參數 `trial_hold_id`。帶了它時，系統會先鎖住那筆暫留，並確認分校、老師、日期都一樣。確認過後，試聽就排進暫留占著的位子，暫留改成「已轉試聽」，並記下對應的課程。
- 暫留已經取消或已轉過，回 409；分校、老師或日期不同，回 422。兩種情況都不會寫入任何資料。
- 一起修：安排試聽失敗（例如衝堂）時，原本是把錯誤「回傳」出去，外層交易會照樣提交。現在改成「丟出」錯誤，外層交易會整筆撤回。
- 沒有帶 `trial_hold_id` 時，行為跟以前一樣。
