## 2026-11-13 — fix(ops): the contract-chain repair refuses only for the contracts a move touches; other gaps become warnings (#5124)

<!-- silent-reason: internal ops operation; no screen, no API route; changes data only after a Founder-approved POP request -->
- POP operation `course-contract-chain-rebalance` (#5124, #5162). A dry-run was refused with `mirror_inconsistent` on a chain contract that no move touched (a deduction-ledger gap that was already there), which blocked an unrelated correction. `mirror_inconsistent` and `counters_not_derived` now refuse only for the contracts a move touches (both ends of every move), the listed lessons, and any lesson whose sign-in, learning record or ledger row points at a touched contract. The same finding on an untouched chain contract is returned in a new `warnings` list (`code`, `contract_id`, `session_id`), is part of the `digest` (a plan with a warning never shares a digest with the plan without it), and is stored with the execute result and snapshot. Execute and verify check that an untouched contract's usage figures are exactly the ones recorded before the first move, so a run cannot hide or worsen the gap. Every warning needs its own repair row on #5162. On a touched contract, minute counters that are NULL (never recomputed) are accepted because the execute's recompute writes the derived values; any other non-derived value is still refused. Runbook: `docs/OPERATIONS_RUNBOOK.md`.
