## 2026-11-01 — fix(scheduling): lowering a shared plan trims the pool, and a reviewed command cleans old over-planned pools
<!-- release-notes: staff_update=staff-2026-11-01-shared-pool-trim -->
- Lowering a shared count plan's total used to cancel only per subject. A 2-subject plan cut from 6 to 4 kept all 6 lessons. A cut now cancels the latest planned lessons of the whole pool past what is left. `SharedPackagePlanningService::sharedPoolExcess` uses the same count as the plan summary. A slot that something points at (a sign-in, ledger, note, substitute or payroll row) is never touched.
- `packages:trim-shared-pool` removes what pools pre-planned before #4730. It is a dry run by default. `--execute` needs the dry run's `plan_sha`, and production also needs `--force` and `ALLOW_PROD_REPAIR=1`. Rows are deleted, not cancelled, so a renewal re-fills those dates, and every deleted row stays in `schedule_audit_logs`. Running it on production data needs a separate Founder-approved run.
