## 2026-10-22 — POP in-app agent credential (ADR-POP-015 part 2, backend)

<!-- silent-reason: no screen yet; the super-admin issuance UI is a separate follow-up PR, and the standing policy flag stays off -->

New `pop_inapp_agent` ApiClient purpose (ADR-POP-015 §2–4). A super admin issues it through `POST /api/v1/admin/pop-inapp-agent-clients` with an explicit, non-empty campus list; the raw key (`alltrue_pop_inapp_…`) is returned once, only its sha256 is stored, and it expires after `pop_inapp.agent_client_ttl_days` (90). With `X-POP-MACHINE-KEY` it can only draft and dry-run the operations `InappStandingPolicy` governs, on its listed campuses, and dry-run only its own requests; it cannot approve or execute. `InappRequesterGuard` now allows a standing-policy approval only for such a client (active, unexpired, issuer still an active super admin) and attributes write-backs to the issuing super admin (`ApiClient.IssuedByUserID`); anything else fails closed. Revoking the client (`DELETE …/{id}` or the existing api-clients revoke) cancels its policy-approved, unexecuted POP requests in the same transaction with a `policy_revoked` event. `X-API-KEY` (attendance swipe) now accepts attendance-device clients only. Additive migration on `ApiClient` (`IssuedByUserID`, `CampusIDs`, `ExpiresAt`, all nullable); no credential is created by this change. Regressions: `PopInappAgentClientTest`. Rollback: revert the code; the nullable columns can stay.
