## 2026-10-23 — A re-attended lesson debits the shared package again
<!-- release-notes: silent_ship=silent-2026-10-23-package-ledger-net-idempotency -->
<!-- silent-reason: billing ledger correctness; no screen or wording changes, the shared pool now matches the lessons taught -->

A lesson marked attended, reverted (for example back to scheduled), then marked attended again was debited again on its course ledger (net-based since #1338) but not on the shared package ledger, which still skipped any session that had ever had a debit row with the same reason, and group packages skipped any slot that had ever had a debit. The pool then showed one lesson fewer than was taught (in-app 419, #4275). The package ledger now uses the same net rule: a session is debited only while its package net is not negative and credited only while it is negative, so a credit is never written for a session that was never debited. Each cycle gets its own reason code (`attendance`, `attendance#2`, ...) to fit the existing unique key, with no schema change. Group packages keep one debit per (date, start time) slot while any member's lesson in it is still charged; reverting the member that carries the slot debit moves it to another member who is still charged (`group_slot_carry`). Writes lock the package row. Existing ledger rows are not rewritten. Regressions: `PackageLedgerNetIdempotencyTest`, `PackageConcurrencyTest::test_deduct_reverse_rededuct_sequence`. Rollback is a normal revert.
