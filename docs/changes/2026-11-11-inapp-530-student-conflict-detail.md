## 2026-11-11 — fix(schedule): the "add next lesson" student-conflict refusal names the lesson holding the slot (in-app #530)
<!-- release-notes: staff_update=staff-2026-11-11-student-conflict-detail -->
- Adding the next manual lesson is refused with `student_conflict` when the same student already has a live lesson overlapping the slot (this contract or another one). The refusal was correct but gave no detail, unlike teacher/room conflicts, so a director could not tell which lesson held the slot.
- The check and create responses now carry `conflict_detail` and `conflicts[].overlap_details` in the same shape as teacher/room conflicts (date, time, subject, contract period, and `same_contract`). The dialog lists the lesson, says whether it is on this contract or another one, and offers the existing open-course and change-time buttons. When a conflict is raised, the code `student_conflict`, HTTP statuses, deduction and billing are unchanged; the rows are the student's own sessions, so no other campus is reachable.
