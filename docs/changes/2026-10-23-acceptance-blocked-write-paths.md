## 2026-10-23 — Production acceptance names the HTTP write its read-only guard blocked
<!-- release-notes: silent_ship=silent-2026-10-23-acceptance-blocked-write-paths -->
<!-- silent-reason: CI/ops log line only; no product change -->

Since #4450 the log shows a flaky first attempt failing at the `afterEach` expectation `read-only acceptance must not send HTTP writes to any origin`, but not which write the guard aborted. `readOnlyAppGuard.js` now gives each unexpected blocked write a public-log-safe name, `METHOD host /path`: the host, no query string, no body or header, and every path segment that is not a plain lowercase route word or `vN` replaced by `:id` (repeats become ` xN`). `calendar-course-consistency.spec.js` records them as `blocked-write` annotations of the failing attempt and puts the same names in the expectation message. `acceptance-report-gate.mjs` prints them under that attempt's `failed-attempt` line, only when a note matches exactly that shape; anything else is counted as `withheld=N`, never echoed. The guard is unchanged (no write is allowed that was not before) and the gate's verdict is unchanged. Unit tests cover the naming, and one runs the gate on a guard-made report so the two patterns cannot drift apart.
