## 2026-10-22 — Enforce the calendar acceptance read-only boundary
<!-- release-notes: silent_ship=silent-2026-10-22-calendar-acceptance-read-only-guard -->
<!-- silent-reason: acceptance harness safety only; no product runtime change -->

Calendar/course acceptance installs the browser-context HTTP guard before each test, blocks service workers, and fails when an HTTP write to any origin is attempted. GET/HEAD/OPTIONS pass through; only app-origin adoption POST telemetry is answered locally with 204. All other writes, including Sentry and other third-party telemetry, are aborted before the first hop. This deliberately replaces the earlier third-party-write exemption: Playwright does not route redirected follow-up requests, so permitting a third-party POST could carry a write through 307/308 redirects back to the app. Popup pages share the same boundary. Native read transport and redirect handling are retained without `route.fetch`; this guard does not cover WebSockets or direct APIRequestContext requests.

This integrates #4139's source into current main while retaining the newer course-payment ledger entry checks and sidebar-search navigation assertions. Unit and three-local-server Chromium self-tests exercise direct and popup writes, single/multiple 307/308 redirect targets, POST/GET 303 controls, reads and the local adoption stub without a production session or credential. Tests assert that neither the app nor third-party servers receive an unsafe HTTP request. No production acceptance, application deployment or reporter verification is implied. The exact T3 smoke-control merge decision and fresh final-head CI/review remain required; rollback is a normal revert of this acceptance-only change.
