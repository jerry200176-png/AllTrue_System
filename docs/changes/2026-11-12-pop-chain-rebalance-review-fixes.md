- POP operation `course-contract-chain-rebalance` (#5124, #5162), review follow-up to #5236, before any production run. The dry-run now refuses `future_reservation_policy: report` when the chain has an active contract or the cascade decision is given (`report_policy_requires_no_active_contract`), and refuses a chain whose stored lesson counters are not the derived ones (`counters_not_derived`; stop and report, do not edit counters by hand). A request that was already restored is refused by its execution records (`restore_already_applied`), also after another request moved the same lessons again. A failed execute or restore gets its failed receipt also when a deadlock makes the transaction rollback itself throw; no data change is committed. Verify's money fingerprint covers the chain only. Undo is a new approved request with `restore_request_id`; the catalog note no longer names POP rollback as a path. Runbook: `docs/OPERATIONS_RUNBOOK.md`.
