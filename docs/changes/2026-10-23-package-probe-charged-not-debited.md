## 2026-10-23 — Package ledger probe lists lessons charged on the course but not on the pool
<!-- release-notes: silent_ship=silent-2026-10-23-package-probe-charged-not-debited -->
<!-- silent-reason: operator diagnostic workflow; no product code or data change -->

`inapp-package-ledger-probe` gains a `charged_slots_not_debited` section and a per-package count in `summary`. It lists member lessons still charged on their course ledger (deduct minus reverse > 0) whose package debit is missing. Group class types (one_on_two, one_on_three, one_on_many, tutoring) debit one (date + start) slot for all members, so they are reconciled per slot. Every other package debits each lesson, so it is reconciled per lesson (`scope`). These are repair candidates for the package ledger's old row-based idempotency, which skipped a lesson reverted and then attended again (#4275, in-app #419). Not every row is a gap. `charged_before_package` = 1 marks a lesson last charged before the package was made: a single-to-shared conversion seeds non-attended lessons as session-less rows, so check `debits_without_session`. The summary counts only the other rows (`charged_since_package_not_debited`). A non-chargeable status is a course-ledger question. The slot net is pre-aggregated once per package. The section lists session ids, dates, start times, statuses, the slot net and the flag; it shows no names, amounts or notes. It still runs in one MySQL READ ONLY session that is rolled back.
