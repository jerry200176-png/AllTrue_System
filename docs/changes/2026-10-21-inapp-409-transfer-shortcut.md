## 2026-10-21 — fix(course): 課程設定被擋下時，可一鍵改用「轉課」並自動帶入內容
<!-- release-notes: staff_update=staff-2026-10-21-inapp-409-transfer-shortcut -->

- in-app #409 / GitHub #4151：堂數制課程上到一半想改科目、老師或時段時，主任在「課程設定」儲存會被擋下（已有上過的堂次或已有扣堂紀錄），訊息沒有指出下一步。
- 被擋下的回應若同時改了科目、老師或每週時段，且課程通過與轉課端點相同的資格檢查（堂數制、按堂計費、非共用方案、未結清、無待處理繳費回報等），已有使用量、仍有剩餘堂數與未點名的堂次，回應的下一步（`next_step`）改為 `course_transfer`，並附上轉課日（第一堂未點名的課）；沿用課程編輯既有的「下一步」對照（courseEditability.js），一次只顯示一個下一步。
- 課程設定與舊版編輯視窗的儲存失敗訊息改由同一個元件（CourseSaveErrorAlert）呈現，下一步按鈕為「改用轉課（M/D 起生效）」，開啟既有的轉課視窗並帶入剛才填的科目／老師／全部每週時段與轉課日；若同時改了購買堂數等鎖定欄位，畫面會明確說明轉課不會套用這些修改；送出仍走原本的轉課 API，轉課日之前的上課與扣堂紀錄不變。
- 不改變任何鎖定規則（BillingContractLockGuard、改科目檢查）、帳務、權限或既有資料；月結、已結清課程維持原本訊息。
- 「轉移已上課紀錄」（把已上課紀錄搬到另一份合約）改名為「搬移上課紀錄」，讓「轉課」只指從某天起改科目／老師／時段。
- 轉課視窗改由單一 `openCourseTransfer(course, prefill)` 開啟（⋯ 選單與課程設定共用）。

- Review 修正：轉課成功後關閉課程管理抽屜與舊編輯視窗，再重新載入課程，避免設定頁保留舊合約被拒絕的表單內容。取消／失敗路徑不變。

- 轉課捷徑明確提示只帶入科目／老師／時段；備註、教室、班型、單價與其他帳務設定不會儲存，需另外處理。在儲存錯誤面板及轉課視窗均顯示，避免混合編輯被誤認為完整儲存。

- 每週 7 時段的修改不再顯示必然失敗的轉課捷徑：現有 endpoint 上限為 6，畫面明確說明尚未儲存並保留原編輯內容，不截斷時段或改變 API 限制。6 時段仍可交接；13 focused tests 通過。

- 只有 server 明確給出 next_step 才顯示轉課錯誤捷徑；不再由 subject_change_requires_transfer 錯誤碼自行重建被 server 隱藏的動作。完整 focused frontend selection：27 tests + lint 通過。

- 客戶端以原編輯 snapshot 列出每個轉課不會儲存的變更欄位（含科目＋購買堂數同時修改、server 未回 locked_fields 的情況）；不更改 server 拒絕原因、權限或帳務。28 focused tests + lint 通過。
