# 115.07 正職老師薪資要件：資料來源與操作

> **權威規則：總管理處 115.05.11 公告（115.07.01 生效）。** 先前的分校版（蘆洲長樂 docx）作廢。校正進度與 Founder 決定見 [`docs/plans/2026-11-14-fulltime-payroll-hq-115-07.md`](plans/2026-11-14-fulltime-payroll-hq-115-07.md)。

結算金額（正職薪資要件頁）：

`獎金合計 = 每週16段課獎金 + 無條件捨去((科目數獎金 + 一對三獎金) × 教師倍率) + 現金加扣款`（這頁只結算獎金，不含本薪；Founder 2026-11-15）

- 科目數獎金 = 附表中「無條件捨去後的核薪總科目數」那一列（不內插）。
- 一對三獎金 = 一對三總計 × 100（附表「一對三獎金(預估)」欄只是示意）。
- 教師倍率 = 100% ＋ 假日16小時 ＋ 平日下午課％ ＋ 特殊表現％ ＋ 行政加給％ ＋ 正課科目數 ≥ 20 的 +5%（不含輔導／試聽）＋ 已核准扣除％。倍率只乘在科目數／一對三獎金上。

## 判定來源

| 要件 | Alltrue 來源 | 缺資料時 |
| --- | --- | --- |
| 每週 16 段 | 老師行事曆（`TeacherClassCalendar`：`ClassSession` 加有效的代課／補課例外列）：該週老師的時鐘時數 ÷ 2。正課、輔導、試聽都算；同一時段重疊的課只算一次；學生請假照算；取消、已改期（含已安排補課的請假）與行政時段不算；代課算給代課老師。整週一到週日判定，歸週一所在月份；該月每一週都滿 16 段才發 4,000，有一週沒滿就沒有 | 不會待確認 有全校停課日的那一週不判定、算達標（停課日 = 當天全公司至少 10 堂課且全部停課，而且沒有還在上的補課／代課；人工補登的假日事件不算）。 |
| 假日 16 小時 | 和每週 16 段同一份老師行事曆（`TeacherClassCalendar`）：每一週的週六＋週日排課時鐘時數都滿 16 小時 → 10%，有一週沒滿 → 0%（公告：假日未滿 16 小時者，假日倍率調整為 0%）。有全校停課日的那一週不看。不再讀點名、假日曆或請假補登 | 不會待確認 |
| 平日下午課 | 和每週 16 段同一份老師行事曆（`TeacherClassCalendar`）：週一到週五 18:00 前的時鐘時數 ÷ 2 = 段數，每段 1%，每週最多 5%，再取各週平均（例：四週 1、2、1、2 段 → 1.5%）。重疊只算一次；有全校停課日的那一週不列入平均 | 不會待確認 |
| 倍率調整（假日／平日下午） | 系統算的值不合實況時，主任在「行政加給」表單選「假日倍率調整」或「平日下午倍率調整」：必填原因、生效日、失效日，範圍 0–10%／0–5%。主任確認 → 總部核准後，取代系統算的值（明細保留系統原值 `system_rate`）；同一期間多筆取生效日最新的 | 尚未核准 → 該項待確認，不能鎖定。主任確認前主任可撤回；確認後或核准後只有總部可以退回，退回即恢復系統值 |
| 新進保底 | 到職日 = 這位老師的第一堂課日期（系統自己推，全分校）：取兩個日期較早者——點名記在他名下的第一堂課（幫別人代的課會算），和現在歸他的課的第一堂（點名記在別人名下的不算，所以接手舊課不會把前任老師上過的課算進來）。取較早者是為了資料缺漏時只會偏早（保底期變短），不會多發。第一堂課那個月算第 1 個月，前 3 個月內、而且該月每一週都排滿 16 段（停課週不看）→ 倍率後獎金至少 2,000；有一週沒滿就沒有保底 | 找不到任何一堂課 → 不適用 |
| 科目數 | 與「科目數統計」頁同一個來源（`SubjectUnitsTimelineService`，全分校合計）：已核准且未排除的評量為主，沒有評量的堂次用點名補；一對三的課算在正課裡；一對三總計另外看時鐘時間（一對三課的時數 × 0.5，同時段多位學生只算一次）；輔導／試聽另計。核薪總科目數＝（正課＋輔導試聽）÷ 8 | 不會待確認；缺時長的舊資料以 2 小時計（同科目數統計） |
| 升學成果／年度績優 | teacher_payroll_achievements，必須有證明與審核 | 待人工確認 |
| 扣除案件 | teacher_payroll_deductions，必須有主任確認及總部核准 | 待人工確認，不自動扣除 |

## Alltrue 操作入口

主任從「正職薪資要件」頁面即可完成資料補登與審核，不需要直接操作資料庫：

1. 假日與平日下午倍率由系統照課表自動算，不必補登假日曆或請假。
   - 這裡預設只補升學成果、年度績優與扣除案件。
   - 「假日／公休／請假」補登入口已收起；以前補登的資料還在，但不再影響金額。
2. 填寫後送出會出現在右側。待審核可修改或撤回；已核准可按「退回」，該筆不再進入薪資。
3. 右側待辦清單可完成主任核准／確認；扣除案件再由總部執行第二階段核准。
4. 報表項目的「待人工確認」會列出實際缺少欄位；課程管理連假後按重新整理即可重新計算。

這個流程採用成熟 HR 系統常見的「表單補登 → 狀態化待辦 → 分級審核 → 審核後才納入計算」模式，避免把未知資料誤當成 0 或直接扣薪。
