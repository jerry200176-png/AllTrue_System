# Role Playbook（角色操作手冊）

本文件給新進同仁、外部協作者、以及 AI agent 使用。  
目標是用角色視角快速理解 AllTrue 日常流程，降低操作錯誤。

## 1) 主任 / 行政（director, admin）

### 主要目標

- 建立與維護學生、課程、排課、財務全流程
- 追蹤當日營運重點（今日課程、待審評量、繳費提醒）
- 確保跨校區資料隔離正確

### 每日 SOP

1. 進入 `DirectorDashboard`：
   - 先看待審評量、繳費提醒、今日課程
2. 進入 `StudentsList`：
   - 新增學生、建立課程、確認剩餘堂數與課程狀態
3. 進入 `SmartCalendar` / `CourseManagement`：
   - 檢查衝堂、請假、補課安排
4. 進入 `AttendancePage`：
   - 補登/修正當日出缺勤
5. 進入 `Billing` / `Finance` 相關頁面：
   - 跟進未繳清與逾期帳單

### 常見錯誤與避免方式

- 錯誤：課程與排課在不同校區操作，造成資料混淆  
  避免：每次操作前確認目前 `branch`。
- 錯誤：只改前端畫面，未同步後端邏輯  
  避免：涉及計費/堂數時，必看 API 與 DB 寫入結果。
- 錯誤：補課後忘記檢查扣堂  
  避免：驗證 `RemainingSessions` 與 `SessionDeducted` 是否一致。

---

## 2) 老師（teacher）

### 主要目標

- 依課表授課、完成出缺勤紀錄
- 撰寫學習評量，送出審核

### 每日 SOP

1. 查看當日課表（課程時間、學生、教室）。
2. 上課後確認出缺勤狀態（到課/請假/補課）。
3. 在 `LearningRecordsPage` 填寫評量內容並送審。
4. 追蹤退回評量（`changes_requested`）並修正重送。

### 常見錯誤與避免方式

- 錯誤：評量未關聯正確課程堂次  
  避免：填寫前確認學生與課程對應。
- 錯誤：只填內容未送審  
  避免：下課後固定檢查評量狀態是否為 `pending`/`approved`。

---

## 3) 櫃台（front desk）

### 主要目標

- 快速處理到班點名與 RFID 異常
- 協助請假、補課、臨時通知

### 每日 SOP

1. 開班前確認 RFID 設備可正常送出紀錄。
2. 在 `AttendancePage` 即時處理到班與缺勤。
3. 對未識別刷卡資料做人工認列（pending swipe 流程）。
4. 將異常名單回報主任（如重複刷卡、非上課時段刷卡）。

### 常見錯誤與避免方式

- 錯誤：把刷卡紀錄認列到錯誤學生  
  避免：核對姓名、班別、時間窗。
- 錯誤：缺勤補登後未通知任課老師  
  避免：完成補登後同步通知授課教師與主任。

---

## 4) 家長（parent portal）

### 主要目標

- 查詢孩子課程、學習評量、繳費狀態
- 取得最新學習與出席資訊

### 使用 SOP

1. 進入 `ParentPortal` 登入。
2. 查看近期課程與出缺勤。
3. 查看學習評量內容與老師回饋。
4. 查看帳單與付款狀態。

### 常見問題

- 問題：看不到最新資料  
  建議：重新登入並確認綁定手機/身份資訊是否正確。
- 問題：課程狀態與櫃台說明不一致  
  建議：由櫃台協助檢查補課/調課是否已同步。

---

## 5) 跨角色共通規範

- 所有操作先確認校區（branch/campus）
- 堂數、出缺勤、繳費三者需一致
- 重大修改前先備份，重大修改後做基本驗證
