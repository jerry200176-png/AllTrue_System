# AllTrue 教師與主任培訓講師操作手冊 (Trainer Runbook)

> **版本**：2026-09-07 Training-Ready Edition  
> **目標對象**：培訓講師、助教、產品負責人  
> **適用角色**：分校主任 (Director)、專兼職教師 (Teacher)  
> **培訓時長**：60 分鐘精準工作坊（情境任務實作導向，非功能型逐頁演講）

---

## 一、 培訓前 15 分鐘準備清單 (Pre-Flight Checklist)

| 檢查項目 | 講師驗證要點 | 異常處理對策 |
| :--- | :--- | :--- |
| **帳號與權限準備** | 確認參訓主任具備 `director` 角色；老師具備 `teacher` 角色。密碼已由系統初始化。 | 登入若顯示密碼變更卡，指示先至「個人管理 > 安全性」完成首登改密。 |
| **分校歸屬 (Campus Scope)** | 確認每位學員的 `branch_id` 已正確綁定至所屬實體分校（若為跨校老師，確認 `teacherBranches` 有包含開課分校）。 | 若跨校老師找不到課程，確認右上角／側欄分校選擇器是否切換至正確分校。 |
| **既有生產資料隔離規範** | **嚴格禁止在未經創辦人核准下清空或假造正式營運資料**。培訓練習採用真實當日指定班級，或專屬安排之培訓練習堂次。 | 任何補建課或點名操作，必須明確註記 `memo: [培訓演練]` 便於事後稽核。 |
| **現場硬體與網路** | 老師準備平板／手機或筆電；主任準備筆電或桌面大螢幕。 | 提醒行動端與桌面版版面略有不同（例如行動版分校選擇在頂部，待點名堂次為卡片呈現）。 |

## 二、 60 分鐘培訓時間表與節奏掌控

```
00:00 - 00:05 (05m) | 單元 0：開場與心態設定（角色閉環思維：不做無效操作）
00:05 - 00:25 (20m) | 單元 1：老師每日黃金閉環（待辦 → 快速到班點名 → 課堂評量）
00:25 - 00:45 (20m) | 單元 2：主任每日營運閉環（工作台巡檢 → 課表追蹤 → 評量審核）
00:45 - 00:55 (10m) | 單元 3：分校協作與例外情境（調課、請假、跨分校反饋）
00:55 - 01:00 (05m) | 單元 4：Q&A、驗收回饋與培訓觀察記錄
```

## 三、 分段執行指引 (Scripted Delivery)

### 單元 0：開場 (00:00 - 00:05)
- **講師話術**：「各位老師、主任好，今天培訓不是要大家背選單，而是掌握每天 3 次登入各花 2 分鐘就能完成的日常閉環。老師負責『點名扣堂』與『課堂評量』；主任負責『分校工作巡檢』與『評量審核』。所有操作只要按照今日指引，系統都會有明確下一步引導。」
- **提示**：引導學員登入後若彈出「新手任務導覽」，可點擊「開始導覽」跟隨畫面引導，或進入實作模式自由操作。

---

### 單元 1：老師每日教學黃金閉環 (00:05 - 00:25)
*學員同步拿出手邊的《教師實作挑戰卡》進行情境演練。*

1. **情境任務 A：登入工作台，確認今日課表**
   - **操作路徑**：首頁 `active = 'teacher-home'` (`TeacherHomePage.vue`)。
   - **觀察指標**：是否看見「今日排課」與「待處理點名」？
   - **常見卡點**：跨校老師抱怨「今天我有課但畫面上是空的」→ **講師指引**：「請看左側欄或頂部切換分校，系統會即時顯示切換通知」。

2. **情境任務 B：課堂結束，完成批次到班點名**
   - **操作路徑**：點擊首頁「開始點名」或導航至 `attendance` (`AttendancePage.vue`)。
   - **核心操作**：勾選全選或逐位勾選，點擊「全部到班（N）」或點擊綠色「到班」按鈕。
   - **高風險提醒**：**點名確認送出後即時扣除學生堂數，並觸發家長 LINE 出席通知！** 不得隨意點擊缺席或退回。
   - **P0 UX 改善驗證**：點名送出且今日無待點名時，畫面立即亮出清晰綠色完成卡片與按鈕：**「下一步：填寫課堂評量」**。
   - **講師提示**：「完成點名後，請直接點擊綠色按鈕跳轉至評量，不需要在選單中迷路尋找！」

3. **情境任務 C：填寫今日課堂學習評量**
   - **操作路徑**：由點名完成按鈕自動跳轉，或導航至 `learning` (`LearningRecordsPage.vue`)。
   - **核心操作**：選取今日授課學生，填寫課堂單元、作業表現與簡評，點擊「儲存紀錄」。
   - **收尾確認**：確認紀錄進入「待主任審核」狀態。

---

### 單元 2：主任每日營運閉環 (00:25 - 00:45)
*學員同步拿出手邊的《主任實作挑戰卡》進行情境演練。*

1. **情境任務 D：主任工作台 3 分鐘晨間巡檢**
   - **操作路徑**：首頁 `active = 'director'` (`DirectorDashboard.vue`)。
   - **核心操作**：檢視頂部指標與「今天要處理的事」聚焦清單（待繳費、待審評量、待確認排課）。
   - **講師指引**：「點擊卡片上的快捷按鈕，即可直達處理頁面，不必手動翻選單。」

2. **情境任務 E：學生與課程展開詳情（P0 UX 改善點）**
   - **操作路徑**：導航至「學生名冊」`students` (`StudentsList.vue`)。
   - **核心操作**：搜尋指定學生。在操作欄點擊新上線的清晰按鈕：**「課程/購課」**（或點擊展開箭頭）。
   - **講師指引**：「過去很多主任不知道在哪裡看學生的剩餘堂數與加購，現在操作欄第一顆按鈕就是『課程/購課』，一鍵展開課表與購課明細！」

3. **情境任務 F：學習評量審核收尾**
   - **操作路徑**：導航至「學習評量」`learning` (`LearningRecordsPage.vue`)。
   - **核心操作**：點擊「待審核」分頁，檢視老師剛才提交的評量紀錄，點擊「核准」（若需修改則點擊「退回」並填寫原因）。
   - **權限與風控**：確認核准後評量方可於家長端 App 顯示；此操作具可審計性。

---

### 單元 3：分校協作與例外情境 (00:45 - 00:55)
1. **跨分校切換驗證**：
   - 示範切換分校時，系統右上角即刻彈出「已切換分校：XX分校」資訊 Toast，各頁面（課表、待辦、評量）自動刷新範圍。
2. **調課與請假認知**：
   - 說明學生請假是否展延結束日期（需主任或授權老師於點名或課表內標記 Leave）。
3. **敏感財務保護與安全規範**：
   - 說明學費收款 `tuition-collect` 與學費報表 `tuition-report` 需輸入專屬「主任 PIN 碼」（防範前台公用電腦窺探）。
   - **嚴格安全準則（資安不可妥協）**：講師與助教**嚴禁記憶、收集、共用或代為輸入主任 PIN 碼**。
   - 若演示或操作過程中彈出 PIN 碼保護畫面，**必須由經授權的主任本人親自輸入解鎖**。
   - 任何情況下均不得繞過、削弱或共享現有 PIN 碼與權限控管。

---

### 單元 4：Q&A、填寫觀察表與收尾 (00:55 - 01:00)
- 助教協助發放或線上開啟《培訓現場觀察與摩擦反饋表》。
- 統計每位學員各任務是否順利完成、是否需要助教介入、卡點在何處。
- 收集所有問題並當場解答，未能當場解決的記錄至當日 UX Backlog。

## 四、 講師應變錦囊 (Troubleshooting & FAQs)

| 學員問題 | 正確解答話術 | 系統原理與依據 |
| :--- | :--- | :--- |
| **Q1：老師點名選錯狀態送出了，可以自己撤回嗎？** | 「老師點名送出後會即時扣堂並進入結算流程。如果點錯，請立即通知主任，由主任在出缺勤管理或異常通報中協助校正。」 | 防止授課人員擅自反覆沖銷堂數引發計費糾紛；維持單一事實來源。 |
| **Q2：我在課表上看不到下週的課？** | 「請先確認頂部週次切換是否正確，以及所選篩選器是否限制了科目或特定教師。」 | `SmartCalendar.vue` 預設呈現本週，篩選器會跨週保留狀態。 |
| **Q3：學生買了新堂數，但點名列表顯示剩餘 0 堂？** | 「請至『學生名冊 > 課程/購課』確認該學生的購課紀錄是否已『確認入帳』，尚未確認入帳的合約堂數不會計入可用額度。」 | 財務合約與可排堂數隔離保護機制。 |
| **Q4：為什麼系統一直要求我輸入 PIN 碼？** | 「學費收取、學費報表與鐘點費計算屬於分校一級機密，主任離開頁面超過閒置時間或重新整理時，系統會自動上鎖以保護學童與財務隱私。」 | `pinGate.js` 闲置保護策略。 |
