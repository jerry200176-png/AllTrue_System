# AI 可以看什麼、可以改什麼（AI Data Access Rules）

> AI 治理 G3（Founder 2026-11-16，#4991）。這一頁只是把**已經生效**的規定收在一起，不新增權限。
> 有衝突時以 `docs/governance/FOUNDER_STANDING_DECISIONS.md` 和 `AGENTS.md` 為準。

## 讀

| 規定 | 怎麼做到的 |
|---|---|
| AI 可以讀全部業務資料的**數字、日期、狀態代碼**（Founder 2026-11-16） | 唯讀金鑰＋`GET /api/v1/triage/db/{table}`（`TriageDbReadController`） |
| **姓名、電話、地址、備註、密碼、登入與綁定資料不外傳** | 文字欄位一律不回傳也不能拿來篩選；登入、金鑰、綁定類資料表整張擋掉；9 位數以上的數字不回傳 |
| 只能讀，不能寫 | 端點只有 SELECT；每次最多 200 列、每分鐘最多 60 次 |
| 每次讀取都有紀錄 | 稽核紀錄含讀了哪張資料表 |
| 可以馬上關掉 | 撤銷金鑰（個人資料 › 安全性），或設 `TRIAGE_DB_READ_ENABLED=false` |
| 讀到的內容不貼到 GitHub | 這個 repo 是公開的：PR、issue、留言只能有編號和技術結論 |

## 改

| 規定 | 怎麼做到的 |
|---|---|
| AI **不能直接改**正式資料 | 沒有寫入用的金鑰或端點 |
| 要改正式資料：**試跑 → Founder 核准 → 執行 → 可還原** | 受控操作（POP）：先出試跑清單，核准後才執行，留稽核紀錄與還原編號 |
| 資料庫結構變更只能經部署流程 | `deploy.yml`；正式環境的 migration 要 Founder 核准 |
| 不碰正式主機 | 禁止對正式主機 SSH、跑 artisan／測試、印出密碼金鑰 |

## 結論和程式

| 規定 | 怎麼做到的 |
|---|---|
| 說「原因是 X」要附資料證據；算得剛好不算證據 | 先用唯讀查詢查到編號和數字再下結論 |
| 動到錢、資料、權限的程式改動要**獨立審查**，每個版本都要 | R3：`security-data-reviewer` 對該版本蓋章才能合併；另有 Codex 審查 |
| 不直接推主線、不跳過檢查 | 一律 PR；禁止 force-push 與 `--admin` |
| 上線要 Founder 核准 | `deploy.yml` 的核准關卡 |
