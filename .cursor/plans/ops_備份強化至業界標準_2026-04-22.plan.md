## 2. 目標與業務背景

### 痛點

今天發生三次 P0 事故，根本原因之一是備份機制有三個明確漏洞：

1. **程式碼備份中斷**：`bin/rclone` 被 `git-sync.sh` 安全掃描誤判為可疑二進位，每小時的 code sync 全部 SECURITY-ABORT，GitHub 上的程式碼最後一次同步停在昨晚
2. **DB 異地備份不穩定**：`gdrive-backup-sync.sh` 每天打 Google Drive API 碰到 rate limit（403），nightly dump 沒有上傳到雲端
3. **sixhour 保留太短**：只保留 8 份（2 天），今天的事故差一點超出視窗；如果 sixhour 備份再早幾小時，就沒有辦法救回來

另外兩個中期風險：
- `monthly-restore-drill.sh` 從未成功執行（log 是空的），無法證明備份是可還原的
- `phpunit.xml` 對 `DB_DATABASE` 的保護不足，是這次 DB 被清空的直接原因

### 業務價值

補習班系統的 DB 包含學生課程紀錄、繳費記錄、出缺席記錄。一次資料損失可能讓主任無法追帳、家長產生糾紛。

### 可量化 KPI

| KPI | 現況 | 目標 |
|---|---|---|
| RPO（資料損失上限） | 最差 6 小時（sixhour 間隔） | ≤ 2 小時（sixhour 縮短） |
| 異地備份成功率 | 今日 0%（403 失敗） | ≥ 95%/月 |
| 程式碼備份頻率 | 0 次/天（卡住） | 每小時 1 次 |
| 備份可還原驗證 | 0 次（從未執行） | 每月自動驗證 + 報告 |
| DB 被誤清風險 | 高（phpunit.xml 無硬保護） | 有斷路器，啟動時 assert `DB_DATABASE ≠ AllTrue` |

## 3. 範圍

### In Scope

1. **修復 git-sync SECURITY-ABORT**：把 `bin/rclone` 加入 `.gitignore`
2. **修復 Google Drive 403**：調整 `gdrive-backup-sync.sh` crontab 時間 + 加入退讓邏輯
3. **sixhour 保留從 2 天改為 3 天**（KEEP 8→12）
4. **驗證 monthly-restore-drill.sh 正常執行**：手動跑一次，確認 log 有 PASSED
5. **phpunit.xml DB_DATABASE 斷路器**：在 `tests/bootstrap.php` 加入 assert，確保測試環境永遠連 `AllTrue_test`
6. **nightly 備份完整性自動驗證**：dump 完成後統計 INSERT 行數，異常時寫 CRITICAL log

### Out of Scope

- 更換 mysqldump 為 XtraBackup（DB 只有約 400MB，mysqldump 足夠）
- 增加第三個異地備份（如 AWS S3）
- 修改 production backend 的任何 PHP 檔案
- 修改 production `.env`
- 修改 `backend/bootstrap/cache/` 下任何檔案

## 5. User Stories

### US-1（程式碼備份）
**As** 系統管理員，  
**I want** 每小時的 git-sync 能穩定成功，  
**so that** 程式碼有最多 1 小時的版本快照，事故後可精確回溯。

**AC-1a**：`git-sync.sh` 執行後 `git-sync-hourly.log` 最後一行包含 `[git-sync] Push successful` 或 `No staged changes`，不出現 `SECURITY-ABORT`  
**AC-1b**：`bin/rclone` 不被 git 追蹤（不出現在 `git status`）

### US-2（DB 異地備份）
**As** 系統管理員，  
**I want** 每天的 nightly dump 能成功上傳到 Google Drive，  
**so that** Pi 硬體損毀時仍能從雲端還原。

**AC-2a**：`gdrive-sync.log` 最後一次執行不包含 `403` 或 `Quota exceeded`  
**AC-2b**：`rclone ls g-drive:AllTrue-Backups/db/` 至少有 1 個 `alltrue_nightly_*.sql.gz` 文件

### US-3（sixhour 保留）
**As** 系統管理員，  
**I want** sixhour 備份保留最近 3 天（12 份），  
**so that** 即使事故在最壞時機發生，資料損失視窗也控制在 6 小時內且有 3 天可回溯。

**AC-3a**：`sixhour-backup.sh` 中 `KEEP=12`  
**AC-3b**：`sixhour/` 目錄下保留數不超過 12 + 2 份

### US-4（備份可還原驗證）
**As** 系統管理員，  
**I want** 每月自動驗證最新備份確實可以還原，  
**so that** 備份不只是「存在」，而是「可用」。

**AC-4a**：手動執行 `monthly-restore-drill.sh` 後 log 結尾包含 `PASSED`  
**AC-4b**：restore drill 在 crontab 每月 1 日 02:00 排程（已存在，確認即可）

### US-5（DB 斷路器）
**As** 開發環境，  
**I want** `tests/bootstrap.php` 在啟動時 assert `DB_DATABASE ≠ AllTrue`，  
**so that** 任何測試程序誤連到 production DB 時立刻報錯終止，不執行任何 migration。

**AC-5a**：在 `/tmp/backend-test` 中模擬 `DB_DATABASE=AllTrue` 執行測試時，bootstrap 拋出明確錯誤訊息並退出，不進入 RefreshDatabase  
**AC-5b**：`DB_DATABASE=AllTrue_test` 時測試正常啟動

### US-6（備份完整性驗證）
**As** 系統管理員，  
**I want** 每次 nightly dump 完成後自動驗證備份檔案含有足夠資料，  
**so that** 損壞的備份在下次使用前就被偵測到。

**AC-6a**：`nightly-backup.sh` 在 dump 後統計 `INSERT INTO` 行數，若 < 20 寫入 CRITICAL log  
**AC-6b**：`db-alert.log` 或 `nightly-backup.log` 包含每次 dump 的 INSERT 行數統計

## 8. 技術方向

### 修改清單（只列檔案名稱，無 code）

| 檔案 | 操作 | 說明 |
|---|---|---|
| `/home/admin/.gitignore` | 新增一行 | 排除 `bin/rclone`（ELF binary 不應追蹤） |
| `/home/admin/scripts/sixhour-backup.sh` | 修改 1 個變數 | `KEEP=8` → `KEEP=12` |
| `/home/admin/scripts/gdrive-backup-sync.sh` | 修改 2 處 | 加入 sleep 退讓邏輯；新增 sixhour 同步區塊 |
| `crontab`（admin） | 修改 1 個排程時間 | gdrive-sync 從 02:30 → 03:00 |
| `/home/admin/backend/tests/bootstrap.php` | 新增 5 行 | DB_DATABASE 斷路器（assert before autoload） |
| `/home/admin/scripts/nightly-backup.sh` | 新增備份完整性驗證段落 | dump 後統計 INSERT 行數，< 20 寫 CRITICAL |

### 架構說明

- **git-sync 問題**：根本原因是 `bin/rclone`（ARM64 ELF）被 `git ls-files --others` 列出後觸發 binary 偵測規則。最乾淨的修法是 `.gitignore` 排除 `bin/` 目錄（或明確列 `bin/rclone`），讓 git 根本看不到這個檔案。此方案優於修改 git-sync.sh 白名單，因為白名單是「允許通過」的邏輯，而 binary 本來就不應進入 git。
- **gdrive 403 問題**：根本原因是 `gdrive-backup-sync.sh` 在 crontab 02:30 執行，剛好緊接 nightly-backup.sh 01:00 完成。nightly 本身可能已對 git tag/push 操作消耗了一些 Google API quota。加入退讓 sleep 和調整時間可解決。
- **bootstrap.php 斷路器**：在 PHPUnit 的 bootstrap 最前面（autoload 之前）讀取 DB_DATABASE，若等於 `AllTrue` 直接 exit。這是最後一道防線，優先於 phpunit.xml 的 `<env force="true">`。

## 10. QA 驗收

### Happy Path

- [ ] 手動執行 `git-sync.sh`：log 顯示 `Security scan passed` + Push successful（或 No staged changes）
- [ ] 手動執行 `gdrive-backup-sync.sh`：log 不含 `403` / `Quota exceeded`，顯示上傳成功
- [ ] 手動執行 `monthly-restore-drill.sh`：log 末尾含 `PASSED: N tables, M students`
- [ ] 修改 `KEEP=12` 後執行 `sixhour-backup.sh`：新備份出現在 `sixhour/`

### Edge Case

- [ ] DB_DATABASE 斷路器：在 `/tmp` 複本設 `DB_DATABASE=AllTrue` 執行 bootstrap，程式立刻 exit(1) 並顯示明確錯誤訊息
- [ ] `bin/rclone` `.gitignore` 後：`git status` 不顯示 `?? bin/rclone`

### Error Case

- [ ] Google Drive 不可用時：`gdrive-backup-sync.sh` 以 non-fatal 結束（local 備份不受影響）
- [ ] nightly dump 空白時：`nightly-backup.sh` 寫入 `CRITICAL` 到 log，但不中斷 git push
