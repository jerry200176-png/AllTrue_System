# 顯示當期已繳費日期計畫

## 目標
在你指定的多個頁面（催繳名單、當月學收、學生課程相關列表）顯示「當期繳費日期」，且以 `Payment.PaidAt` 為唯一準則，不改變既有 `Paid` 與提醒規則。

## 目前現況（已確認）
- `Payment` 模型已有 `PaidAt` 欄位：[`/home/admin/backend/app/Models/Payment.php`](/home/admin/backend/app/Models/Payment.php)
- 繳費入帳 API 已寫入 `PaidAt`（未傳時預設 now）：[`/home/admin/backend/app/Http/Controllers/BillingController.php`](/home/admin/backend/app/Http/Controllers/BillingController.php)
- 催繳名單 API 目前只回傳 `paid/due_date` 等欄位，未含已繳日期：[`/home/admin/backend/app/Http/Controllers/AlertController.php`](/home/admin/backend/app/Http/Controllers/AlertController.php)
- 當月學收 API 目前也未回傳繳費日期：[`/home/admin/backend/app/Http/Controllers/FinanceController.php`](/home/admin/backend/app/Http/Controllers/FinanceController.php)
- 前端頁面目前沒有「繳費日期」欄位：
  - [`/home/admin/frontend/src/pages/TuitionCollectionPage.vue`](/home/admin/frontend/src/pages/TuitionCollectionPage.vue)
  - [`/home/admin/frontend/src/pages/TuitionReportPage.vue`](/home/admin/frontend/src/pages/TuitionReportPage.vue)

## 實作策略
- 不新增 DB schema（先不加 migration），直接利用既有 `Payment.PaidAt`。
- 在後端統一計算並回傳 `last_paid_at`（或 `current_period_paid_at`）欄位，前端只顯示不運算。
- 「當期」定義：以目前該筆課程/報表月份對應到的付款紀錄，取最後一次有效付款時間（latest `PaidAt`）。

## 變更步驟
1. 後端：抽出共用查詢邏輯（Service 或 Controller 私有方法）
- 依 `student_class_id`（必要時含 `year/month`）查出對應付款紀錄，回傳最後繳費日。
- 建議落在 [`/home/admin/backend/app/Http/Controllers/FinanceController.php`](/home/admin/backend/app/Http/Controllers/FinanceController.php) 與 [`/home/admin/backend/app/Http/Controllers/AlertController.php`](/home/admin/backend/app/Http/Controllers/AlertController.php) 共用，避免各自實作。

2. 後端：擴充 API 回傳欄位
- `GET /api/v1/finance/branch-monthly-tuition` 加入 `last_paid_at`。
- `GET /api/v1/alerts/tuition` 加入 `last_paid_at`（若未繳費則 `null`）。
- 保持舊欄位不變，避免前端其他頁面回歸風險。

3. 前端：催繳名單頁新增欄位
- 在 [`/home/admin/frontend/src/pages/TuitionCollectionPage.vue`](/home/admin/frontend/src/pages/TuitionCollectionPage.vue) 表格新增「繳費日期」。
- 顯示規則：`paid=true` 顯示日期；未繳費顯示 `—`。

4. 前端：當月學收頁新增欄位
- 在 [`/home/admin/frontend/src/pages/TuitionReportPage.vue`](/home/admin/frontend/src/pages/TuitionReportPage.vue) 表格新增「繳費日期」。
- 支援手機版欄位隱藏策略（維持現有 responsive 行為）。

5. 前端：學生課程相關頁面補顯示（第二階段）
- 盤點 [`/home/admin/frontend/src/pages/StudentsList.vue`](/home/admin/frontend/src/pages/StudentsList.vue) 與 [`/home/admin/frontend/src/pages/CourseManagement.vue`](/home/admin/frontend/src/pages/CourseManagement.vue) 目前資料來源。
- 若現有 API 未帶付款資訊，新增最小欄位回傳後再顯示，避免額外 N+1 請求。

6. 測試與驗證
- 後端 Feature test：
  - 已繳費時回傳 `last_paid_at`
  - 未繳費時為 `null`
  - 多校區隔離仍正確（`branch_id` / `CampusID`）
- 前端驗證：
  - 欄位顯示正確
  - 無資料時顯示 `—`
  - 舊功能（催繳排序、繳費單按鈕）不受影響

## 風險與注意事項
- 同一期多次付款（partial -> paid）時，要定義取「最後一次 PaidAt」。
- `StudentClass.Paid` 與 `Invoice.Status` 可能短暫不同步，顯示欄位應明確標示為「最後入帳日」。
- 避免在前端自行推估月份對應，統一由後端決定，減少規則分裂。
- 需維持現有催繳規則不變（只新增顯示欄位，不改提醒條件）。

## 建議上線順序
先上 `TuitionCollection + TuitionReport`，確認資料可用後再擴到 `StudentsList/CourseManagement`，可降低一次性改動風險。
