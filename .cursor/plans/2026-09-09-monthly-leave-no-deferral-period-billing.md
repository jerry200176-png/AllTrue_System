## 2. 目標與業務背景

### 痛點（非技術語言）

1. 家長按「這個月實際上幾堂」付錢，但系統若把請假堂**往後推到下個月**，八月帳與九月帳都會錯。
2. 主任想把跨到九月的那一堂歸回九月時，系統擋下並叫去「帳務更正」，但**找不到按鈕**——感覺像壞掉，其實是入口沒對齊。
3. 老師必須反覆解釋「為什麼多出一堂在下個月」，行政成本高、容易重複計費或漏收。

### 業務價值

- 月結語意對齊家長認知：請假＝本期少收一堂，不是免費延到下個月。
- 減少跨期人工搬堂與錯帳。
- 歷史個案有清楚、可稽核的清理路徑（或乾淨拒絕＋白話步驟）。

### 可量化 KPI

| KPI | 基線（假設） | 目標 |
|---|---|---|
| 月結請假後產生「合約結束日之後」新堂次 | 修法前可發生 | **0**（新請假路徑） |
| 主任因「帳務更正找不到」而卡住的支援次數 | 本案 ≥1 | 錯誤畫面直接給可完成步驟或入口 |
| 歷史跨月尾巴需人工／工程修數 | 未知 | 有盤點清單＋標準清理手冊或工具 |

### In Scope

| ID | 項目 |
|---|---|
| A | **政策確認**：月結請假＝標記請假＋本期可計費 −1；**不**自動順延、不補尾、不改合約結束日（與老師建議一致） |
| B | **防再發稽核**：確認所有請假寫入路徑（出缺勤、課程管理、智慧行事曆、批次請假）對月結皆遵守 A；補回歸測試缺口 |
| C | **入口／文案對齊**：月結點「合約／堂次調整」不得 silently 開「只搬紀錄」；錯誤訊息改白話步驟；導向可做的「本期費用／區間對齊」或「跨期清理」流程 |
| D | **歷史尾巴處理產品規格**（二選一或分階段，見 Decision Log）：要么提供「月結跨期歸檔」安全流程（搬堂＋同步兩期費用／區間），要么明確不做搬移、只提供「上期縮短＋九月補登」標準 SOP |
| E | 教職員更新卡／操作說明（白話） |

### Out of Scope

- 堂數制（預付包堂）請假順延邏輯（維持現況）
- 共用方案池調整
- 自動向家長收款／LINE 催繳文案改寫
- 大量 production 資料一次修補（另開 Repair Manifest；本案只定義規則與工具／SOP）
- 整包重寫排課／帳務系統

## 5. User Stories + AC

### US-1 — 老師月結請假不長出下個月尾巴

**As a** 老師，**I want** 月結課請假只影響當期，**so that** 不會自動多出下個月的課。

**AC**

- [ ] AC-1.1 月結課程將合約內一堂標請假後：該堂＝請假；未來已排堂日期不變；合約結束日不變；**不**新增結束日之後的堂次。
- [ ] AC-1.2 八月原排 5 堂、其中 1 堂請假 → 本期可計費堂次＝4；九月新合約不因該請假自動多 1 堂。
- [ ] AC-1.3 堂數制課程請假順延行為不變（回歸）。

### US-2 — 主任看懂為什麼不能「只搬紀錄」

**As a** 主任，**I want** 清楚的下一步，**so that** 不會空找不存在的「帳務更正流程」按鈕。

**AC**

- [ ] AC-2.1 月結課程的「合約／堂次調整」顯示月結專用選項（或直接說明不可只搬紀錄），**不**再默認開啟「轉移已上課紀錄」。
- [ ] AC-2.2 若仍觸發轉移 API：回傳白話步驟（上期怎麼收、九月怎麼處理），禁止只寫內部流程名。
- [ ] AC-2.3 未收款且需對齊本期費用／結束日時，有可點的入口（名稱與實際 modal 一致）。

### US-3 — 歷史跨月尾巴可收斂（依 Decision Log）

**As a** 主任，**I want** 把誤落在上期的跨月已上堂歸到正確月份，**so that** 家長帳單與行事曆一致。

**AC（若選 D1 — 不做一鍵搬移）**

- [ ] AC-3.1 系統提供固定 SOP 文案：上期結束日縮到請假前最後可計費日、上期費用＝實際上堂數、九月合約開始日涵蓋該日並「新增月結堂次」＋重點名（評量可能需重填）。
- [ ] AC-3.2 畫面錯誤直接連到該 SOP，不暗示有隱藏按鈕。

**AC（若選 D2 — 做月結跨期歸檔）**

- [ ] AC-3.3 單一交易內：堂次改掛目標期＋來源／目標費用與區間同步試算＋預覽確認＋稽核紀錄。
- [ ] AC-3.4 已收款／待對帳回報的期別：fail closed，引導先作廢或對帳，禁止 silent 改帳。
- [ ] AC-3.5 同日同時段目標已有堂次：fail closed 並列出衝突。

## 8. 技術方向（禁 code）

### 受影響邊界

| 層 | 名稱／區域 |
|---|---|
| 頁面 | 課程管理（合約／堂次調整、轉移堂次、帳務更正／本期對齊 modal） |
| API | 請假相關寫入、堂次轉移、帳務更正／費用更正、（可選）月結跨期歸檔 |
| 資料 | 課程合約起訖、堂次歸屬、未收款帳單金額；**不**改已確認收款除非先作廢 |
| 測試 | Feature：月結請假邊界、入口分流、錯誤文案、（可選）跨期歸檔預覽／提交 |
| 文件 | CHANGELOG、AI_REGRESSION、STAFF_UPDATES |

### 架構取捨

1. **期間邊界權威**：月結合約起訖日是自動排課與帳務邊界（延續 R136／R26）。
2. **請假與補課分離**：請假不自動產生補課；若業務要補課，走明確「新增月結堂次／調課」並受區間檢查。
3. **搬紀錄 ≠ 改帳**：只搬點名對月結不安全；要嘛禁止＋SOP，要嘛做「搬＋雙期對帳」具名命令。
4. **T3**：任何會改收費語意或 production 列的動作，Founder GO 後才部署／修資料。

## 9. 資安與存取控制

| 維度 | 評估 |
|---|---|
| Spoofing | 維持既有主任／超級管理員＋校區 middleware |

## 10. QA 驗收

### Happy Path

1. 月結八月 5 堂，標 8/29 請假 → 結束日不變、無 9/5 新堂、可計費 4。
2. 月結「合約／堂次調整」看到月結說明，不進無效轉移。
3. （D1）錯誤區顯示步驟；主任可完成上期費用對齊。
4. （D2 若做）預覽顯示兩期費用變化 → 確認 → 9/5 掛九月且八月費用為 4 堂。

### Edge

- Legacy 月結列仍帶正的購買堂數欄位 → 仍走月結請假政策。
- 目標九月已有同日同時段 → 衝突拒絕。
- 上期已收款 → 拒絕改費，引導作廢。

### Error

- 未登入／無權限 → 401／403。
- 部分成功不可出現（交易原子性）。

### UI/UX 清單

- [ ] 無「找不到的功能名」
- [ ] 手機可完成調整
- [ ] loading／錯誤 alert 齊全

## 13. 風險／假設／開放問題

### 本專案既有結論

- R136／教職員卡：月結請假維持合約日期、只減可計費堂次。
- R26：月結續報必須新舊期分離。
- 邱致元數學跨期先例：採「留在正確計費期＋對齊費用／結束日」，而非只搬紀錄。

### 業界／開源對齊（已 WebSearch）

| 來源 | 作法 | 對 AllTrue 意義 |
|---|---|---|
| [TutorCruncher 出勤](https://help.tutorcruncher.com/en/articles/14183041-marking-lesson-attendance) | 出席可計費／缺席不可計費／缺席仍計費 **三態分離**；計費與是否補課分開 | 月結請假應對應「不可計費」，不自動產生下一堂 |
| [Teachworks 取消／狀態](https://blog.teachworks.com/2021/12/save-time-with-customer-cancellations/) | 取消政策可設定；補課是**另一步**請求／預約，不是取消的預設副作用 | 支持「請假 ≠ 自動順延」 |
| [Tutorbase recurring](https://tutorbase.com/blog/recurring-lesson-scheduling-software) | series 可 mark skip／pause；例外與帳單週期分開設定 | 期間邊界內 skip，不默認跨期補 |
| [Bizzly tutoring subscription](https://www.bizzly.net/industry/tutoring/subscription-software) | 未用堂次是否滾入下期由**方案政策**決定，需明示 | AllTrue 月結採「不滾入」；與家長溝通一致 |
| Stripe 訂閱 period 邊界 | 取消／變更以 billing period 為界，避免 silent 改寫已計費區間 | 跨期變更必須具名命令＋預覽 |

### 假設

- 本案英文 9/5 多半來自「舊順延」或等價路徑；修法後新請假不應再產生。
- 家長契約是「實上實付按月」，不是「保證每月固定 N 堂一定補滿」。
