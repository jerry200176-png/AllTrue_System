# PRD：老師多選篩選（課表 + 老師清單）

## 1. 背景與問題
目前老師篩選為單選，主任/教務在排課與查詢時需要反覆切換老師，造成操作成本高、比對慢。目標是支援「同時勾選多位老師」，在同一視圖快速掌握排課與教師資料。

## 2. 目標與範圍
- MVP 範圍：
  - 課表頁（班級行事曆/課表）
  - 老師清單頁
- 行為規則（已確認）：
  - 多選結果採 **聯集顯示**
  - 視覺呈現採 **老師色標區分**
- 非目標（MVP 不做）：
  - 交集模式
  - 自訂分組看板
  - 跨頁全域永久條件同步（先保留頁內記憶）

## 3. 使用者與場景
- 使用者：主任、教務（admin/director）
- 核心場景：
  - 課表頁同時檢視多位老師時段，快速找衝堂與可排空檔
  - 老師清單頁一次篩選多位老師，進行批次檢視/比對

## 4. 需求定義（Functional Requirements）
### FR-1 課表頁老師多選
- 在課表頁老師篩選列由單選改為多選（Tag/Chip 可勾選）。
- 預設狀態：未選任何老師 = 顯示全部（維持現況語意）。
- 勾選 1 位以上老師後：
  - 顯示被勾選老師的課程聯集。
  - 每筆課程卡片顯示對應老師色標（顏色穩定映射至 teacherId）。
- 支援「全清除」操作，一鍵回到顯示全部。

### FR-2 老師清單頁老師多選
- 老師清單頁篩選器改為多選。
- 勾選多位老師後，列表顯示所選老師聯集資料。
- 支援快速全清除。

### FR-3 URL/狀態保存（頁內）
- 同頁切換週次/日期/分校時，保留目前已勾選老師（除非該老師不在當前分校資料集）。
- 分校切換後若老師不屬於該分校：自動剔除並提示「已移除 X 位不在本分校的老師」。

### FR-4 權限與資料隔離
- 僅顯示使用者可見分校與可存取老師資料。
- 不得突破既有 `branch_id` / `CampusID` 隔離。

## 5. 視覺與互動規格（UX/UI）
- 老師篩選元件：
  - 支援搜尋 + 多選。
  - 已選老師以 chips 顯示，可單一移除。
- 色標規則：
  - 同一位老師在所有卡片顏色一致。
  - 提供高對比配色，避免與狀態色（請假/取消）混淆。
- 空狀態：
  - 若多選後無資料，顯示「所選老師在此條件下無課程/無資料」。

## 7. 驗收標準（Acceptance Criteria）
- AC-1：課表頁可同時選 2 位以上老師，畫面顯示其聯集課程。
- AC-2：同一老師課程卡片色標一致，跨週切換後仍一致。
- AC-3：老師清單頁可多選，列表結果正確過濾。
- AC-4：清除篩選後回到「全部老師」。
- AC-5：切換分校時自動清除不合法老師，且不出現跨校資料。
- AC-6：效能可接受（300ms 內完成前端過濾渲染，目標值）。

## 8. 風險與對策
- 風險：多色標與課程狀態色衝突。
  - 對策：老師色標使用邊框/標籤，不覆蓋狀態主色。
- 風險：多選導致列表資料量增大。
  - 對策：先前端過濾，必要時增加 API server-side filter 與分頁。
- 風險：跨分校老師殘留選取狀態。
  - 對策：分校切換時做合法化清理並提示。

## 9. 指標（Success Metrics）
- 主任完成「多老師排課比對」平均操作步驟下降 30%。
- 老師篩選切換次數下降 40%。
- 課表查詢任務完成時間下降 25%。

## 10. 里程碑
- M1（MVP）：課表頁 + 老師清單頁多選、聯集顯示、色標、清除、分校合法化。
- M2（優化）：URL 可分享篩選條件、API `teacher_ids[]` 查詢優化、色彩可配置。

## 11. 跨部門審閱與簽核狀態
- UI/UX 設計師：已審閱，無阻擋問題（確認多選 chips + 搜尋、聯集顯示、老師色標方案）。
- CTO：已審閱，無阻擋問題（同意 MVP 先以前端過濾為主，保留後端 `teacher_ids[]` 擴充位）。
- 架構師：已審閱，無阻擋問題（確認不破壞 `branch_id`/`CampusID` 隔離與既有 API 相容）。
- 結論：進入測試規劃與排程階段。

## 12. 測試部測試計畫（Test Plan）
### 12.1 測試目標
- 驗證「課表頁 + 老師清單頁」多選篩選功能正確、穩定、可用。
- 確保多選聯集顯示與老師色標符合 PRD 定義。
- 確保分校切換與權限隔離不發生跨校資料外露。

### 12.2 測試範圍
- 功能測試（Functional）
- 回歸測試（Regression）
- 權限與資料隔離測試（Security/Access）
- 可用性與視覺一致性測試（UX/UI）
- 效能驗證（Performance baseline）

### 12.3 測試環境與資料準備
- 環境：
  - Staging（與正式同版本 API 與資料表結構）。
  - 測試帳號：`admin/director`、`teacher`（只檢視可見權限邏輯）。
- 測試資料：
  - 至少 2 個分校（A/B），每分校 >= 8 位老師。
  - 每位老師至少 10 筆課程資料，包含 `scheduled/leave/cancelled/attended`。
  - 準備跨週、跨日期、空資料日、高密度資料日。

### 12.4 測試案例清單
- TP-01 預設顯示
  - 步驟：進入課表頁/老師清單頁，不選老師。
  - 預期：顯示全部老師資料；UI 無錯誤。
- TP-02 單一老師選取
  - 步驟：選 1 位老師。
  - 預期：僅顯示該老師資料；清單與課表一致。
- TP-03 多位老師選取（聯集）
  - 步驟：同時選 2~5 位老師。
  - 預期：顯示聯集結果；資料筆數正確；無重複渲染。
- TP-04 單一移除與全清除
  - 步驟：移除 1 個 chip、再點全清除。
  - 預期：結果即時更新；全清除後回到顯示全部。
- TP-05 色標一致性
  - 步驟：切換週次/日期後回看同一老師課程卡片。
  - 預期：同一老師色標不變；不與狀態色混淆。
- TP-06 分校切換合法化
  - 步驟：分校 A 選多位老師後切到分校 B。
  - 預期：不屬於 B 的老師被移除；出現提示；無跨校資料。
- TP-07 無資料空狀態
  - 步驟：選擇在該條件下無課程老師組合。
  - 預期：顯示明確空狀態文案，無 console error。
- TP-08 權限驗證
  - 步驟：用不同角色登入檢查可見老師與課程。
  - 預期：僅見授權範圍資料，權限外資料不可見。
- TP-09 大資料量效能
  - 步驟：同時選 8~12 位老師，切換週次與日期。
  - 預期：前端過濾與畫面更新 <= 300ms（目標）；互動不卡頓。
- TP-10 回歸驗證
  - 步驟：驗證原有單選邏輯衍生流程（排課查看、老師清單搜尋）。
  - 預期：既有功能不退化、不破壞其他篩選器。

### 12.5 自動化與手動分工
- 手動測試：
  - TP-01~TP-08、TP-10（以 QA 腳本逐步驗證）。
- 自動化建議：
  - 前端 E2E：多選、清除、分校切換、空狀態。
  - API/整合測試：分校隔離與 `teacher_ids[]`（若後續導入）。

### 12.6 進出場標準（Entry/Exit Criteria）
- Entry：
  - UI/UX、CTO、架構師簽核完成。
  - 需求凍結，測試資料建置完成。
- Exit：
  - Critical/Major 缺陷 = 0。
  - 所有 AC（AC-1~AC-6）通過。
  - 測試報告與已知限制文件化完成。

### 12.7 缺陷分級與回報節奏
- Critical：跨校資料外露、資料錯顯、功能無法使用。
- Major：聯集邏輯錯誤、色標映射錯亂、清除行為失效。
- Minor：文案、對齊、非阻擋互動瑕疵。
- 回報節奏：每日一次 QA sync；Critical 即時通報。
