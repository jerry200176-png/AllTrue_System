## 8. 技術方向

**涉及檔案：**

- `backend/app/Http/Controllers/ClassSessionController.php`：`index` 方法內 `leftJoin(DB::raw('(...) AS sub_sched'), ...)` 的 `whereRaw`，將 `sub_sched.start_time = SUBSTRING(cs.StartTime, 1, 5)` 改為 `SUBSTRING(sub_sched.start_time, 1, 5) = SUBSTRING(cs.StartTime, 1, 5)`
- `backend/database/migrations/2026_04_21_000002_normalize_schedules_start_time.php`：`up()` 執行 UPDATE；`down()` 為空操作（時間格式長版本可回退無害）
- `backend/tests/Feature/ClassSessionsSubstituteStartTimeFormatTest.php`：新增 1 個 test class，2 個 case（HH:MM:SS 格式代課命中 / 無代課回契約老師）

**架構取捨：**

- 採「join 兩側 SUBSTRING」而非「migration-only 修正」：migration 僅修歷史壞資料，不能防範未來寫入路徑再出現異常；join 兩側 SUBSTRING 為防禦性程式碼，永久有效
- 不修改 `schedules.start_time` 欄位型別為 MySQL TIME：該欄位在多處直接字串比對，型別遷移影響面廣，列入 tech-debt 計畫
- migration 採 raw UPDATE 而非 Eloquent：schedules 筆數少，raw UPDATE 最直接；down() 為 no-op（舊格式不影響業務邏輯）

**不做的事：**

- 不更改 `normalizeSessionTimeForSchedule()` 函數——已正確輸出 HH:MM，不需動
- 不修改 `schedules.start_time` 的寫入路徑（ScheduleController、SubstituteController）——現有路徑已正確
- 不改前端邏輯

## 13. 風險 / 假設 / 開放問題

### 風險

| 風險 | 等級 | 業界標準解法（來源） | 本專案採行方式 |
|---|---|---|---|
| SUBSTRING 兩側改動誤影響現有 HH:MM 格式代課記錄 | 低 | 在 join 兩側同時做截斷，HH:MM 前 5 碼仍為 HH:MM，語意不變（MySQL docs 2026 — TIME type） | AC-002 regression test + 抽樣驗證現有 schedules.id=1211 等記錄 |
| migration 修正資料後有其他寫入路徑再寫入 HH:MM:SS | 低 | 確認所有寫入 schedules.start_time 的路徑都經過 normalizeSessionTimeForSchedule 或等效處理（StackOverflow MySQL time format mismatch 2026） | join 兩側 SUBSTRING 為永久防禦；migration 後監控 `LENGTH(start_time)>5` 筆數 |
| `schedules.start_time` 存在 `8:30:00` 等單位數小時格式 | 低 | SUBSTRING(1,5) 對 `8:30:00` 取出 `8:30:`（含冒號），與 `SUBSTRING('08:30:00',1,5)='08:30'` 仍不匹配；需額外 migration | 目前資料庫無此格式（已驗 80 筆），列入 `[AI-RESOLVABLE]` 監控 |

### 假設

- `schedules.start_time` 寫入路徑已統一使用 `normalizeSessionTimeForSchedule()`（HH:MM），本次壞資料為舊版 SmartCalendar 直接 POST `/api/v1/schedules` 遺留的孤例
- 其餘 schedules 寫入路徑（ScheduleController、直接 Supabase insert）在現行代碼中不會再產生 HH:MM:SS 格式

### 開放問題

- `[AI-RESOLVABLE]` 確認是否有其他寫入路徑（如 ScheduleController 或 SmartCalendar Supabase insert）仍可能寫入非 HH:MM 格式：`grep -r "start_time" backend/app/Http/Controllers/ScheduleController.php | grep -v normalize` 驗證
