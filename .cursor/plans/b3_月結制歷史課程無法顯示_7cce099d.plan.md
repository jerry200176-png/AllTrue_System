# Bug Fix Plan：月結制課程無法進入歷史課程

---

## 0. 根因確認（Root Cause）

| 欄位 | 內容 |
|---|---|
| 嚴重度 | P2 |
| 根因類型 | 邏輯錯誤 |
| 根因摘要 | `CourseManagement.vue::effectiveClosedReason` 在沒有 `closed_reason` DB 值時，只對 `isSessionMode(c)` 為 true（堂數制）的課程自動推斷 `'completed'`；月結制（`payment_type === 'monthly'`）被排除，且後端 `StudentClassController::togglePause` 停用月結課時也不自動寫入 `closed_reason`，導致月結課永遠 `effectiveClosedReason === null` → 無法進入 `historyCourses` 區。 |
| 錯誤行為 | 月結制課程停用後（`status = inactive`），在課程管理「歷史課程」摺疊區看不到，混在「進行中」清單或卡在「暫停」狀態。 |
| 預期行為 | 月結制停用課程（`status = inactive`）與堂數制相同，出現在學生的「歷史課程」摺疊區。 |
| 影響範圍 | director / admin 角色；`CourseManagement.vue` `historyCourses` 邏輯；`StudentsList.vue` `getHistoryStudentCourses`；`GET /api/v1/student-classes` 回傳資料；現有所有 `ScheduleMode !== 'count'` 且 `closed_reason IS NULL` 的停用課程記錄。 |
| B1 偵查來源 | 本計畫整合 B1 偵查結果（探索代理 b9549569） |

## 2. 業務背景與影響

月結制課程是補習班主要收費模式之一（`ScheduleMode !== 'count'`，含 `settlement_day` / `monthly_sessions`）。當月結課程結束後，主任無法在課程管理頁看到歷史紀錄，也無法在學生管理頁的歷史課程清單中找到，造成：

- 主任無法追溯月結課的歷史排課、出缺勤、評量記錄。
- UI 混亂：月結停用課仍顯示在「進行中」區塊，或無限期留在「暫停」狀態，無法被清理。

**修復後預期行為**：

- 月結制課程停用（`status = inactive`）後，出現在課程管理頁該學生的「歷史課程」摺疊區，與堂數制一致。
- 後端 `togglePause` 為月結停用課自動補 `closed_reason = 'completed'`（無明確原因時）。
- 前端 `effectiveClosedReason` 對月結 inactive 課程同樣推斷 `'completed'`，處理現有 `closed_reason IS NULL` 的歷史髒資料。

---

## 3. 範圍

### In Scope

- `CourseManagement.vue`：`effectiveClosedReason` 加月結 inactive 推斷邏輯
- `StudentsList.vue`：同步修正 `effectiveClosedReason`（兩頁共用相同邏輯但各自定義）
- `StudentClassController.php::togglePause`：月結停用自動補 `closed_reason = 'completed'`

### Out of Scope

- `useCourseSessionsDisplay.js::isSessionMode`：不改動，月結判斷仍為 `payment_type !== 'session'`
- `isHistoricalCourse`（StudentsList 用於隱藏列表的獨立函式）：不改，不影響本 bug
- `GET /api/v1/student-classes` 的 query / index 邏輯：無需改動
- 家長 Portal、老師工作台：不涉及歷史課程區
- 任何 DB migration：無需新增欄位

## 5. Acceptance Criteria

### AC-001：月結停用課程進入歷史區（前端）

- AC-001-a：director 查看月結制 `status=inactive` 課程，`CourseManagement.vue` 的歷史課程摺疊區顯示該課程
- AC-001-b：`closed_reason IS NULL` 的月結停用課，前端 `effectiveClosedReason` 仍回傳 `'completed'`，不回傳 `null`

### AC-002：後端停用月結課補寫 closed_reason

- AC-002-a：呼叫 `PUT /api/v1/student-classes/{id}/toggle-pause`（或同等停用端點）停用月結課，DB `closed_reason` 自動寫入 `'completed'`（未傳入 `reason` 時）
- AC-002-b：傳入明確 `reason`（如 `'settled'`）時，DB `closed_reason` 以傳入值為準，不被覆蓋

### AC-003：堂數制課程行為不變

- AC-003-a：堂數制（`payment_type=session`）課程的歷史判斷邏輯與修改前完全相同（Revert-proof 可驗）

### AC-004：StudentsList 歷史課程同步

- AC-004-a：StudentsList 的 `getHistoryStudentCourses` 對月結停用課回傳非空清單（與 CourseManagement 行為一致）

## 6. 功能需求 FR

| 編號 | 描述 |
|---|---|
| FR-001 | 修復後，`CourseManagement.vue::effectiveClosedReason(c)` 應在 `c.status === 'inactive'` 且 `c.payment_type` 為月結（非 `'session'`）且無 `c.closed_reason` 時，回傳 `'completed'` |
| FR-002 | 修復後，`StudentsList.vue::effectiveClosedReason(course)` 應加入與 FR-001 相同的月結 inactive 推斷分支 |
| FR-003 | 修復後，`StudentClassController::togglePause`（或對應停用邏輯）應在停用月結課（`ScheduleMode !== 'count'`）且 `$reason` 為空時，自動設定 `$reason = 'completed'`，寫入 `closed_reason` |
| FR-004 | 修復後，`historyCourses(group)` 回傳的課程清單應包含所有 `status=inactive` 的月結課（無論 `closed_reason` DB 值是否為 null） |

## 8. 技術方向

### 涉及檔案與方法

| 檔案 | 方法 / 位置 | 修改說明 |
|---|---|---|
| `frontend/src/pages/CourseManagement.vue` | `effectiveClosedReason`（約 1743 行） | 在 `isSessionMode` 分支後，新增月結 inactive 推斷：`c.status === 'inactive'` 且 `!isSessionMode(c)` → return `'completed'` |

| `backend/app/Http/Controllers/StudentClassController.php` | `togglePause`（約 3459 行） | 擴充現有自動推斷 block：原條件僅限 `ScheduleMode === 'count'`；新增月結分支（`ScheduleMode !== 'count'`，無需檢查 `RemainingSessions`，直接設 `completed`） |

### 架構取捨理由

- **選擇前端 + 後端同時修**（而非只改其中一方）：後端修正確保新停用月結課 DB 有值，前端修正解決現有 `closed_reason IS NULL` 的歷史資料，兩者互補。
- **月結 inactive 無條件推 `'completed'`**（而非加 `EndDate` 判斷）：月結課「暫停」在現有 UI 沒有明確欄位與「永久停用」區分；所有 `inactive` 的月結課業務上均視為結束；若未來需要「月結暫停」語意，再透過 `closed_reason = 'paused'` 擴充。

## 13. 風險 / 假設 / 開放問題

> WebSearch 查詢結果（2026-04-21）：查詢 monthly billing course history filter 業界慣例，主流 SaaS billing 設計（Stripe、Recharge API）採用明確 status enum（`active` / `canceled` / `ended`）區分永久停止與暫停，不依賴剩餘堂數推斷。業界一致以「明確 status 寫入 DB」為歷史判斷依據，本修正方向（後端補寫 `closed_reason` + 前端 fallback）符合此慣例。

| 類型 | 內容 |
|---|---|
| 風險 | 現有「月結暫停」語意不明確：若未來出現「月結臨時暫停、預期恢復」需求，前端把所有 inactive 月結推成 `completed` 會產生語意衝突。建議屆時以 `closed_reason = 'paused'` 明確標記暫停，前端改為判斷 `closed_reason` 而非 inactive。 |
| 假設 | 月結制課程業務上「停用 = 永久結束」，無臨時暫停後恢復的場景（現有系統無對應 UI）。 |
| 開放問題 | `StudentsList.vue::isHistoricalCourse`（用於隱藏列表）對月結的行為是否也需要對齊？目前暫列為 Out of Scope，待 AC-004 驗收後再評估。 |
