## 2. 目標與業務背景

**痛點**：老師幫學生點名「請假」後，進入評量頁（LearningRecordsPage）卻仍看到該堂顯示「未填」，並被要求填寫評量表。造成老師困惑，並干擾未填評量的實際待辦計數。

**業務價值**：還原老師評量工作台的正確語意，降低誤操作與客服溝通成本。

**KPI**：
- 請假堂次在評量頁「週檢視 missingCount」中計數為 0
- 請假堂次的評量卡片不顯示「未填」標籤，不可點擊填寫
- 通過既有回歸測試無新增失敗

---

## 3. 範圍

**In Scope**：
- `LearningRecordsPage.vue` 的 `buildEvents` 對 `leave`、`leave_adjusted`、`excused` 堂次的顯示邏輯
- `scheduleStatusLabel` 補上請假／取消的 label 分支
- `missingCount` 計算排除請假類堂次
- `LearningRecord.scopeExcludeLeaveSessionPendingReview` 補上 `excused` 狀態（後端次要修正，與 SmartCalendar LEAVE_STATUSES 對齊）

**Out of Scope**：
- 後端 `ClassSessionController` 回傳 `learning_record_status: na` 的重構（風險較高，留下次評估）
- TeacherHomePage「今日待填」邏輯（現已正確，不動）
- 主任端待審列表（已有 `excludeLeaveSessionPendingReview` 保護）

## 5. User Stories

> **As a** 老師，**I want** 已請假的堂次在評量頁不顯示「未填」提示，**so that** 我不會誤以為還需填評量表，每週未填計數也能正確反映真實待填數量。

Acceptance Criteria：
- [ ] 請假堂次（`ClassSession.Status` 為 `leave` / `leave_adjusted` / `excused`）在週日曆格中顯示「請假」而非「未填」
- [ ] 取消堂次（`cancelled`）在週日曆格中顯示「取消」而非「未填」
- [ ] 上述堂次不計入每日 `missingCount`
- [ ] 上述堂次的評量卡片為不可點擊狀態（`fillLocked = true`）
- [ ] 仍有真實待填（`scheduled` 且課程已結束）的堂次正常顯示「未填」，不受影響

## 5b. UI/UX 精緻化需求

受影響頁面：**評量頁（LearningRecordsPage）週課表區塊**

| 面向 | 要求描述 |
|---|---|
| **版面層次** | 請假卡片視覺層次應低於「未填」卡片：使用較低對比度的灰色文字 + 淡色背景，與「未填（紅/橙色警示）」明顯區隔 |
| **色彩一致性** | 沿用 SmartCalendar 已有 `rc-tag rc-leave`（藍灰系）作為請假標籤色；`cancelled` 使用現有 cancelled 色調；禁止自創新色票 |
| **互動回饋** | 請假卡片不可點擊（cursor: not-allowed 或無 hover 效果）；`fillLocked = true` 時不觸發 modal |
| **空狀態設計** | 若整週全為請假／取消，`missingCount` 全為 0，週標頭不顯示紅點 badge；顯示「本週無待填評量」空狀態文字（非空白） |
| **載入狀態** | 無新增 API，不額外影響 loading 流程 |
| **防呆設計** | 請假卡片上方不得顯示「填寫」按鈕；若有誤觸，不應打開評量 modal |
| **響應式 / 行動裝置** | 評量頁以手機操作為主（老師常用手機點名），請假 label 在行動版仍需保持觸控目標 ≥ 44px、不截字 |

## 6. 功能需求（FR）

**FR-001**：`buildEvents` 在組裝 event 物件前，若 `rawSession.status` 屬於請假類（`leave`、`leave_adjusted`、`excused`），則 `formStatus` 設為 `'leave'`，`fillLocked` 強制設為 `true`，`fillLockReason` 設為「此堂已請假，無需填寫評量」。

**FR-002**：`buildEvents` 若 `rawSession.status === 'cancelled'`，則 `formStatus` 設為 `'cancelled'`，`fillLocked` 強制設為 `true`，`fillLockReason` 設為「此堂已取消」。

**FR-003**：`scheduleStatusLabel` 補上對應分支：`'leave'` / `'leave_adjusted'` / `'excused'` → `'請假'`；`'cancelled'` → `'取消'`。

**FR-004**：`weekDays` 的 `missingCount` 只計算 `formStatus === 'missing'` 的 event（現行邏輯已如此，但因 FR-001/002 修正後，請假堂不再 formStatus='missing'，故 missingCount 自動正確）。

**FR-005**（後端次要）：`LearningRecord.scopeExcludeLeaveSessionPendingReview` 將 `excused` 加入請假類 `ClassSession.Status` 判斷，與前端 `LEAVE_STATUSES` 對齊。

## 10. QA 驗收標準與測試計畫

### FR-001 / FR-002 — buildEvents 請假堂次過濾

| 類型 | 案例 |
|---|---|
| Happy Path | 老師將學生點名為請假 → 進入評量頁週視圖 → 該堂顯示「請假」標籤，無「未填」 |
| Happy Path | 取消堂次顯示「取消」，不計入 missingCount |
| Edge Case | 同一堂先請假後轉為已上（leave → attended）：`rawSession.status = attended`，應正常顯示可填評量 |
| Edge Case | `leave_adjusted`（調課後請假）堂次，同樣不顯示「未填」 |
| Edge Case | `excused` 狀態堂次，同樣不顯示「未填」 |
| Error Case | API 回傳 `learning_record_status: null` 且 `rawSession.status: leave`：應顯示「請假」而非「未填」 |
| 回歸 | 正常 `scheduled`（過去）且無 LR：仍顯示「未填」，未受影響 |
| 回歸 | `deduplicateSessionsBySlot` 的去重邏輯不因新增狀態判斷而改變（AI_REGRESSION_LESSONS §2026-04-15） |

### FR-005 — scopeExcludeLeaveSessionPendingReview 補 excused

| 類型 | 案例 |
|---|---|
| Happy Path | ClassSession.Status = excused 且 LR.Status = pending → 不出現在 learning-records 待審列表 |
| 回歸 | ClassSession.Status = leave 的現有行為不變 |

### 假設（Assumptions — 業界慣例：明確列假設讓 CTO/QA 可挑戰）

> 參考 Google SRE、Atlassian PRD 模板：「未驗證的假設是最大的隱性風險。」

- **A-01**：`GET /api/v1/class-sessions` 對請假堂次穩定回傳 `status: 'leave'`（或 `leave_adjusted` / `excused`），不會因 cache 或 eager-load 問題回傳舊值 → 若不成立，需在 API 層加 cache-invalidation
- **A-02**：`LEAVE_STATUSES = ['leave', 'leave_adjusted', 'excused']` 涵蓋目前所有請假語意；業務上不存在未被這三值覆蓋的「已請假但仍需評量」場景
- **A-03**：評量表「已填但請假」的孤兒 LR（老師先填評量、後補請假）已由 `VoidedAt` cascade 正確處理，不會因本次前端修改產生新孤兒
- **A-04**：`deduplicateSessionsBySlot` 的輸出順序在本次修改後不變（`SESSION_STATUS_PRIORITY` 不調整），去重結果一致
