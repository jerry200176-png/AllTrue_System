# 代課換老師流程 UX 優化 PRD

## 1. 文件資訊

| 欄位 | 內容 |
|---|---|
| 功能名稱 | 代課換老師流程 UX 優化（Substitute Teacher UX Revamp） |
| 版本 / 日期 | v1.0 / 2026-04-18 |
| 狀態 | Draft |
| 目標角色 | 主任（主要操作者）、櫃檯、任課老師（請假發起者）、家長（被通知方） |

---

## 2. 目標與業務背景

### 現在的痛點

- 代課 Modal 的「代課老師」下拉選單是原生 `<select>`，**列出全部老師沒有任何篩選**：使用者看不出誰綁此分校、誰在該時段已有課、誰教該科目，容易選錯；送出才由後端回 422 錯誤。
- 老師請假時，系統沒有「老師請假」的一級流程：主任必須**逐堂手動拖曳/右鍵逐一代課**，一位老師當天 4 堂課就要操作 4 次，耗時且容易漏改。
- 操作回饋用 `alert()`，**無 toast、無 Undo**；選錯老師只能再操作一次代課改回來。
- 代課 + 調課組合操作（老師請假 + 學生換時間）容易出錯，前一份 PRD 3972a088 已修正資料一致性，但流程上的**引導缺失**還沒解決。
- 家長不知道今天老師被換了；ParentPortal 沒有提示。
- 主任儀表板看不到「近期代課歷史」，無法掌握代課頻率與老師負載。

### 業務價值

- 單次代課操作時間從「約 40 秒/堂」降到「≤ 15 秒/堂」。
- 老師請假時批次代課：從「N 堂 × 40 秒 = 數分鐘」降到「一次操作 ≤ 30 秒」。
- 降低選錯代課老師的錯誤率（分校不符、衝堂、不授此科）。
- 提升家長對臨時代課的知情度與信任感。

### 成功指標（KPI）

- 代課操作平均完成時間 ≤ 15 秒（單堂）、≤ 30 秒（批次 N 堂同老師）。
- 代課提交後被後端 422 擋下的比例 < 2%（目前憑感覺約 10-15%）。
- 代課成功 → 家長站內通知送達率 ≥ 98%。
- 近 7 天代課記錄卡片在主任儀表板的 p95 渲染時間 < 400ms。

## 3. 範圍

### In Scope

- 單堂代課 Modal（SmartCalendar）UX 全面重做：智能老師清單、inline 衝堂/容量/科目/分校提示、toast、5 秒 Undo。
- 新增「老師請假」一級流程入口：可在 SmartCalendar 點老師列表頭或 TeachersList 觸發，填入請假日期區間後系統列出當日受影響堂次，支援「全部指派同一代課老師」或「逐堂指派」。
- 代課成功後自動產生家長站內通知（`Notification` 表 + `NotificationController`），家長在 ParentPortal 可讀取與清除。
- 主任儀表板新增「近 7 天代課記錄」卡片（只讀）。
- UI/UX 精緻化：頭像、色彩層次、空狀態、loading、動畫，符合既有 design token。
- **多分校主任的老師池擴充（scope 調整，非跨分校教學）**：代課老師清單來源由「代課堂次的分校」擴充為「當前操作者（主任）在 `UserCampus` 中所有有管理權限的分校」之老師聯集，單分校主任行為不變。Modal 在候選卡片上顯示該老師綁定的分校徽章；若老師綁定分校與代課堂次分校不同，以「跨分校協調」警告徽章（次要警示色）提醒操作者需私下確認老師能否到場。系統不強制阻擋，也不自動安排學生跨分校上課。
- **跨分校全域衝堂偵測（物理不可分身）**：老師的衝堂判定必須橫跨該老師綁定的**所有分校**（即 `UserCampus` 中全部 `CampusID`，不限於操作者的 `managed_campus_ids`），因為同一位老師同一時間只能在一個物理位置上課。若老師於別分校同時段已有課，候選卡片顯示紅色「衝堂」標籤並 disabled 不得選取；後端 `substitute` 與 `batch-substitute` API 於寫入前必須再次跨分校檢查，防止繞過前端直接送出。Availability API 的回應僅包含 busy/idle 區間，**不揭露別分校的學生/科目/教室明細**，避免越權看他校資料。

### Out of Scope

- LINE 主動推播（使用者確認「現在 LINE 沒有自動推播」，本次僅做站內通知）。
- 代課老師排班預設偏好 / 代課老師黑白名單。
- 老師請假流程連動薪資計算（老師端時數統計）。
- 課程管理頁（CourseManagement）的代課顯示邏輯（前一份 PRD 3972a088 已處理，本次不重構）。
- 家長端 ParentPortal UI 重做（僅利用既有通知 feed 新增代課類別）。
- **學生跨分校上課**：本次不支援將學生課堂地點改到另一個分校（教室/刷卡/家長動線皆需連動，複雜度高）。若老師來自別分校代課，預設視為「老師到該堂課原本的分校授課」，系統不變更 ClassSession 的分校歸屬。
- **跨主任權限邊界的代課調度**：主任只能使用自己在 `UserCampus` 有權限的分校老師；不支援總部層級的跨主任調度 UI。

## 5. User Stories

### US-01（主任：單堂代課更快更準）
> **As a** 主任, **I want** 在代課 Modal 的老師清單中立即看到每位老師的「分校狀態 / 此時段忙碌 / 是否授此科」標籤, **so that** 我不用逐一嘗試就能選對代課老師。
>
> Acceptance Criteria：
> - [ ] 老師清單顯示：頭像、姓名、分校綁定徽章（顯示老師綁定的分校縮寫）、此時段衝堂標籤（紅）、授此科標籤（綠）。
> - [ ] 候選老師池 = 當前主任在 `UserCampus` 有管理權限的所有分校之老師聯集。
> - [ ] **衝堂判定跨全分校**：只要該老師在該時段（同日 + 時段重疊）於任何分校有課（含正班、已被指派代課、已加課），卡片顯示紅色「衝堂」標籤且 disabled 不可選取；衝堂原因 tooltip 顯示「於 XX 分校有課」但不顯示學生/科目細節。
> - [ ] 與代課堂次分校不同但此時段無課的老師：卡片可選取，加註「跨分校協調」次要警告徽章提醒人工確認交通/意願。
> - [ ] 完全不在當前主任管理分校範圍內的老師：不出現在清單中（不是 disabled，而是不可見）。
> - [ ] 支援姓名關鍵字搜尋，搜尋框 ≤ 150ms 反應。

### US-02（主任：代課不怕選錯，有後悔藥）
> **As a** 主任, **I want** 代課送出成功後有 5 秒 Undo 機會, **so that** 手滑選錯不用再操作一次代課改回去。
>
> Acceptance Criteria：
> - [ ] 成功 toast 顯示老師姓名 + 「復原」按鈕 + 5 秒倒數條。
> - [ ] 5 秒內按復原會把代課動作逆轉（schedules + ClassSession + 通知家長一起撤回）。
> - [ ] 5 秒後復原按鈕消失、通知家長不可撤回。

### US-03（主任：老師請假一次搞定多堂）
> **As a** 主任, **I want** 登記某位老師某日請假後，系統列出當日受影響的所有堂次，讓我一次派同一代課老師或逐堂指派, **so that** 不用來回切換日期與學生。
>
> Acceptance Criteria：
> - [ ] 填入老師 + 日期區間 → 列表顯示所有受影響 ClassSession（學生姓名、時段、科目）。
> - [ ] 「全部指派同一老師」輸入框旁邊即時顯示該老師的衝堂堂數警告。
> - [ ] 逐堂指派時每堂保留獨立老師欄位。
> - [ ] 送出後顯示 summary：X 堂成功 / Y 堂衝堂需處理。

### US-04（家長：知道今天老師被換了）
> **As a** 家長, **I want** 在 ParentPortal 看到一條「XX 老師今天由 XX 老師代課」的通知, **so that** 我不會在刷卡後才發現。
>
> Acceptance Criteria：
> - [ ] 代課成功 2 秒內，該學生家長的 `Notification` 清單新增一筆，type = `substitute`。
> - [ ] 通知包含：學生姓名、科目、日期時段、原老師 → 代課老師。
> - [ ] 在 Undo 時間窗內若復原，該通知會被標記為 `voided` 不再顯示。

### US-05（主任：掌握代課頻率）
> **As a** 主任, **I want** 在 DirectorDashboard 看到近 7 天代課記錄彙總, **so that** 我能評估老師負載與請假頻率。
>
> Acceptance Criteria：
> - [ ] 卡片顯示近 7 天每筆代課：日期、學生、原老師 → 代課老師、原因。
> - [ ] 僅顯示當前切換分校的代課記錄。
> - [ ] 空狀態顯示「近 7 天無代課記錄」+ 插畫。

## 5b. UI/UX 精緻化需求

### 5b-1. 代課 Modal（SmartCalendar.vue）

| 面向 | 要求描述 |
|---|---|

## 6. 功能需求（FR）

- **FR-001**：代課 Modal 必須顯示每位老師的「分校綁定徽章 / 此時段衝堂（含跨分校）/ 授此科」三種標籤，標籤資料來源為 `UserCampus`、**該老師所有分校**的同日同時段 `schedules` + `ClassSession`、老師授課科目字典（若無授課科目字典則僅顯示前兩類標籤）。
- **FR-002**：代課 Modal 必須支援姓名搜尋框過濾老師清單，最少支援中文與英文姓名關鍵字，防抖 ≤ 150ms。
- **FR-003**：老師候選池必須等於「當前操作者於 `UserCampus` 有管理權限的所有分校的老師聯集」；不在此範圍的老師不出現在清單。老師綁定分校與代課堂次分校不同但此時段無課時，卡片顯示「跨分校協調」警告徽章但不阻擋選取（系統視為老師到原堂次分校授課）。後端 `substitute` API 必須相應放寬「所選老師未綁定此分校」檢查為「所選老師未綁定任一操作者管理分校」。
- **FR-004a（新增，跨分校衝堂防呆）**：老師若於該時段於**任一分校**已有課（含正班排課、已被指派的代課、已加課），前端卡片必須 disabled 且顯示紅色衝堂標籤；後端 `POST /api/v1/class-sessions/{id}/substitute` 與 `POST /api/v1/teacher-leaves/batch-substitute` 寫入前必須再跨分校查一次 `schedules` + `ClassSession` 確認該老師該時段無其他課程，若有則回 422 並回 `conflicts: [{campus_id, start_time, end_time}]`（僅回 campus_id 不含學生/科目）。衝堂偵測**不可**被單一 `branch_id` query param 繞過。
- **FR-004**：送出代課前若偵測到衝堂或容量爆表，必須在 Modal 內 inline 顯示警告且保留送出按鈕；送出後若後端仍回 422，錯誤訊息顯示在按鈕上方而非 alert。
- **FR-005**：代課送出成功後必須呈現右下角 toast + 5 秒 Undo 按鈕；點擊 Undo 呼叫「取消代課」API，復原 schedules + ClassSession teacher + 廢止家長通知。
- **FR-006**：新增「老師請假」入口（SmartCalendar 老師欄位右鍵選單或新按鈕），可選老師 + 日期區間。
- **FR-007**：提交請假後，系統列出受影響 ClassSession 清單（該老師為正班或已是代課老師，且在請假區間內且未請假/未取消的堂次）。
- **FR-008**：批次代課頁提供「全部指派同一老師」輸入與逐堂指派兩種模式；切換任一模式時 UI 必須即時同步。
- **FR-009**：批次送出後系統以單一交易處理所有指派（失敗回滾），回傳每堂成功/失敗狀態；前端顯示 summary。
- **FR-010**：代課（單堂或批次內每堂）成功時，系統為該學生家長建立一筆 `Notification` 記錄，type = `substitute`，包含學生、科目、日期、原老師、代課老師、原因。
- **FR-011**：Undo 代課時，關聯的 `Notification` 必須被標記為作廢（voided / hidden），家長端不再顯示。
- **FR-012**：DirectorDashboard 新增「近 7 天代課記錄」卡片，API 必須依當前 `branch_id` 過濾，最多回 50 筆（前端顯示前 5 筆 + 展開）。

## 9. 資安與存取控制

- 所有新 API 受 `role:director|teacher_admin`（代課操作）或 `role:director`（Recent、批次）保護；家長 API 在 ParentPortal session 下讀通知（既有機制）。
- **授權邊界定義（跨分校相關）**：
  - 「操作者管理分校集合」`managed_campus_ids` = 當前 token 使用者在 `UserCampus` 的所有 `CampusID`（可為 1 個或多個）。
  - 「代課堂次分校」`session_campus_id` = 該 ClassSession 原本歸屬的分校。
  - 操作者必須 `session_campus_id ∈ managed_campus_ids` 才能對該堂操作代課（不能動別人分校的堂次）。
  - 代課老師候選池 = 所有 `UserCampus.CampusID ∈ managed_campus_ids` 的老師。
  - 老師綁定分校與 `session_campus_id` 不同時系統不阻擋，但前端 UI 呈現「跨分校協調」徽章；後端寫入 `ClassSession.TeacherID` 為代課老師 ID，**`ClassSession` 分校歸屬與教室不變更**。
- 所有新 API 必須強制以 `managed_campus_ids` 作為範圍：
  - `teacher-leaves/preview` 與 `batch-substitute`：僅可針對 `managed_campus_ids` 內分校的老師與堂次。
  - `substitutes/recent`：結果限 `session_campus_id ∈ managed_campus_ids`。
  - `teachers/{id}/availability`：查詢對象老師必須有任一 `UserCampus.CampusID ∈ managed_campus_ids`；但回傳的忙碌時段跨老師全部分校（因為物理衝堂判定需跨全分校），僅揭露 `{start_time, end_time, campus_id}`，不含別分校的學生/科目/教室資訊。
- PII：家長通知包含老師姓名（非敏感）與學生姓名（中度敏感）；沿用既有 Notification 儲存方式，不記錄手機/Email。
- 稽核 log：
  - 單堂代課（既有）保留；新增 `cross_campus=true/false` 欄位標記是否為跨分校老師被指派。
  - Undo：新增 `[substitute_undo]` log 行，包含 operator、原 substitute schedule id、反向 id、時間窗內/外。
  - 批次代課：新增 `[teacher_leave_batch]` log 行，包含 operator、受影響堂次數、成功/失敗計數、跨分校堂次數。
- STRIDE 快評：
  - Spoofing：Undo 必須驗證 operator 是原代課建立者或 `session_campus_id ∈ operator.managed_campus_ids`，單分校主任不可跨分校 Undo 別分校的代課。
  - Tampering：批次交易保證原子性，避免半成功狀態。
  - Repudiation：完整稽核 log（含 cross_campus 旗標）。
  - Info Disclosure：Availability 僅回傳時段 busy/idle 不洩露學生姓名；跨分校老師的 availability 回傳內容同一格式，不揭露別分校的學生明細。
  - DoS：批次 preview 限最多 30 天、最多 50 堂；超過須分段。
  - EoP：role + `managed_campus_ids` 雙層檢查；不得以單一 `branch_id` query param 繞過。

## 10. QA 驗收標準與測試計畫

### 對應 FR 的測試分類

**Happy Path**
- FR-001/002/003：開啟代課 Modal → 老師清單正確顯示三類標籤 → 搜尋 → 選中 → 送出成功。
- FR-005：送出 → toast 顯示 → 按 Undo → 代課逆轉，schedules/ClassSession/Notification 皆回復。
- FR-006~009：請假 → 預覽受影響堂次 → 一鍵全部指派 → 送出 → summary 全成功。
- FR-010：代課成功後該學生家長 `Notification` 立即新增一筆。
- FR-012：DirectorDashboard 顯示近 7 天代課。

**Edge Case**
- 老師清單僅 1 位老師可選（其他都衝堂或未綁分校）。
- 批次代課其中 1 堂衝堂：FR-009 summary 顯示 N-1 成功 + 1 堂需處理；整批交易仍 commit 成功堂次（或依 CTO 決策選擇整批回滾）。**[TODO: 需確認交易策略 — 部分成功 vs 整批回滾]**（Owner: CTO + PM）
- 日期區間跨月底。
- 同一堂課已被代課過（舊代課老師 → 新代課老師），Undo 時回到誰?（應回到 Undo 當下的 previous 狀態，不是原始正班老師）。
- 家長未綁定 ParentPortal 時，Notification 仍應寫入，待家長登入後可見。

**Error Case**
- 代課老師與正班相同：inline 錯誤提示，不送出。
- 代課老師未在當前主任管理分校集合內：不出現在清單，後端收到也回 422。
- Undo 逾時（> 5 秒）：按鈕消失，API 呼叫回 410。
- 批次代課所有堂次都衝堂：阻擋送出，提示調整指派。
- 單分校主任嘗試 Undo 另一分校的代課記錄：回 403。

**跨分校 Edge Case**
- 多分校主任（管理 A、B 分校）操作 A 分校的堂次代課：候選老師包含 A 與 B 分校老師；B 分校老師且此時段無課：卡片顯示「跨分校協調」徽章可選取；送出成功不變更 ClassSession 分校歸屬。
- 單分校主任（僅管理 A 分校）操作 A 分校的堂次代課：候選老師只有 A 分校老師；行為與本次優化前相同。
- **老師在別分校同時段已有課**：卡片必須紅色「衝堂」標籤 + disabled；tooltip 顯示「於 XX 分校有課」但不顯示學生/科目；若前端被繞過直接打 API，後端必須回 422 with conflicts 陣列。
- 老師跨分校衝堂狀態在操作過程中被即時消解（別人取消了另一堂）：重開 Modal 或重查 availability 後該老師應變回可選。
- 主任操作不在其 `managed_campus_ids` 內的堂次：回 403，不應看到堂次資料。
- Availability API 回應必須僅含 `{start_time, end_time, campus_id}`，不得含其他欄位（schema snapshot 測試）。
- 稽核 log 必須正確寫入 `cross_campus=true`（當代課老師綁定分校 ≠ 堂次分校）。

**回歸測試**（對照 `docs/AI_REGRESSION_LESSONS.md`）
- 代課 + 調課組合（PRD 3972a088）：本次變更不得重新引入 duplicate scheduled rows。
- 請假不扣堂數：代課不得誤觸 SessionDeducted。
- 多校區隔離：**主任不得對自己 `managed_campus_ids` 外的堂次做任何操作**（本次授權邊界比以前精細化，需重新驗證所有既有跨校隔離測試仍通過）。

### 假設

- 目前 `NotificationController` 支援建立任意 type 的通知且家長 ParentPortal feed 會自動顯示（需實作前小驗證）。
- 老師的分校綁定資訊已在 `UserCampus` 完整；一位老師可綁多分校。
- 衝堂判定以「同老師 + 同日 + 時段重疊」為標準，**跨該老師所有綁定分校**（物理不可分身原則）。
- 跨分校老師被指派代課時，預設情境為**老師前往原堂次的分校授課**；學生、教室、刷卡、家長動線皆不變。
- 單分校主任的操作體驗與本次優化前相同（候選池僅該分校老師），無跨分校疑慮。
