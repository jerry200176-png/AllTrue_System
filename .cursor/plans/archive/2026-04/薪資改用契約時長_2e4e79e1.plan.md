# PRD — 薪資改用客約排定時長

## 根本原因

`FinanceController::calcHours`（行 433）優先用實際 `StartTime`/`EndTime`，`buildConcurrencyBonusMap`（行 1378）也用實際 end time 建構 interval endpoint。當主任在「備註 / 調整時段」修改結束時間（如 20:00 → 19:30），老師薪資就被縮短（350 × 1.5 = 525，而非 350 × 2 = 700）。

## 業務規則（已確認）

> 老師薪資以**客約排定時長**（`StudentClass.resolveSessionDurationForWeekday` 或 `SessionDuration`）為準；時段微調僅供記錄用，不影響薪酬。

## 受影響檔案

- [`backend/app/Http/Controllers/FinanceController.php`](backend/app/Http/Controllers/FinanceController.php)
- [`backend/tests/Feature/ParttimePayrollTest.php`](backend/tests/Feature/ParttimePayrollTest.php)
- [`backend/tests/Feature/PayrollConcurrencyTest.php`](backend/tests/Feature/PayrollConcurrencyTest.php)

## 技術修改

### 1. `calcHours` — 翻轉優先順序（行 433）

```php
// 新優先順序：
// 1. 契約排定時長（resolveSessionDurationForWeekday 或 SessionDuration）
// 2. 實際 StartTime/EndTime（fallback，當合約資料缺失時）
// 3. 2.0h default

private function calcHours(
    ?string $startTime, ?string $endTime,
    $studentClass = null, ?string $sessionDate = null
): float
```

呼叫端（3 處）需同步加上 `$r->SessionDate` / `$cs->SessionDate`：
- 行 241：`$this->calcHours($r->StartTime, $r->EndTime, $r->studentClass, $r->SessionDate)`
- 行 283：`$this->calcHours($cs->StartTime, $cs->EndTime, $sc, $cs->SessionDate)`
- 行 1266：`$this->calcHours($r->StartTime, $r->EndTime, $sc, $r->SessionDate)`

### 2. `buildConcurrencyBonusMap` — interval end 改用契約時長

新增 `private function contractedDurationMinutes($lr): int` helper：
- 嘗試 `resolveSessionDurationForWeekday(isoWeekday)` → 若 ≥ 30 則採用
- fallback 到 `SessionDuration`
- 若皆無，返回 0（由呼叫端 fallback 到 actual end）

Interval 建構（行 1420 區塊）：
```php
$contractedDur = $this->contractedDurationMinutes($r);
$endMin = $contractedDur > 0 ? ($startMin + $contractedDur) : $endMin;
```

### 3. 測試更新

現有 fixture 全部 `SessionDuration = 120`（2h）。

**不受影響**（實際時長 = 2h）：
- 大多數 `14:00-16:00`、`18:00-20:00` 測試 → contracted = actual → 無變化

**需更新預期值**（實際時長 ≠ 2h）：
- `ParttimePayrollTest` 中 `17:00-20:00`（3h actual）→ 改用契約 2h 計算
- `PayrollConcurrencyTest` 中 `18:00-19:00`（1h actual，n=3）→ 改用契約 2h：
  - 預期從 450 → **900**（700 base + 200 concurrency）

新增 1 個回歸測試案例：contracted 2h / actual 1.5h → 薪資仍等於 contracted 2h 的結果

## 與「單堂費用固定不隨時長」的關係

兩個計畫修的是同一根本問題的不同側：

| 側 | 計畫 | 修改點 |
|---|---|---|
| 學收端 | 單堂費用固定不隨時長 | `ClassSessionController::syncSessionChargeForTimeChange` |
| **薪資端** | **本計畫** | `FinanceController::calcHours` + `buildConcurrencyBonusMap` |

可以**先**完成本計畫（較小），**再**處理學收端（含 Backfill Migration），或平行進行。
