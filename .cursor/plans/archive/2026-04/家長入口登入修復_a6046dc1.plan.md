---

## 2. 目標與業務背景

**現在的痛點：**

1. 家長輸入正確的學生姓名與手機號碼，卻顯示「登入失敗，請確認學生姓名及手機號碼是否正確」，無從得知真正原因（手機未登錄？姓名不符？還是其他問題）。
2. 系統管理員曾用自己的 LINE 帳號測試綁定某學生，導致該學生的 `LineID` 欄位被佔用，家長無法用自己的 LINE 帳號登入家長 LINE 入口。

**解決後帶來的業務價值：**

- 家長可以明確知道登入失敗的原因，自行判斷是否需要聯繫分校。
- 分校主任不需要花時間接電話排查「到底是姓名不對還是手機沒填」。
- 避免因測試操作污染學生資料，阻礙真實家長使用系統。

**成功指標：**

- 黃品皓媽媽可以在 5 分鐘內成功登入家長入口。
- 登入失敗時，家長可看到明確的原因說明（非通用錯誤文字）。

---

## 3. 範圍

**In Scope：**

- 補登 `Student.Phone` 欄位（資料修復）
- 清除測試用 `Student.LineID`（資料修復）
- 改善 `ParentPortal.vue` 登入失敗錯誤訊息的展示邏輯（前端程式修改）
- 為錯誤提示增加「聯繫分校」引導 CTA

**Out of Scope：**

- 修改後端登入邏輯或驗證規則
- 新增 `parent_phone` 欄位作為第二登入方式
- LINE 綁定/解綁的管理後台 UI（本次不做）

## 5. User Stories

**Story 1 — 手機號碼登入**

> **As a** 家長，**I want** 輸入學生姓名和手機號碼後能看到明確的失敗原因，**so that** 我知道該怎麼處理（自己打錯字 vs 需要聯繫分校）。

Acceptance Criteria：
- [ ] `Student.Phone` 已填且與輸入吻合時，登入成功並進入儀表板
- [ ] `Student.Phone` 為空時，顯示「此學生尚未設定聯絡手機，請聯繫分校補登後再登入」
- [ ] 姓名或手機不符時，顯示「查無此學生或手機號碼不符，請確認姓名與手機是否正確」
- [ ] 上述訊息下方有「聯繫分校」的引導連結或說明

**Story 2 — LINE 綁定重置**

> **As a** 系統管理員，**I want** 能清除學生的測試用 LINE 綁定，**so that** 真實家長可以正常進行 LINE 登入綁定。

Acceptance Criteria：
- [ ] 執行 tinker 指令後，`Student.LineID` 被設為 null
- [ ] 家長重新透過 LINE LIFF 登入時，流程引導其完成新的綁定

## 5b. UI/UX 精緻化需求

以下針對 [`frontend/src/pages/ParentPortal.vue`](frontend/src/pages/ParentPortal.vue) 的登入區塊：

| 面向 | 要求描述 |

## 6. 功能需求（FR）

**FR-001**：`ParentPortal.vue` `login()` 的 `catch` 區塊應優先顯示 `error.message`（即後端 API 回傳的 `data.message`），若 `error.message` 為空才 fallback 至「登入失敗，請確認學生姓名及手機號碼是否正確」。

**FR-002**：`Student.Phone` 欄位補登（資料修復）——黃品皓的 `Phone` 須設為 `0933393964`，使 `login()` 的名字+手機比對可正確通過。

**FR-003**：`Student.LineID` 清除（資料修復）——黃品皓的 `LineID` 須設為 `null`，使家長可用自己的 LINE 帳號完成綁定。

**FR-004**：登入按鈕在 API 請求期間顯示 loading 狀態，防止重複送出。

---

## 7. 非功能需求（NFR）

- **效能**：`POST /api/v1/parent/login` 回應時間 < 500ms（現有即符合，無需調整）
- **錯誤處理與降級**：API 請求 timeout 或網路錯誤時，`catch` 應顯示「網路異常，請稍後再試」，不得顯示技術性 stack trace
- **向下相容**：後端 API 回應格式不變，僅修改前端顯示邏輯

- API：`POST /api/v1/parent/login`（後端不需改動）

- 資料表：`Student`（欄位 `Phone`、`LineID`——純資料修復，無 migration）

- 資料修復透過管理後台 UI（StudentsList）執行 `Phone`，透過 `php artisan tinker` 清除 `LineID`；兩者均不需 migration。

## 9. 資安與存取控制

- `POST /api/v1/parent/login` 為公開路由（無認證要求），現有設計正確。
- 本次修改**僅影響前端展示層**（catch 訊息），不改變後端驗證邏輯，無新增攻擊面。
- **PII 考量**：後端錯誤訊息明確指出「此學生尚未設定聯絡手機」，可能略微洩漏學生存在性資訊，但與現有設計一致；若有疑慮可在後端統一改為通用訊息（Out of Scope）。
- **STRIDE 快評**：
  - Spoofing：無影響（登入仍需正確手機號碼）
  - Tampering：無影響（前端只改 UI 顯示）
  - Information Disclosure：後端訊息直接顯示，風險低但略有資訊洩漏（見 PII 考量）
  - 其他：無影響
- 稽核 log：資料修復（`tinker` 指令）不自動寫 log，需人工記錄操作時間與執行人。
