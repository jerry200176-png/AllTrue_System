# 課程管理「新增堂次」入口重設計畫（給 UI/UX + Dev + QA）

## 目標與成功指標
- 目標：把目前藏在「單堂檢視」內的 `+ 新增堂次` 提升為課程管理列表的直覺入口，讓使用者不用先點某一堂才能加課。
- 成功指標（上線後 1-2 週觀察）：
  - 「新增堂次」操作路徑從 3-4 步降至 1-2 步。
  - 透過 `SessionEditModal` 觸發加課的比例顯著下降。
  - 加課成功率維持不變或提升（不增加 API 失敗率）。

## 現況摘要（對齊現有實作）
- 目前入口 A：`SessionEditModal` 右下角 `+ 新增堂次`（可見性低）
  - 位置：[`/home/admin/frontend/src/components/course-management/SessionEditModal.vue`](/home/admin/frontend/src/components/course-management/SessionEditModal.vue)
- 目前入口 B：`編輯課程` modal 內「＋ 單次加課」
  - 位置：[`/home/admin/frontend/src/pages/CourseManagement.vue`](/home/admin/frontend/src/pages/CourseManagement.vue)
- 主要加課流程已存在（可重用）：
  - 開啟與送出：`openQuickAddSessionModal` / `submitQuickAddSession`
  - API：`POST /api/v1/student-classes/{id}/add-session`
  - 位置：[`/home/admin/frontend/src/pages/CourseManagement.vue`](/home/admin/frontend/src/pages/CourseManagement.vue)

## UX 策略（本次決策）
- 主入口放在「每筆課程列操作區」：在課程列的操作按鈕群中新增 `新增堂次` 按鈕。
- 保留舊入口但降權：
  - `SessionEditModal` 內入口改為次要連結或移除（依 UI/UX 最終稿）；避免多處主入口造成認知分散。
- 文案一致化：統一叫法為 `新增堂次`，副標註明「不增加總堂數」。
- 入口治理規則（新增）：
  - 僅對「堂數制 + 進行中課程 + 有操作權限」顯示可點按鈕。
  - 非堂數制/已暫停/已結案課程顯示 disabled 狀態與 tooltip，避免誤導使用者。
  - 所有觸發都需綁定當前分校上下文，不允許跨分校誤操作。

## UI/UX 交付內容（給設計）
- 在課程列表 `操作` 欄新增按鈕：
  - 主要態：`+ 新增堂次`
  - 條件顯示：建議僅 `payment_type=session` 顯示；月結課程顯示 disabled + tooltip（若產品決策需要）。
- 快速加課 modal（沿用現有）：
  - 標題保留「加課／補登（不增加總堂數）」
  - 強化資訊層級：學生名、科目、原時段預設值清楚展示。
- RWD 規範：
  - 桌面：放在操作列第一層按鈕
  - 行動：可折疊進 `操作 ▾` 下拉第一項，確保可點擊熱區
- Empty/Error/Success 狀態文案：
  - 成功：保留「總堂數不變」提醒
  - 失敗：顯示可行動訊息（日期衝突/驗證錯誤）

## 前端實作計畫
- 主要檔案
  - [`/home/admin/frontend/src/pages/CourseManagement.vue`](/home/admin/frontend/src/pages/CourseManagement.vue)
  - [`/home/admin/frontend/src/components/course-management/SessionEditModal.vue`](/home/admin/frontend/src/components/course-management/SessionEditModal.vue)
  - [`/home/admin/frontend/src/components/course-management/QuickAddSessionModal.vue`](/home/admin/frontend/src/components/course-management/QuickAddSessionModal.vue)
- 變更步驟
  - 在課程列 `cell-actions` 新增 `新增堂次` 觸發，直接呼叫 `openQuickAddSessionModal(c)`。
  - 建立單一判斷函式（如 `canQuickAddSession(course)`）集中管理按鈕顯示/禁用邏輯，避免散落判斷造成行為不一致。
  - 調整按鈕優先序：`新增堂次` 與 `詳情/操作` 視覺分層明確。
  - `SessionEditModal` 中 `+ 新增堂次` 改為次要入口（或移除）以避免重複主路徑。
  - 補齊埋點：`course_row_add_session_click`、`quick_add_modal_open`、`quick_add_submit_success/fail`、`quick_add_submit_fail_reason`。
  - 埋點欄位需含 `branch_id`、`course_id`、`payment_type`、`course_status`，便於後續分群分析。

## 後端與 API 檢查點
- 既有 API 可沿用，不需新增端點：
  - `POST /api/v1/student-classes/{id}/add-session`
- 檢查項目（避免 UI 入口變更帶來邏輯誤解）：
  - 堂數已滿時「搬移最後一筆可調整未來排課」行為訊息一致。
  - 權限與分校隔離（`branch_id` / token）維持現狀。
  - 回傳錯誤內容可被前端直接顯示為可理解文案。
  - 明確列出不可操作錯誤語意（例如 403/409/422），讓 UI 能對應正確提示，避免一律顯示通用錯誤。

## QA 驗收與回歸
- 核心驗收
  - 在課程管理列表，不開單堂檢視也可完成新增堂次。
  - 堂數制加課成功後，課程列表與堂次 chip 正確刷新。
  - 堂次已排滿時，搬移提示正確（含 `moved_from_date` 文案）。
- 回歸範圍
  - `SessionEditModal` 單堂操作（已上/請假/調課）不受影響。
  - 編輯課程 modal 內既有「單次加課」仍可用（若選擇保留）。
  - 不影響請假、調課、補課空檔查詢流程。
- 負向測試（新增）
  - 非堂數制課程：按鈕不可操作且提示正確。
  - 已暫停/已結案課程：不可新增堂次。
  - token 過期與權限不足：前端提示需可引導重新登入或聯繫管理員。
  - 跨分校切換中：操作不得寫入錯分校資料。

## 里程碑與分工
- M1（UI/UX）
  - 完成版位與互動稿：桌面 + 行動、正常/禁用/錯誤狀態，並標註入口治理規則。
- M2（Frontend）
  - 接上課程列新入口與事件追蹤，保留既有 API；先採雙入口並行。
- M3（QA）
  - 走完核心驗收 + 回歸清單。
- M4（Release）
  - 觀察 1-2 週操作行為與錯誤率，再決定是否完全移除 `SessionEditModal` 舊入口；若異常可即時回退至雙入口。

## 上線策略（新增）
- Phase 1：雙入口並行（課程列主入口 + modal 次入口），蒐集實際行為數據。
- Phase 2：若指標達標，將 modal 入口降為純文字引導或移除。
- Rollback：若失敗率上升或誤操作增加，立即恢復雙入口並保留原路徑。

## 風險與對策
- 風險：入口太多造成使用者困惑。
  - 對策：明確定義主入口（課程列）與次入口（可逐步退場）。
- 風險：按鈕擁擠影響操作可讀性。
  - 對策：桌面保留一級按鈕，手機收斂到 `操作 ▾`。
- 風險：使用者誤解為「加購堂數」。
  - 對策：按鈕旁或 modal 副文固定標註「不增加總堂數」。
- 風險：顯示條件分散於多處導致行為不一致。
  - 對策：集中到單一 `canQuickAddSession` 規則與共用文案常數。
- 風險：僅以點擊率判斷成功，忽略失敗與誤操作。
  - 對策：同時追蹤成功率、失敗原因分布、平均完成時間與回退率。
