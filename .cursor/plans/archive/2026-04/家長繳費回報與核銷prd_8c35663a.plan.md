# 學收核銷系統 PRD

## PM 可行性評估

**結論：可行，建議分兩期執行。**

現有系統具備 `Invoice`/`Payment` 資料表、家長入口（ParentPortal）、催繳名單（TuitionCollectionPage）、繳費通知單圖（PaymentSlipModal）等基礎。缺少的是：家長自主回報匯款的表單流程、會計核帳確認步驟、正式電子收據的生成與發送。

**風險提示（資安部門必讀）：**
- 帳號後5碼屬半敏感金融資訊，表單連結需具時效性驗證，不可用純靜態公開網址
- 現有家長登入已有 `StudentID` + 手機驗證，回報表單應沿用此驗證機制
- 電子收據不等於法定電子發票，文件需明確說明（非適用加值型統一發票法規）

---

## 角色定義

| 角色 | 任務 |
|------|------|
| 家長 | 填寫繳費回報表單（匯款 or 現金） |
| 現場老師 | 轉告家長填寫連結，並於現金付款時輔助登記 |
| 會計 / 主任 | 在系統核帳、確認入帳、開立電子收據 |
| 系統 | 自動帶出學費期間與堂數、發送電子收據給家長 |

---

## 功能範疇（兩期規劃）

### 第一期 MVP（4-6週）

**F1：家長繳費回報表單（無需登入，Token 驗證）**
- 存取方式：主任/老師從催繳名單點選「產生繳費回報連結」→ 複製後透過 LINE 傳給家長
- 連結格式：`/pay-report?token=<jwt_token>`（含 `StudentClassID`、有效期 72 小時）
- 表單欄位：
  - 學生姓名（系統帶入，唯讀）
  - 學費期間（系統自動帶出，唯讀）
  - 堂數（系統帶入，唯讀）
  - 應繳金額（系統帶入，唯讀）
  - 繳費日期（家長填寫）
  - 繳費方式：匯款 / 現金
  - 帳號後5碼（匯款時必填）
  - 實際繳費金額（家長填寫，用於核帳比對）
- 提交後：家長看到「已送出，等待會計確認」訊息

**F2：主任端「待核帳」列表（TuitionCollectionPage 新增 Tab）**
- 資料來源：新建 `payment_reports` 表
- 欄位顯示：學生姓名、科目、繳費方式、申報金額、帳號後5碼、申報日期、狀態
- 操作：
  - 「確認入帳」→ 帶入 Amount/Method 自動建立 `Payment` 記錄，Invoice 更新為 `paid`
  - 「金額有誤」→ 備註原因，通知家長（第二期加 LINE 通知）
  - 「核帳備註」→ 自由輸入

**F3：系統開立電子收據（收據圖）**
- 核帳確認後，系統自動生成電子收據圖（Canvas，沿用 PaymentSlipModal 風格）
- 收據資訊：學生姓名、科目、學費期間、堂數、繳費金額、繳費方式、核帳日期、流水號
- 主任可從列表下載 PNG / 複製圖片
- 收據連結儲存於 `Payment.receipt_url`（本期為靜態路徑）

**F4：家長查看收據（ParentPortal 新增）**
- 帳單列表中，已核帳的 Invoice 旁增加「查看收據」按鈕
- 顯示由系統生成的收據圖（或開啟圖片連結）

## 資安需求（Security Team）

1. **Token 設計**：`/api/v1/parent/generate-report-link` 產生含 `StudentClassID`、`exp`（72h）、`branch_id` 的 JWT，以後端密鑰簽署；後端驗證時同時檢查 `payment_reports.report_token_hash` 是否已被使用（防重放）
2. **速率限制**：`POST /api/v1/pay-report` 同一 token 只允許提交一次；同一 IP 每小時最多 5 次
3. **後5碼儲存**：`account_last5` 以明文存 DB（非完整帳號，風險可接受），但 API 回傳給前端時 director 以外角色只顯示 `***45` 格式
4. **收據存取**：收據圖的 URL 需含 HMAC 簽名，不可猜測，有效期 7 天
5. **Log 稽核**：核帳（confirm/reject）操作寫入 audit log（`confirmed_by`、`confirmed_at` 已在表中）

## QA 測試場景

**P0 核心流程：**
- 主任產生連結 → 家長開啟 → 填寫匯款後5碼 → 提交成功 → 主任看到待核帳 → 確認入帳 → Invoice 變 `paid` → 家長端可見收據
- 同連結二次提交 → 系統拒絕（token already used）
- Token 過期（72h後）→ 頁面顯示「連結已失效，請聯繫老師」

**P1 邊界條件：**
- 家長申報金額與系統應繳金額不符 → 主任端顯示金額差異警示（不阻擋核帳，由主任判斷）
- 現金繳費不填帳號後5碼 → 驗證放行
- 同一課程同月已有一筆 `confirmed` report → 重複提交警示
- 分校隔離：A 分校主任不可查看 B 分校的 payment_reports

**P2 回歸檢查：**
- 既有 `TuitionCollectionPage` 催繳通知單圖流程不受影響
- `Invoice.Status` 正確性（`unpaid` → `paid`）仍觸發 `alerts/tuition` 消失
- `Payment.Method` 舊有 `cash` 預設不影響新欄位
