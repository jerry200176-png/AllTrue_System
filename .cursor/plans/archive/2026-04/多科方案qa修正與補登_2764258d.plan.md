# 多科方案 QA 修正與補登

## 一、開始日期 + 過去日期補登 — UX 設計

每個科目列加入「開始日期（必填）」和可展開「補登已上課日期」區塊：

```
[ 數學 ]  [ 王老師 ]  [ 2h ]  [ 開始日期: 2026-04-01 ]  [▶ 補登 0 堂]  [✕]

  ↓ 展開後

  2026-04-07  2026-04-10  2026-04-14   [+ 新增日期]
```

- **`start_date`（必填）**：用於設定 `StudentClass.StartDate`，課程管理據此顯示課程起始時間
- `confirmed_dates[]`（可選）：補登已上過的課，限今天以前，每科獨立管理
- 右側方案摘要顯示「已上課堂合計 = 各科 confirmed_dates 總和」，提醒不可超過總堂數
- **不使用月曆元件**，改用 `<input type="date">` + chips，UX 簡潔

### 為何需要 start_date？

- 目前後端 `createMultiSubject` 硬寫 `StartDate = Carbon::today()`
- `ClassSession` 完全不建立 → 課程管理顯示該課程但時間軸空白
- 有了 `start_date`：`StudentClass.StartDate` 設為正確日期；有 `confirmed_dates` 則建立 `ClassSession(Status=attended)` 讓時間軸有內容

## 二、Bug 修正

### Bug 1: student_id 不同步
- [`frontend/src/components/UniversalClassScheduler.vue`](frontend/src/components/UniversalClassScheduler.vue)
- 加一個 `watch(() => form.student_id, ...)` 同步到 `pkgForm.student_id`，反之亦然
- 避免切換 tab 後學生遺失

### Bug 2: 允許重複科目
- 在 `addPkgSubject()` 和 `submitPackage()` 驗證時，若同一 `subject` 已存在，顯示警告（不強制阻擋，只提示）

## 三、後端修正

[`backend/app/Http/Controllers/CoursePackageController.php`](backend/app/Http/Controllers/CoursePackageController.php) `createMultiSubject`：

- validation 加上：
  - `subjects.*.start_date` → `nullable|date`（不填則 fallback 今天）
  - `subjects.*.confirmed_dates` → `nullable|array`
  - `subjects.*.confirmed_dates.*` → `nullable|date`
- `StudentClass::create` 中 `StartDate` 改為 `$subjectSpec['start_date'] ?? Carbon::today()->toDateString()`
- 對每個 `confirmed_date`：
  1. 建立 `ClassSession(Status=attended, SessionDate=date, StartTime, EndTime)`
  2. 呼叫 `PackageDeductionService::deductForSession($pkg->id, $sc->ID, $session->id)`

## 四、補寫測試

[`backend/tests/Feature/CoursePackageTest.php`](backend/tests/Feature/CoursePackageTest.php) 補兩個 test：

- `test_create_multi_subject_with_subject_name_string`：送 `subject_name='Math'`，驗證解析成功、package 建立
- `test_create_multi_subject_unknown_subject_name_returns_422`：送未知 `subject_name='Unknown'`，驗證 422
