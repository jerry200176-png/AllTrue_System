# 修正 Universal Scheduler 死結與 UI

## 已確認的核心規則

- `未被勾選的過去日期 = 請假`，不是系統預排。
- 系統自動推算的 `future_dates` 必須永遠大於今天，不能落在過去。
- 正確推算起點應為 `max(最後手動確認日期, 今天)`，再從該起點之後往未來找符合 `days_of_week` 的日期。

## 現況與根因

- 前端目前在 [UniversalClassScheduler.vue](/home/admin/frontend/src/components/UniversalClassScheduler.vue) 以最後一個手動日期作為唯一 anchor，直接從隔天開始補滿剩餘堂數：

```294:319:frontend/src/components/UniversalClassScheduler.vue
const anchor = confirmed[confirmed.length - 1];
const cursor = new Date(`${anchor}T00:00:00`);
while (selected.length < remaining && guard < 3660) {
  cursor.setDate(cursor.getDate() + 1);
  // ... 依 weekday 補 futureDates
}
```

- 後端在 [ClassSessionController.php](/home/admin/backend/app/Http/Controllers/ClassSessionController.php) 又嚴格要求 `future_dates` 必須 `> today`：

```65:97:backend/app/Http/Controllers/ClassSessionController.php
foreach ($futureDates as $date) {
    if (Carbon::parse($date)->lte($today)) {
        return response()->json([
            'errors' => [
                'future_dates' => ['系統預排日期必須晚於今天'],
            ],
        ], 422);
    }
}
```

- 兩者衝突會造成你描述的 paradox：歷史未勾選日期被前端塞進 `future_dates`，但送出時又被後端拒絕。

## 實作方向

- 在 [UniversalClassScheduler.vue](/home/admin/frontend/src/components/UniversalClassScheduler.vue) 重構 `futureDates`：
  - 若沒有任何手動日期，維持不自動預排。
  - 取 `lastConfirmed = confirmed[confirmed.length - 1]`。
  - 取 `effectiveAnchor = max(lastConfirmed, todayYmd)`。
  - 以 `effectiveAnchor` 建立 cursor，從下一天開始找符合固定星期的日期。
  - 額外保底過濾 `ymd <= todayYmd` 的結果，確保任何系統預排都不會落到今天或更早。
- 同步檢查下列相依邏輯，避免 UI 顯示與 payload 不一致：
  - `futureDateSet`
  - `calendarCells`
  - `submit()` 的堂數補齊驗證與 `future_dates` payload
  - 日曆說明文字，明確表達「過去未點選視為請假，系統只補未來」

## UI 與欄位調整

- 在 [UniversalClassScheduler.vue](/home/admin/frontend/src/components/UniversalClassScheduler.vue) 的「上課時間」區塊改成：
  - `start_time`：改為固定 30 分鐘間隔的下拉式 time picker，而不是自由輸入 `input[type=time]`
  - `duration_minutes`：改成以「小時」為單位的純數字輸入，例如預設 `2`、允許 `1.5`
  - 結束時間維持背景計算，但不再顯示於 UI
- 新增或抽出半小時選項陣列與時長換算邏輯：
  - 顯示層保存 `duration_hours`
  - 送出 payload 前轉回 `duration_minutes`
  - `computedEndTime` 若仍保留於內部計算，需改用小時輸入推算分鐘數
- 視覺樣式改成更商用的淺灰背景 + 白色卡片：
  - modal/body 區塊採 `bg-gray-50` 風格
  - 各區塊卡片加大圓角與柔和陰影，對應現有 `.scheduler-card`、`.scheduler-layout`、`.calendar-card` 樣式
  - 保留並強化顏色標籤：`🟢 手動確認(已上課)`、`🔵 系統預排(未來)`

## 驗證重點

- 用你提供的案例驗證：
  - 今天 `3/15`
  - 購買 `8` 堂、固定 `週六`
  - 手動只勾 `3/7`
  - `3/14` 不勾選
  - 預排結果應為 `3/21, 3/28, 4/4, 4/11, 4/18, 4/25, 5/2`
- 再補兩個邊界案例：
  - 最後手動日期就是今天時，預排必須從下一個符合星期的未來日期開始。
  - 手動日期已經包含多個歷史日期時，任何未勾的過去固定星期都不能被回填成預排。
