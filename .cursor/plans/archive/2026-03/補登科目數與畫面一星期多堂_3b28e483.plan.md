# 補登舊資料與科目數實作計畫

## 規格摘要（已定）


| 項目                 | 決定                                                                        |
| ------------------ | ------------------------------------------------------------------------- |
| 補登科目數 API 是否加老師科目數 | 是：每建立一筆已核准 LearningRecord 即對該老師 `increment('TeachingSessionCount')`（做法 A） |
| 課程管理補登畫面           | 與編輯課程表單一致；排課日改為**多選**（一星期多堂）                                              |


---

## 一、後端 — 做法 A（補登科目數加老師科目數）

**檔案**：[BackfillController.php](backend/app/Http/Controllers/BackfillController.php)

在 `registerSubjectUnits` 的 transaction 內，每建立一筆 `LearningRecord`（約 117–129 行）之後，對該筆的 `TeacherID` 執行與 [LearningRecordController::approve](backend/app/Http/Controllers/LearningRecordController.php) 相同的邏輯：

- 在 `LearningRecord::create([...])` 之後加上：  
`User::where('id', $studentClass->TeacherID)->increment('TeachingSessionCount');`  
- 需在檔案頂端或 controller 內 `use App\Models\User;`（若尚未引用）。

效果：呼叫 `POST /api/v1/backfill/register-subject-units` 建立之每筆「補登／納入科目數」的已核准紀錄，都會讓該老師的科目數 +1，與評量審核通過行為一致。

## 二、後端 — 補登科目數 API 支援一星期多堂（可選）

**檔案**：[BackfillController.php](backend/app/Http/Controllers/BackfillController.php)

目前 `courses` 陣列每筆只接受單一 `day_of_week`（必填）。若要讓同一門課在一個請求內涵蓋多個星期幾（與前端 `days_of_week` 對齊），可擴充 API：

- 新增選填欄位：`courses.*.days_of_week`（陣列，每元素 1–7）。
- 若存在 `days_of_week`：對其中每個 `dow` 呼叫既有 `findStudentClass(..., $dow)`，並各推入一組 `[$sc, $dow, $startTime, $endTime]` 到 `$pairs`（同一 StudentClass 可能重複出現，對應不同星期幾）。
- 若無 `days_of_week`：維持現狀，使用單一 `day_of_week`。

此為選做：僅在「課程管理補登」或其它前端會呼叫 `register-subject-units` 且需一次送多日時才必要；若目前僅用 `student_class_ids` 或單日課程，可略過。

## 三、前端 — 補登畫面與編輯一致、一星期多堂

**檔案**：[CourseManagement.vue](frontend/src/pages/CourseManagement.vue)

### 3.1 補登表單欄位與編輯對齊

- **排課日**：改為與編輯相同的**多選**（`days_of_week` + `DAY_OPTIONS` day-chips），移除單選「固定排課（星期幾）」的 `<select v-model="backfillForm.day_of_week">`。
- **其餘與編輯一致**：開課日 (`first_class_date`)、繳費方式 (`payment_type`)、結算日 (`settlement_day`)、每月堂數 (`monthly_sessions`)、教室 (`room_id`)、備註 (`memo`)。補登專用保留「堂數資料」區塊（已購買、已上、剩餘）。
- **資料結構**：`backfillForm` 改為包含 `days_of_week`（陣列）、`first_class_date`、`payment_type`、`settlement_day`、`monthly_sessions`、`room_id`、`memo`；預設值與編輯表單合理對齊（例如 `days_of_week: []`，堂數制預設）。

### 3.2 補登送出邏輯

- 若課程建立走 **Laravel API**（`POST /api/v1/student-classes`）：payload 與編輯儲存時一致，包含 `days_of_week`（陣列）、`first_class_date`、`payment_type`、`settlement_day`、`monthly_sessions`、`room_id`、`Memo` 等；並帶 `branch_id`、`student_id`、`subject`、`teacher_id`、`class_type`、`rate_per_30min`、`duration_hours`、`start_time`/`end_time`、堂數欄位。
- 若仍使用 **Supabase** 直接 insert：payload 改為帶 `days_of_week`（陣列）；若 Supabase 表無 `days_of_week` 欄位，則依現有 schema 以陣列第一個元素寫入 `day_of_week` 或依既有同步規則處理，避免遺失多日資訊。

### 3.3 教室與 rooms

- 補登 modal 需取得與編輯相同的 `rooms` 列表（例如在開啟補登時呼叫 `loadRoomsForBranch()` 或共用編輯的 `rooms`），以便「上課地點（教室）」選項一致。

## 五、建議實作順序

1. **後端做法 A**：在 `BackfillController::registerSubjectUnits` 內，每筆 `LearningRecord::create` 後加上 `User::increment('TeachingSessionCount')`。
2. **前端補登表單**：補登 modal 改為與編輯相同的欄位配置與 day-chips（`days_of_week`），並補齊開課日、繳費方式、教室、備註等；保留堂數資料區塊。
3. **前端補登送出**：依目前課程建立路徑（Laravel 或 Supabase）帶上 `days_of_week` 及上述欄位。
4. **（選做）後端 API**：`register-subject-units` 支援 `courses.*.days_of_week`，以便未來一次補登多日科目數。
