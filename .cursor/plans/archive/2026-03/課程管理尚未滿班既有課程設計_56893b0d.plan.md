### 目標與原則

- **目標**：在現有補課空檔演算法上，將「尚未滿班的既有課程」也視為可補課時段，讓學生可以併入同老師、同科目、同分校的課程中上課。
- **容量規則**：依 `class_type` 決定老師在同一時段最多可同時上課人數，例如 `one_on_one = 1`、`one_on_two = 2`、`one_on_three = 3`、`tutoring` 可自訂（如 4）。
- **併班條件**（依你選擇的偏好）：
  - 必須 **同老師 (`teacher_id`) ＋ 同科目 (`subject`) ＋ 同分校 (`branch_id`)**。
  - 同一個 30 分鐘 slot 內，**當前人數 < 對應 `class_type` 容量** 時，視為「尚未滿班」可補課。
- **UI 原則**：
  - 不需硬切「併入既有課程」與「老師完全空檔」兩區塊，**同一個列表中都可以選擇**。
  - 但在每一筆候選時段中，要顯示「正在上課學生是誰」，以週視角呈現，讓前台容易判斷要不要併班。

### 一、資料與模型調整設計

- **1.1 定義各類型容量 mapping**
  - 在 `[frontend/src/pages/CourseManagement.vue](frontend/src/pages/CourseManagement.vue)` 的 `<script setup>` 中（靠近 `CLASS_TYPE` 或 `classTypeLabel` 區域）定義：
    - `const CLASS_CAPACITY = { one_on_one: 1, one_on_two: 2, one_on_three: 3, tutoring: 4 }`。
    - `function getCapacityForClassType(type) { return CLASS_CAPACITY[type] ?? 1; }`。
  - 說明：目前使用 "固定容量"；未來若要 per-course 客製，可改為讀取 `student-classes` 的新欄位 `max_students`。
- **1.2 擴充 `fetchMakeupSlots` 輸出結構**
  - 目前 `availableMakeupSlots` 元素為：`{ date, start_time, end_time, day_of_week, ... }`。
  - 計畫改為：「內部仍以此為基礎」，但增加：
    - `currentStudentCount`: 此時段內（該老師＋該分校＋同科目）已有的學生數。
    - `capacity`: 該課程類型的最大人數（由 `getCapacityForClassType` 算出）。
    - `existingStudents`: 簡要列表，例如 `[{ student_name, course_id }]`，僅在此 slot 其實已有課程時填入，讓 UI 可以顯示「目前一起上課的學生」。
  - 若要避免前端過重，也可以先只加 `currentStudentCount` 與 `capacity`，`existingStudents` 作為第二階段優化。
- **1.3 以週為單位的呈現規劃（概念）**
  - 後端/前端計算仍以「日期」為 key（如 `2026-03-10`），但在 UI 上可以：
    - 依照目前程式的 `makeupSlotsGrouped`（以 `date` 分組）繼續沿用。
    - 在未來若要「切換週」視角，可在 Modal 外面再加一層週度切換（例如 `weekOfYear`），不影響目前 `fetchMakeupSlots` 輸出格式。

### 二、演算法調整：從 boolean 佔用改成人數計數

- **2.1 目前行為回顧**
  - 檔案：[frontend/src/pages/CourseManagement.vue](frontend/src/pages/CourseManagement.vue)
  - `fetchMakeupSlots` 目前流程（簡化）：
    - 取出該老師的所有 `student-classes`（`teacherCourses`）。
    - 取出該老師的 `schedules` 例外（請假、調課等）（`schedExceptions`）。
    - 用 `markOcc(date, st, et)` 把每個 slot 標成「occupied」（用 `Set` 存 slot index）。
    - 迴圈掃每一天的 `09:00 ~ 21:00`，找到沒有被 `Set` 佔用且長度足夠的一段，產生候選時段。
- **2.2 改為「每 slot 有幾個學生」**
  - 將 `occMap` 結構從 `Set` 改為 `Map<string, Record<number, number>>`：
    - `const occMap: Record<string, Record<number, number>> = {};`
  - `markOcc(date, st, et)` 調整概念：
    - 若當天尚未有紀錄：`occMap[date] = {}`。
    - 將 `[startSlot, endSlot)` 每個 slot index 做：`occMap[date][slotIdx] = (occMap[date][slotIdx] || 0) + 1`。
  - 載入 `teacherCourses` 時，需先依條件過濾：
    - 僅納入 `teacher_id === form.teacher_id`、`branch_id === branchId`、`subject === form.subject` 的課程（避免不同科目一起算容量）。
- **2.3 將請假／調課例外套用到「人數計數」**
  - `schedExceptions` 目前已會分類成 `leaveSet` / `reschFromSet` / `reschToList`。
  - 併班時規則不變：
    - 對於 `leave` 與 `rescheduled` 的原日，要「扣除」原本在 `teacherCourses` 推算出來的那堂（你現在是直接 `continue` 不標佔用，已經符合同一邏輯）。
    - 對於 `status = 'scheduled' 且有 original_schedule_id` 的補課日，要呼叫 `markOcc` 再加一次人數，代表那天那個時段多了一名學生。
- **2.4 產生候選時段時依容量判斷**
  - 取出目前補課課程類型容量：
    - `const maxStudentsPerSlot = getCapacityForClassType(form.class_type || 'one_on_one');`
  - 掃描每個起始 slot `i`，長度為 `durSlots` 時：
    - 取得 `occ = occMap[ymd] || {};`。
    - 對 `[i, i + durSlots)` 的每個 slot：取 `currentCount = occ[idx] || 0`。
    - 若 `currentCount >= maxStudentsPerSlot`，此區間不可用（滿班）。
    - 否則，全區皆 `currentCount < maxStudentsPerSlot` 則為可補課候選。
  - 額外：可同時計算此區間的 `maxOcc`（最大 `currentCount`）：
    - 若 `maxOcc === 0` → 老師完全空檔。
    - 若 `0 < maxOcc < maxStudentsPerSlot` → 尚未滿班的既有課程。
    - 依據此資訊將 `currentStudentCount = maxOcc` 存入候選 slot。
- **2.5 尋找該 slot 下「正在上課的學生」列表（選配）**
  - 目標：`existingStudents` 欄位可以列出同一時段正在上的學生名稱。
  - 設計方向：
    - 可在建立 `occMap` 時，同步建立一個 `slotStudentsMap`：
      - 結構類似：`slotStudentsMap[date][slotIdx] = [{ student_name, course_id }]`。
    - 當掃描 `teacherCourses` 時：
      - 對於哪一天、哪個 slot 有這門課，就在 `slotStudentsMap` 裡 push 一筆對應學生。
    - 產生候選區間時，依該區間內所有 slot 的 `slotStudentsMap` 合併去重，得到一份 `existingStudents`。
  - 若第一階段不想那麼複雜，可以先只顯示 `currentStudentCount`，第二階段再加 `existingStudents`。

### 三、UI 呈現與互動設計

- **3.1 Makeup Slots Modal 現有結構回顧**

  - `<!-- Makeup Slots Modal (補課空檔查詢) -->` 中目前的列表：
    - 以 `makeupSlotsGrouped`（依 `date` 分組）渲染 `group`。
    - 每個日期下渲染多個 `slot`，顯示 `start_time ~ end_time`，並有「選擇」按鈕。
- **3.2 新增容量與人數提示**
  - 在 slot Row 顯示：
    - 例如：`14:00 ~ 15:00（目前 1 / 2 人）`。
    - 若實作 `existingStudents`，可在 hover 或細字顯示：`學生：小明、小華`。
  - 規則：
    - `currentStudentCount === 0` 也顯示為 `0 / capacity`，方便前台一眼看出這是完全空檔。
    - 若之後想特別標示，可在 slot Row 加上不同 class（如 `slot-free` / `slot-join-existing`），目前需求是「不需切區塊，只在同列表中呈現」，所以只用文案與顏色淡淡區隔即可。
- **3.3 以週呈現的延伸（選配）**
  - 第一步可以維持現有「日期列表」樣式，只是日期範圍依 `makeupDateRange` 控制。
  - 若要強化「週視角」，可以在 Modal 上方再加一層週度切換邏輯（不影響核心演算法）：
    - 例如：左上角顯示「第 N 週」，左右箭頭切換；下方日期組織仍用 `makeupSlotsGrouped`，只是每次只顯示一週內的日期。
- **3.4 選擇後寫回邏輯**
  - 與現行相同：
    - `selectMakeupSlot(slot)` 把 `slot.date`、`slot.start_time` 回寫到 `rescheduleForm.new_date`／`new_start`。
    - 其餘欄位（`duration_hours`、`end_time`）沿用既有邏輯（`computeEndTime`）。
  - 若未來要在後端紀錄「這堂是併入哪門原本課程」：
    - 需要再擴充一個欄位，例如 `group_base_course_id`，並在 slot 結構中帶出。
    - 這部分牽涉到資料庫 schema 與報表需求，可以作為後續延伸。

### 四、效能與邊界情境考量

- **4.1 效能與上限**
  - 目前 `fetchMakeupSlots` 每次抓 `per_page=1000` 的 `student-classes`、`schedules`，對一般補教規模已夠。
  - 改成 `occMap` 人數計數後，計算量為：
    - `O(課程數 × 影響天數 × 每日 slot 數)`，仍在可接受範圍（每天約 26 個 half-hour slot，30 天約 780 slot）。
- **4.2 邊界情境**
  - **老師長時間大班課程**（例如 `tutoring` 容量大於 4 或更多）：
    - `CLASS_CAPACITY` 需按實際需求調整，避免補課學生過多。
  - **跨分校授課**：
    - 依你目前需求「同分校」才可以併班，如果未來要支援跨分校併班，需在查詢與 UI 上明確標示分校名稱，並重新檢查教室衝突邏輯。
  - **教室容量**：
    - 若未來要做到「教室座位數」限制，可以在 `rooms` 資料中加入 `capacity`，然後在 `fetchMakeupSlots` 再疊一層「教室容量」判斷（同一時段同一教室的總人數不能超過教室容量）。

1. 在 `CourseManagement.vue` 中定義 `CLASS_CAPACITY` 和 `getCapacityForClassType`，並在 `fetchMakeupSlots` 取出 `maxStudentsPerSlot`。
