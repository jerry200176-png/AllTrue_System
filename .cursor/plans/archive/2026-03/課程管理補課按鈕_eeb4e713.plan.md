# 課程管理新增補課按鈕與老師空檔列表

## 目標

- **在現有「調課」流程內**，新增「查詢可補課時段」與「一鍵套用補課時段」功能。
- 以 **老師的既有排課資料 (`schedules`) 推算空檔**，列出可補課時段列表供使用者選擇。
- 新增的補課紀錄以 `original_schedule_id` 關聯回原本被請假的堂次（或原堂次），方便日後對帳與報表。

## 相關現況與檔案

- **課程管理頁**：`[frontend/src/pages/CourseManagement.vue](frontend/src/pages/CourseManagement.vue)`
  - 已規劃新增「請假」「調課」按鈕，以及對應 modal 與 `rescheduleForm` / `leaveForm` 狀態。
- **智慧排課頁**：`[frontend/src/pages/SmartCalendar.vue](frontend/src/pages/SmartCalendar.vue)`
  - 已有請假與調課寫入 `schedules` 的實作，可作為補課寫入邏輯與欄位的參考。
- **資料表**：Supabase `schedules`
  - 重要欄位：`id`, `branch_id`, `student_course_id`, `student_id`, `teacher_id`, `subject`, `schedule_date`, `day_of_week`, `start_time`, `end_time`, `duration_hours`, `status`, `class_type`, `deduction`, `original_schedule_id`, ...

## 功能流程設計

### 一、進入補課流程

- **入口**：沿用課程管理表格中每筆課程的「調課」按鈕。
- 使用者點「調課」後：
  1. 先選擇「要調動 / 要補的原堂次」（沿用現有 `sessions(c)` 選擇堂次的設計）。
  2. 原本的調課 modal 打開，顯示原日期 / 原時段等資訊。
  3. 在此 modal 中新增一顆 **「查詢可補課時段」** 按鈕，點擊後打開第二層或側邊的補課空檔列表 UI。

### 二、查詢老師可補課空檔

- **查詢條件來源**：
  - 老師：從原堂次（或課程 `c`）帶入 `teacher_id`。
  - 學生課程：`student_course_id` 同原堂次 / 課程。
  - 分校：`branch_id` 由當前頁面的 `props.branchId` 或課程記錄帶入。
  - 補課時長：使用原課程的 `duration_hours` 或 `class_type` 對應的固定長度。
  - 查詢日期範圍：預設未來 30 天（可在 UI 設定選項，例如「未來 7 / 30 / 60 天」）。
- **取得老師已排時段**：
  - 呼叫 Supabase：`schedules` 表，條件大致為：
    - `teacher_id = :teacherId`
    - `branch_id = :branchId`
    - `schedule_date BETWEEN :startDate AND :endDate`
    - `status IN ('scheduled', 'rescheduled', 'leave', 'cancelled', ...)`（具體依專案定義）
- **建立可用時間網格**：
  - 以「每天可授課時間」建立一個 time grid，例如：
    - 每日 09:00–21:00，間距 30 分鐘。
    - 來源可以是：
      - 簡單寫死在前端的常數（例如 `TEACHING_HOURS = { start: '09:00', end: '21:00' }`）。
      - 或參考若既有 `branch` / `settings` 中的營業時間設定（若程式中已有）。
- **演算法概念（前端計算即可）**：
  1. 對每一天（在查詢日期範圍內）：
    - 先建立當日完整 slot 列表：`[09:00, 09:30, 10:00, ... 20:30]`。
  2. 將 `schedules` 中該天老師所有紀錄轉成「佔用區間」，例如：
    - `start_time = '14:00'`, `end_time = '15:30'` → 佔用 `14:00–14:30`, `14:30–15:00`, `15:00–15:30`。
  3. 在 time grid 中標記這些 slot 為「occupied」。
  4. 將連續的「not occupied」區間整理出來，且長度需 **>= `duration_hours`**：
    - 例如補課 1.0 小時且以 30 分鐘為單位：
      - 連續空檔長度至少需 2 個 slot。
  5. 將每一段可用區間轉成補課候選時段：
    - 例如可用區間為 13:00–15:00，補課長度 1 小時 → 輸出：
      - 13:00–14:00
      - 13:30–14:30
      - 14:00–15:00
- **輸出資料結構（前端 state）**：
  - 例如 `availableMakeupSlots: Array<{ date: string; start_time: string; end_time: string; day_of_week: number; teacher_id: string; branch_id: string; }>`。

### 三、補課空檔 UI

- **顯示形式**（建議簡化為列表 + 日期切換）：
  - 上方：日期切換（例如左右切換前一天 / 後一天，或日期選擇器）。
  - 中段：該日所有 `availableMakeupSlots` 列表，格式如：
    - `2026-03-10（二） 14:00–15:00`
    - `2026-03-12（四） 19:30–20:30`
  - 每一列有一顆「選擇」按鈕。
- **與調課 modal 的整合**：
  - 使用者在補課空檔 UI 中點「選擇」：
    - 自動將該 slot 的 `date`, `start_time`, `end_time`, `day_of_week` 回寫到 `rescheduleForm` 中的 `new_date`, `new_start`, `new_end`, `new_day_of_week`。
  - 關閉補課空檔 UI，回到原調課 modal；此時 `rescheduleForm` 已帶好補課時段，使用者只需按下「確認調課 / 補課」。

### 四、寫入補課紀錄（與原堂次關聯）

- 整體寫入路徑延伸自既有調課邏輯：

```mermaid
flowchart TD
  selectOriginal[selectOriginalSession] --> openRescheduleModal[openRescheduleModal]
  openRescheduleModal --> openMakeupSlotsModal[openMakeupSlotsModal]
  openMakeupSlotsModal --> chooseSlot[chooseMakeupSlot]
  chooseSlot --> fillRescheduleForm[fillRescheduleFormWithSlot]
  fillRescheduleForm --> submitReschedule[submitRescheduleOrMakeup]
  submitReschedule --> supabaseOriginal[insert/select rescheduled(original)]
  submitReschedule --> supabaseNew[insert scheduled(new)]
```



- **步驟細節**：
  1. 使用者選原堂次（被請假或需調動的堂次），`original_date`, `original_start`, `original_end` 已存在於 `rescheduleForm`。
  2. 選定補課空檔後，`rescheduleForm` 帶入：
    - `new_date`, `new_start`, `new_end`, `new_day_of_week`。
  3. 提交時：
    - 先查詢 `schedules`：是否已存在 `student_course_id = course_id && schedule_date = original_date && status = 'rescheduled'` 的紀錄：
      - 若有：取該 `id` 作為 `originalId`。
      - 若無：insert 一筆原日紀錄
        - `status = 'rescheduled'`
        - 其他欄位依原堂次填入，並取得 `id` 作為 `originalId`。
    - 再 insert 一筆補課日紀錄：
      - `status = 'scheduled'`
      - `schedule_date = new_date`
      - `start_time = new_start`, `end_time = new_end`
      - `day_of_week` 由 `new_date` 計算
      - `original_schedule_id = originalId`
      - `deduction` 依專案規則（例如 1 或 0，看你們是否要扣堂數）
      - 其他欄位沿用原堂次（`student_id`, `teacher_id`, `subject`, `branch_id`, `student_course_id`, `class_type`, `duration_hours` 等）。
    - 若現有調課已呼叫 `/api/v1/learning-records/reschedule-session`：
      - 可沿用同一 API，將 `old_date` 設為原堂次日期、`new_date` 設為補課日期。

### 五、錯誤處理與邊界情境

- **無可用補課空檔**
  - 若在指定日期範圍內算不到任何 `availableMakeupSlots`：
    - 在 UI 顯示「查無可補課空檔，請嘗試放寬日期或更換老師」。
    - 可提供調整查詢範圍的控制（例如「往後多查 30 天」按鈕）。
- **老師已被其他使用者搶先排到**
  - 在提交補課時，再做一次 `schedules` 查詢（或利用 Supabase row-level constraint）驗證該時段仍為空檔：
    - 若發現衝突（新增前後有重疊）：提示「該時段已被排課，請重新選擇」。
- **時段長度不符**
  - 若未來有不同長度課程，演算法需依 `duration_hours` 動態產生候選時段。

### 六、未來可擴充方向（非本次必做）

- 在補課空檔列表中增加：
  - **多位老師切換**（同科目、同分校的其他老師也可補課）。
  - **教室資源衝突判斷**（若 `schedules` 或其他表有 `classroom_id`）。
- 將「計算老師空檔」的邏輯抽到共用 util（例如 `[frontend/src/lib/timeSlots.js](frontend/src/lib/timeSlots.js)`）， SmartCalendar 也可重用。
