---

## 2. 目標與業務背景

**痛點**：主任在「學收月報」頁面查詢某月份時，若學生課程在月中或月底完成結案（Stop=1），該課程在本月已出席的堂數完全不出現在報表內，導致學收試算金額偏低、對帳有缺漏。

**業務價值**：報表應如實反映「本月到底上了幾堂、收了多少錢」，與課程目前是否仍在進行無關。結案是行政動作，不應影響已發生的財務事實。

**KPI**：
- 修正後，指定月份內有 attended/completed/late 堂次的所有課程（無論 Stop 值）均出現在報表。
- 報表總金額與課程台帳對帳差異率降至 0%。

---

## 3. 範圍

**In Scope**：
- `GET /api/v1/finance/branch-monthly-tuition` 後端查詢邏輯修正。
- `GET /api/v1/finance/branch-monthly-tuition/export` CSV 匯出同步修正（相同邏輯）。
- API 回傳每筆 course 行新增 `is_stopped` 欄位，讓前端可區分進行中與歷史課程。
- 前端 `TuitionReportPage.vue` 對已結課行顯示「已結課」標籤（視覺識別）。
- 新增 Pest 回歸測試，覆蓋「已結案課程當月仍計入學收」情境。

**Out of Scope**：
- `Invoice` / `BillingController` 帳單邏輯不動。
- `alerts/tuition`（催繳名單）`Stop = 0` 條件不動（催繳邏輯須對應進行中課程，語意不同）。
- `finance/revenue`、`finance/summary` 等其他 API 不在本次修正範圍。
- 月結方案（CoursePackage）`stop` 欄位的催繳顯示邏輯不動。

## 5. User Stories

> **As a** 主任, **I want** 學收月報在查詢任何月份時，只要該月份內有出席記錄的課程都被列出，**so that** 我可以完整對帳當月學費收入，不因學生課程在月底結案而漏算。
>
> Acceptance Criteria：
> - [ ] 課程已設為 Stop=1（歷史），但該月有 attended/completed/late 堂次 → 報表顯示該行。
> - [ ] 課程 Stop=0（進行中），當月有堂次 → 報表顯示（現有行為保持不變）。
> - [ ] 課程 Stop=1，且該月無任何堂次 → 報表不顯示（避免汙染報表）。
> - [ ] 已結課行有視覺標籤「已結課」與既有進行中課程行做區分。
> - [ ] 報表 summary（total_students / total_sessions / total_tuition）正確包含已結課行貢獻。
> - [ ] CSV 匯出結果與頁面報表一致。

## 6. 功能需求（FR）

- **FR-001**：`GET /api/v1/finance/branch-monthly-tuition` 應移除對 `StudentClass.Stop = 0` 的過濾條件，改為「有指定月份 attended/completed/late 堂次的所有課程」皆納入。
- **FR-002**：`GET /api/v1/finance/branch-monthly-tuition/export` 與 FR-001 採相同查詢邏輯，確保 CSV 匯出與頁面一致。
- **FR-003**：API 回傳的每筆 `row_type: 'course'` 行需新增 `is_stopped: true/false` 欄位（取自 `StudentClass.Stop`）。
- **FR-004**：前端 `TuitionReportPage.vue` 在 `is_stopped: true` 的行顯示「已結課」灰色 badge，並降低整列文字透明度（`opacity: 0.65`）。
- **FR-005**：月結方案行（`row_type: 'package'`）不受影響；月結方案的成員 StudentClass（Fix 後已納入 `$allRows`）若有 Stop=1 的成員，其堂數仍正確彙整至方案聚合行。

---

## 7. 非功能需求（NFR）

- **效能**：移除 `Stop = 0` 條件後，舊有 JOIN 已確保只返回當月有堂次的課程；查詢返回時間仍應 < 800ms（P95）。
- **錯誤處理**：無新增錯誤路徑；現有 500/403 處理保持不變。
- **降級**：若新增 `is_stopped` 欄位導致前端舊版本解析失敗（布林欄位為新增，非移除），前端應以 `?? false` 預設值安全處理。

## 8. 技術方向（給 CTO，非實作細節）

**受影響頁面**：
- `frontend/src/pages/TuitionReportPage.vue`

**受影響 API**：
- `GET /api/v1/finance/branch-monthly-tuition`
- `GET /api/v1/finance/branch-monthly-tuition/export`

**受影響資料表**：
- `StudentClass`（Stop 欄位的過濾邏輯）
- `ClassSession`（SessionDate / Status，無變更，查詢邏輯已正確）

**架構選擇理由**：
- 移除 `Stop = 0` 的條件是最小範圍修正；不需新增 migration、不影響任何其他模組。
- JOIN 設計本身已保證「只有當月有堂次的課程才出現」，移除 Stop 過濾後不會讓零堂次的歷史課程汙染報表。
- `is_stopped` 作為新增欄位（非移除欄位），前後端均可安全降級。

**不需要 migration。**

**子任務 Agent 派發**：
- `[FEATURE]` → 後端移除 Stop=0 條件 + 新增 is_stopped 欄位；前端增加已結課 badge 與透明度
- `[TEST]` → 新增 Pest 測試覆蓋 FR-001 ~ FR-003
- `[REVIEW]` → 確認 Stop=0 移除不影響其他使用 branchMonthlyTuition 的呼叫路徑
- `[DOCS]` → 更新 `docs/CHANGELOG.md` 與 `docs/AI_REGRESSION_LESSONS.md`

## 9. 資安與存取控制

- 本功能已受 `require_campus` middleware 限制，分校隔離（`auth_campus_ids`）不受影響。
- 新增的 `is_stopped` 欄位僅為 boolean，不含額外 PII。
- 本次移除的是 `Stop = 0` 過濾，不新增任何資料寫入路徑。
- **STRIDE 快評**：
  - Spoofing：無新增認證面，不受影響。
  - Tampering：唯讀 GET，不受影響。
  - Info Disclosure：仍受分校隔離；已結案課程的學生姓名/金額屬同分校主任本有權限存取之資訊，不構成新增洩漏。
  - 其餘：不適用。
- 稽核 log：本次無新增寫入操作，無需新增 log。
